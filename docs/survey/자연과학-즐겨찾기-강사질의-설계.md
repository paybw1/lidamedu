# 자연과학 — 즐겨찾기 검색 + 문제별 강사 질의 설계안

> 읽기 전용 조사 기반. 선택지·tradeoff·권고·결정 포인트. 구현은 승인 후. 모든 기존 라우트·데이터 보존.
> 핵심 사실: **자연과학 문제 = 법과목과 같은 `problems` 테이블·같은 UUID**, 구분자는 `problems.science_subject`(non-null) 뿐. → 강사질의(`qna_target_type='problem'`)·즐겨찾기(`target_type='problem'`) **DB/enum 변경 불필요**.

---

## A. 문제별 강사 질의 (Q&A) — 자연과학 문제 뷰어에 추가

### 현황
- **강사 질의 기능 = `app/features/qna/`**: 학생이 질문 스레드 생성 → 강사가 답변(스레드당 1강사 점유) → 이메일·카카오 알림. polymorphic `qna_target_type = ['article','case','problem']`.
- **법과목 마운트**: `laws/components/article-right-panel.tsx`의 **"Q&A" 탭** → `<QnaPanel threads={qnaThreads} ...>`(`:468`). 조문/판례/문제 뷰어가 loader에서 `qnaThreads`를 조회해 ArticleRightPanel에 전달(article-viewer·case-viewer·problem-viewer(법)).
- **자연과학 문제 뷰어**(`subjects/screens/science/problem-viewer.tsx`): **QnaPanel 미마운트·qnaThreads 미조회**. 현재 **메모(content_comments)만** 있음(`:434` CommentsPanel — 강사 공개 메모 + 학생 본인 메모. 이건 "질문→답변" 스레드가 아니라 개인/공지성 메모).
- ★ 즉 "강사에게 질문"(=Q&A 스레드)은 자연과학에 **없음**. (메모는 별개로 이미 있음.)

### 옵션
- **(A-1) QnaPanel 직접 마운트** ★권고: science 문제 뷰어 loader에 `qnaThreads` 조회(법 problem-viewer가 쓰는 qna 조회 함수 재사용) 추가 + 본문 하단(현재 메모 옆/아래)에 `<QnaPanel>` 렌더. 자과 뷰어가 이미 패널을 직접 배치하는 스타일이라 정합·최소 변경. 메모는 그대로 둠(개인 메모 ↔ 강사 Q&A 별개 용도).
- (A-2) ArticleRightPanel로 전환: Q&A+코멘트+하이라이트 탭 일괄 제공. 단 ArticleRightPanel은 법과목 전용 탭(관련 판례 등)을 품고 있어 자과엔 부적합·레이아웃 대수술. **비권고**.

### 필요 변경(A-1, 추정)
- science `problem-viewer.tsx` loader: qna 스레드 조회 추가(`target_type='problem'`, `target_id=problemId`) — 법 problem-viewer의 조회 재사용.
- 같은 뷰어에 `QnaPanel` 마운트(질문 작성·목록). 질문 생성/답변은 기존 `qna/api/thread.tsx`·`qna-new`·알림 그대로 재사용(타깃 problem 이미 지원).
- DB·enum·알림 **변경 없음**. 강사 답변·가시성도 기존 규칙 그대로.

### 결정 포인트 A
1. 추가할 게 **Q&A 스레드(QnaPanel)** 맞는지 — 권고 확정(메모는 이미 있으니 그건 유지). 
2. 배치: 메모 옆/아래 직접 마운트(권고) vs 탭형.

## B. 즐겨찾기 검색 (둘 다)

### 현황
- 자과 문제 즐겨찾기 = `user_bookmarks` `target_type='problem'` + `science_subject`로 구분(전용 target_type 없음). 별점 UI는 science 문제 뷰어(`:427` `BookmarkStars`).
- **통합 `/study/bookmarks`**: 자과 문제 즐겨찾기 **이미 목록에 잡히고** 클릭 시 자과 뷰어로 이동(`listAllBookmarks`의 science 분기 `queries.server.ts:726-752`). 그러나 **텍스트 검색 없음** — 필터는 과목(법령 슬러그)/유형/별점/기간뿐(`bookmarks.tsx:93-105`). ⚠ 자과 문제는 `lawCode=null`이라 **과목 칩 필터에 안 걸림**(전체에서만 보임).
- **자연과학 화면**(`science-hub.tsx` 등): 즐겨찾기 목록·검색 UI **전무**. 재사용 쿼리도 부족 — `listBookmarkedProblems`는 `laws!inner` 조인이라 **자과 문제를 떨굼**(재사용 불가).

### 목표 ⑴ — 통합 `/study/bookmarks` 텍스트 검색
- **(B-1a) 클라 텍스트 검색 추가** ★권고: 검색 input + `items.filter`에 `primaryLabel`(연도·번호)/`secondaryLabel`(과목명 "물리")/`bodySnippet`(본문 80자)/`notePreview`(메모) 소문자 매칭. **이미 메모리에 있는 필드 → 서버/쿼리 변경 0**.
- (B-1b 선택) **"자연과학" 과목 칩** 추가: 자과는 `lawCode=null`이라 현재 과목칩 미적용. `BookmarkListItem`에 `scienceSubject` 노출 + 칩/필터 분기 추가. (검색만으로 충분하면 생략 가능.)
- (B-1c 선택) 본문 전문 검색 원하면 `bodySnippet` 80자 확대.

### 목표 ⑵ — 자연과학 화면 전용 즐겨찾기 검색
- **(B-2) science-hub에 즐겨찾기 섹션 + 신규 science 즐겨찾기 쿼리** ★권고:
  - 신규 쿼리(annotations 또는 science.server): `target_type='problem'` & `science_subject={과목}` & `star_level≥min` & `deleted_at IS NULL`, 검색어(연도/번호/본문) 지원. (`listAllBookmarks`의 problem+science 매핑 로직을 과목 한정 버전으로 재사용. `listBookmarkedProblems`는 laws 조인 때문에 재사용 불가.)
  - 진입점: `subjects/components/science-hub.tsx`(4과목 공용) KPI 아래에 "즐겨찾기 검색" 섹션 — 한 곳 수정으로 전 과목 반영. (또는 전용 라우트 `/subjects/science/:subject/bookmarks` 신설.)

### 결정 포인트 B
1. ⑴ 통합 검색: **클라 텍스트 검색만(권고)** vs "자연과학 과목칩"까지(B-1b)?
2. ⑵ 전용 검색 진입점: **science-hub 공용 섹션(권고)** vs 전용 라우트?

## C. 단계적 적용안 (안전·작은 것부터)
- **C-1** ⑴ 통합 검색(B-1a) — 클라 한 줄 수준, 위험 0, 즉시 효용. (typecheck·격리 커밋)
- **C-2** A-1 자과 문제 Q&A 마운트 — loader 조회 + QnaPanel 렌더(기존 자산 재사용).
- **C-3** ⑵ 자과 전용 즐겨찾기 검색(B-2) — 신규 쿼리 + science-hub UI.
- 각 단계: 기존 라우트·데이터 보존, typecheck, 단계 격리 커밋. 배포는 가오픈이라 단건 푸시 OK.

> 결정(A1·A2 / B1·B2)만 주시면 C-1부터 구현 설계→코드로 들어갑니다.
