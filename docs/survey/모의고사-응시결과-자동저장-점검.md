# 모의고사 응시 → 채점 → 저장 → 학습현황 반영 점검

> 읽기 전용 점검(코드 변경 0). 조사일 2026-06-22. 근거는 파일:라인.
> 목표: (a) 미저장 / (b) 저장되나 학습현황이 모의고사 제외 / (c) 자동 저장+자동 반영 — 판정.

---

## 0. 판정 — **(c) 이미 자동 저장 + 자동 반영된다**

- 모의고사 응시는 **`user_problem_attempts`에 자동 저장**(`mode='exam'`, pack 세션 연결, 자동 채점).
- 진도·정답률·약점·KPI·추이·히트맵·SRS **모든 학습현황 리더가 mode/세션 구분 없이 그 행을 읽어** 모의고사 결과를 **자동 반영**한다. 제외 로직 없음.
- **"응시결과 입력"(수동)은 플랫폼 모의고사 채점과 무관** — `/me/exam-results`는 **실제(오프라인) 변리사 시험 결과 자기보고**(feat-8-002)다. 즉 (ii) 외부 결과 기록용이며, **제거 대상이 아니다**.

→ 사용자가 우려한 "자동이어야 할 걸 수동으로" 상황은 **없다**. 핵심 흐름은 이미 완전 자동((c)). "수동 입력 제거"의 전제(중복 수동 채점)는 성립하지 않는다.

---

## 1. 응시 · 저장 흐름 (자동)

```
mcq-pack-detail (모의고사 시작, mode=exam)
  → POST /api/mcq-pack/start  → createQuizSession(mode='exam', scope_type='pack', pack_id, problem_ids, time_limit_sec)
  → /latest/mcq/:packId/sheet/:sessionId  (mcq-pack-sheet = 시험지 러너, 타이머)
      └ 선지 클릭마다 recordAttempt → POST /api/problems/attempt → user_problem_attempts INSERT
  → /api/study/session-complete  → /latest/mcq/:packId/result/:sessionId (결과·점수·등수)
```

- **시작**: `mcq-pack-detail.tsx:189-203` — 모의 팩만 "모의고사 시작"(`mode=exam`). 세션 생성 `mcq-packs/api/start.tsx:103-129`(타이머 = `durationMin*60`).
- **저장(핵심)**: 러너 `mcq-pack-sheet.tsx:214-238`의 `recordAttempt`가 **선지 선택 즉시** `POST /api/problems/attempt`(`mode`=세션 mode='exam', `sessionId`, `isCorrect`, `selectedChoice*`). → `recordProblemAttempt`가 **`user_problem_attempts` INSERT**(`study/queries.server.ts:192-204`): `user_id, problem_id, is_correct, mode('exam'), session_id, selected_*`. **= 진도·정답률·약점이 읽는 바로 그 테이블.**
- **세션**: `quiz_sessions`(`scope_type='pack'`, `pack_id`) — 점수/등수 집계 단위.
- **모의 전용 결과 테이블 없음**: `mcq_pack_attempts` 식별자 0건. 점수·합격·등수는 `user_problem_attempts`에서 **RPC `mcq_pack_attempt_stats`로 매번 파생**(저장 안 함, feat-10-004 설계 "derived").
- **채점 = 자동**: `is_correct`는 선지의 `is_correct`(정답) 비교로 계산·저장. 점수 = 정답수/문항수×100(미응답은 분모 포함·오답 아님).

> 조건부 1점: 미응답 문항은 attempt 행이 없다(선지 클릭한 문항만 기록). 점수 분모는 세션 `problem_ids` 길이라 미응답도 반영됨.

## 2. "응시결과 입력"(수동)의 정체 — 외부 실제 시험 결과 (플랫폼 채점과 무관)

- 화면 `/me/exam-results` (`exam-results/screens/my-exam-results.tsx`, feat-8-002 "학생 본인 합격 결과 입력").
- 테이블 **`exam_results`**: `exam_year, exam_round, status(미응시/대기/불합격/합격), self_reported_total_score(자가신고 0~200), study_summary_md` + 합격증 업로드(`certificate_path`) + 운영자 검증(`verification_status`).
- **의도(ii 외부/오프라인)**: 자동 채점 불가능한 **실제 변리사 1·2차 시험 결과를 학생이 자기보고**하는 것. 회수 cron(`cron/api/exam-result-reminder.tsx`, feat-8-005) + 합격자 평균 비교·실패패턴 분석(`admin-failure-patterns`)·analytics 동의에 사용. **플랫폼 모의고사 점수 수동 입력이 아니다.**
- (참고) 운영자가 넣는 건 `mcq_packs.pass_score`(합격선 기준 설정)뿐 — "결과 입력"이 아니라 채점 기준.

→ **이 수동 입력은 제거 대상이 아니다.** 제거하면 합격자 벤치마크·실패분석 데이터원이 사라진다(학습데이터 = soft-delete 원칙 대상이기도).

## 3. 학습현황 반영 — 전 지표 자동 포함 (제외 리더 0)

모든 리더가 `user_problem_attempts`를 `.eq("user_id", …)`만으로 읽고 **mode/세션 필터가 없다** → 모의고사(exam) 시도 포함:

| 리더 | 반영 | 근거(필터 유무) |
|---|---|---|
| getOverallProgress (문제 풀이%) | 포함 | `study/queries.server.ts:1431-1437` mode 필터 없음 |
| getAllSubjectsProgress (과목별 정답률) | 포함 | `:1689-1705` 없음 |
| buildNodeProgressByArticle (약점·노드 진척 토대) | 포함 | `node-progress.server.ts:90-95` 없음 |
| getWeakNodes (대시보드 약점 단원) | 포함 | `weak-nodes.server.ts:59`(위 함수 합산) |
| getWeakAreas / listWrongAttempts (약점·오답노트) | 포함 | `:1818`, `:1861-1869` (`ox_answer IS NULL`만, mode 없음) |
| getDashboardKpis (정답률/시도/시간 KPI) | 포함 | `:1596-1602` 없음 |
| getDailyStudyStats (히트맵·연속·주별시간) | 포함 | `:1508-1514` 없음 |
| getUserAccuracyTrend (주별 정답률) | 포함 | `:2549-2553` 없음 |
| getProblemStatsBulk / get_problem_stats(전역 난이도) | 포함(전역) | `:1112` 인자 `p_ids`뿐(mode 파라미터 없음) — RPC 본문 미열람(추측) |

- **의도적 제외 로직 없음.** `mode='exam'`을 거는 곳은 `getPreviousPackScores`(`:2797`) **단 1곳**인데, 제외가 아니라 "같은 팩 이전 응시 점수 추이"용 **명시 포함**.
- SRS도 mode 무관 실행(`queries.server.ts:206-226`) → 모의고사 오답도 복습 큐·오답노트·약점에 유입.
- **동의 게이트(my_analysis)**: `/study/stats` loader가 `hasMyAnalysisConsent` false면 통계 미fetch + `MyAnalysisOffNotice`만(`stats.tsx:200-218`). **표시 레이어 게이트일 뿐** — 데이터 적재/집계 자체는 막지 않고, mode 구분과도 무관. 즉 동의 ON이면 모의고사 포함 분석이 보이고, OFF면 (모의고사 포함) 분석 전체가 가려진다. → "결과의 분석 반영을 동의가 게이트하나?" = **예(표시 단위로)**.

## 4. 판정 + 최소 수정안

**판정 = (c).** 모의고사 응시 = 자동 저장(user_problem_attempts, mode='exam') + 자동 채점 + 학습현황 전 지표 자동 반영. (b)(저장되나 제외) 아님 — 제외 리더 0. (a)(미저장) 아님.

**최소 수정안 = 핵심 흐름엔 변경 불필요.** 요청한 "자동 저장 + 학습현황 반영"은 이미 충족. "수동 입력 제거"는 **하지 말 것** — 그 수동 입력은 외부 실제 시험 결과(`exam_results`)로 모의고사 채점과 별개·필요 기능.

### 다만 검토할 nuance (선택 · 운영 판단)
1. **즉시 기록 vs 제출 기록**: 모의고사는 **선지 클릭 즉시** attempt 기록(미제출·답 변경분도 그 시점 정오가 남음, `mcq-pack-sheet.tsx:234-238`). 시험 환경에서 "최종 답"만 정답률·약점에 반영하고 싶다면 exam 모드는 **세션 완료 시점에 최종 선택으로 정정 기록**하는 방안 검토 가능(현재는 학습/시험 동일하게 클릭마다). → 설계 의견이지 버그 아님.
2. **학습 vs 모의 분리 지표(선택)**: 현재 둘을 합산. 만약 "모의고사 정답률"을 따로 보고 싶다면 `mode` 컬럼이 이미 있어 **리더에서 분기만 추가**하면 됨(데이터는 이미 구분 저장됨). 지금은 통합이 의도된 듯(분리 요구 시 저비용).

→ 결론: **(c) 정상 작동. 코드 변경 없이 목표 충족. 수동 입력은 외부 결과용이라 유지.** 위 nuance는 원하면 별도 태스크.
