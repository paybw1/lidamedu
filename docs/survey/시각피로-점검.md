# 시각 피로(눈 피로) 전반 점검 — 측정 진단 + 우선순위

> 읽기 전용 점검(코드 0). 수험생이 하루 몇 시간 정독하는 플랫폼 — 측정 가능한 요소(대비율·글자크기·행간·다크배경값·줄길이·밀도)를 진단하고, 주관적 편안함은 라이브 확인으로 분리. 개선은 **토큰 레벨(한 곳 → 전파)** 우선.
> 측정 출처: `app/app.css`(토큰 SSOT) + 정독 화면(조문/판례/해설) 컴포넌트 실측(2026-06-28).

---

## 1. 색·명암 (대비·눈부심)

### 측정값 (app.css)
| 토큰 | Light | Dark |
|---|---|---|
| `--background` | `#ffffff` (순백) | `#252525` (다크 회색, **순검 아님 ✅**) |
| `--foreground` | `#252525` (≈검정, 순검 아님 ✅) | **`#ffffff` (순백 ⚠)** |
| `--card` | `#ffffff` | `#333333` |
| `--muted-foreground` | `#64748b` (slate-500) | `#b5b5b5` |
| `--primary` | `#2d5ba8` (딥 블루) | `#3b6fc4` |
| `--border` | `#e5e9ef` | `rgba(255,255,255,0.1)` |

### 본문 대비율 (계산)
- **Light**: `#252525` on `#ffffff` ≈ **15:1**
- **Dark**: `#ffffff` on `#252525` ≈ **15:1**
- WCAG AAA(본문) = 7:1. → **양 모드 모두 ≈15:1 = AAA의 2배 = "과한 대비"**. 정독 권장대(약 10~13:1)보다 강함 → 장시간 정독 시 눈부심·피로.

### 객관적 문제
- **⚠ [P1] 다크모드 본문이 순백 `#ffffff`**: 배경 `#252525`(비순검=좋음) 위 **순백 글자 = halation(글자 번짐)** — 다크 눈부심의 핵심 원인. 배경은 이미 잘 잡혀 있으나 **글자가 너무 밝음**. (card/popover/secondary/sidebar foreground도 전부 `#ffffff`.)
- **⚠ [P2] Light 본문 대비 ≈15:1 + 순백 배경**: 본문색 `#252525`은 이미 톤다운(좋음)이나 **배경이 순백**이라 종합 대비가 강함. 장시간 정독엔 살짝 톤다운(off-white)이 편함.
- **✅ 채도**: `--primary` 딥블루(중채도), chart 팔레트 중채도, 하이라이트는 파스텔(α 0.5~0.7). **큰 면적의 고채도 색 없음** → 채도 피로 낮음. 문제 아님.

## 2. 글자 (가독성·정독)

### 측정값 (정독 화면 실측)
| 화면 | 본문 크기 | 행간 | 줄 최대폭 | 비고 |
|---|---|---|---|---|
| 조문 뷰어 | **17px** | **1.85** | `max-w-[800px]` ✅ | 보조(개정메모·각주) **10px ⚠** |
| 판례 뷰어 | **17px** | 1.8 | **제한 없음 ⚠** | 본문색 `foreground/90`(경미 흐림) |
| 문제 발문/해설 | 17px / 16px | 1.8 / 1.85 | (3-pane 중앙) | `--study-fs` 적용 ✅ |
| **MarkdownView 공용 root** | **`text-xs` = 12px ⚠** | 1.625 | `max-w-none` | prose 미사용 |
| 표 (MarkdownView / 판례) | 12px / 14px | — | — | |

- **글꼴**: **Pretendard Variable**(한국어 정독 최적 — 적절 ✅). `--font-serif`도 Pretendard로 통일(조문 `font-serif`가 실제론 sans 렌더 — 피로 문제 아님, 의도된 serif 구분만 무효).

### 객관적 문제
- **⚠ [P3] MarkdownView root = 12px(text-xs)**: 공용 마크다운 렌더의 **기본 본문이 12px** — 정독엔 과소. 대부분 호출부가 14~17px로 덮지만, **오버라이드 없는 경로(science 문제 해설·선지)는 12px 그대로 노출**. 안전 기본을 ≥14px로.
- **⚠ [P3] 판례 본문 줄 최대폭 없음**: 조문은 `max-w-[800px]`로 줄길이 제한(45~50자, 적정). **판례는 제한 없어** 좌/우 패널 접으면 한 줄이 1500px까지 퍼짐 → 줄길이 과다(정독 피로). 조문과 불일치.
- **⚠ [P3] 작은 보조 텍스트 10px**: 조문 개정메모·각주가 본문 흐름 내 10px.
- **✅ 본문 크기·행간**: 조문/판례/발문 17px·행간 1.8~1.85 = **정독 적정**(문제 아님). 줄길이도 조문은 양호.

## 3. 여백·밀도

- 정독 본문 컬럼: 행간 1.8+·패딩 충분 → **본문 자체 밀도 양호**.
- **조문/판례/문제 뷰어 = `max-w-screen-2xl`(1536px) 3-pane**(좌 트리·중앙 본문·우 패널). 데스크톱에서 정보 밀도 높음(단 패널 접기 가능). `StudentShell`의 "읽기=narrow(768px)" 규칙이 **정독 뷰어엔 미적용**.
- 객관적 문제는 경미 — 밀도는 주관 비중이 커 **라이브 확인 항목**(3-pane가 답답한지).

## 4. 사용자 선택권

| 기능 | 상태 |
|---|---|
| 다크/라이트 전환 | **있음 ✅** |
| 글자크기 조절(`--study-fs` 3단 가-가-가) | **problem-viewer(법학 문제) 1곳 전용 ⚠** |
| 조문 뷰어 글자크기 조절 | **없음 ⚠** |
| 판례 뷰어 글자크기 조절 | **없음 ⚠** |
| science(자연과학) 문제 글자크기 | **없음 ⚠** |
| 읽기/집중 모드 | **없음** |

### 객관적 문제
- **⚠ [P4] 정독 비중 최대인 조문·판례에 글자크기 조절·읽기모드 부재**: `--study-fs`는 이미 `:root` 토큰이나 problem-viewer 요소만 참조 → 문제에서 키워도 조문/판례로 이동하면 **무반영**(고정 px). 눈 상태·기기·시간대별 편의 차 큰데 선택권 없음 = 효과 큰 gap.

## 5. 움직임

- 전역 keyframes = `caret-blink`(OTP 입력)·`fast-pulse`(로딩) 2개뿐. 커스텀 페이지 전환 없음(브라우저 기본 crossfade).
- **정독(조문/판례) 화면 내 무거운 애니메이션 없음 ✅** — 접힘 알약 `hover:-translate-y-px`(1px, 경미)만.
- 무한 반복(`animate-pulse`)은 빈칸·암기·OTP 등 **비정독 컨텍스트 한정**.
- 목록/허브 카드 hover lift(`transition-all` + `-translate-y-0.5` + shadow) 다수 — 정독과 분리, 경미.
- **객관적 문제 거의 없음.** (`transition-all` → 특정 속성 한정은 미세 최적화, 피로와 무관 수준.)

## 6. 진단 + 우선순위

### 우선순위 (피로 감소 효과 ↑ · 토큰 레벨 우선)

| 순위 | 항목 | 수정 레벨 | 효과 / 근거 |
|:---:|---|---|---|
| **P1** | **다크 본문 순백 `#ffffff` → 톤다운 off-white(예 `#e6e6e6`/oklch~0.92)** | **토큰(app.css `.dark` 1~수 줄)** | halation 직접 해소. **한 곳 → 전 다크화면 전파.** 최고 효과·최저 위험. card/popover/secondary/sidebar fg 순백도 일관 톤다운 |
| **P2** | **Light 정독 배경 순백 완화**(off-white 읽기 배경 토큰, 예 `#fafafa`) 또는 본문 약간 톤다운 | **토큰** | 15:1 과대비 완화. 단 전역 `--background` 변경은 영향 넓음 → 읽기 표면 한정 토큰 권장. **주관 큼 → 라이브 병행** |
| **P3** | MarkdownView root 12px → **14px(text-sm) 기본** | 컴포넌트 단일 소스(markdown-view.tsx) | 오버라이드 없는 경로 정독 보정 |
| **P3** | 판례 본문 `max-w`(예 800px, 조문과 통일) | 컴포넌트(case-body.tsx) | 줄길이 과다 해소 |
| **P3** | 조문 보조 10px → 11~12px | 컴포넌트(article-body.tsx) | 작은 글자 완화 |
| **P4** | **`--study-fs`(기존 토큰)를 조문·판례·science 정독에 확장 + 공용 글자크기 컨트롤·읽기집중 모드** | 토큰 활용 + 컴포넌트 | 정독 비중 최대 화면에 사용자 선택권. 효과 크나 신규 기능(별도 태스크) |

> **권장 착수 순서**: P1(다크 순백→톤다운, 토큰 1곳) → P2(라이트 대비 완화, 라이브 확인 병행) → P3(작은 글자·판례 줄길이, 컴포넌트) → P4(글자크기 조절 확장, 신규 기능). P1·P2는 토큰 레벨이라 한 곳 수정으로 전파.

### 라이브 확인 항목 (주관적 — 사용자가 직접)
- 다크 본문을 off-white로 낮췄을 때 **밝기 적정선**(너무 흐려 안 읽히지 않는지) — 개인차.
- 라이트 대비 완화(off-white 배경)가 실제로 **편한지** vs 흐려 보이는지.
- 조문/판례 **줄길이**(800px) 체감 — 더 좁게/넓게.
- **Pretendard** 장시간 정독 체감(글꼴 만족도).
- 3-pane **밀도** 답답함 여부(패널 기본 접힘 선호?).
- 글자크기 3단(0.9/1/1.18) 폭이 충분한지, 더 큰 단계 필요한지.

## 적용 내역 (2026-06-28 — P1·P2·P3)

- **P1 (토큰)** `app.css .dark` 본문 fg 3종(`--foreground`·`--card-foreground`·`--popover-foreground`) **순백 `#ffffff` → off-white `#e6e6e6`**. 다크 halation 완화(≈15:1→≈12:1). 배경(#252525)·버튼/뱃지 fg(primary/secondary/sidebar)는 유지.
- **P2 (토큰)** `app.css :root` 본문 fg 3종 **`#252525` → `#2e2e2e`**. 라이트 과대비 완화(≈15:1→≈14:1). ★**라이브 적정선 확인 필요**(주관 — 더 톤다운 vs 원복).
- **P3a (컴포넌트)** `markdown-view.tsx` root **`text-xs`(12px) → `text-sm`(14px)**(오버라이드 없는 경로 정독 보정), 표 12→13px·code/pre 11→13px(전부 `--study-fs` calc 유지). 헤딩은 problem-viewer 연동이라 미변경.
- **P3b (컴포넌트)** `article-body.tsx` 개정메모 inline 텍스트 **10px → 12px**(각주 `<sup>`는 마커라 유지).
