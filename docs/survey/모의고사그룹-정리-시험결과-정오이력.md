# 모의고사 그룹 정리 — 시험결과 일원화 · 정오 이력 약점탭 편입 (점검·설계)

> 점검·설계 문서(코드 0). 작성 2026-06-24. 근거 file:line.
> 핵심: 두 항목("응시 결과"·"정오문제 응시 이력")은 **단순 이동이 아니라 기존 통로와 합치기** —
> 시험결과 입력 → **대시보드 허브**, 정오 이력 → **학습현황 약점 탭**. /me 전용 화면은 유지(전체관리).

## 0. 한눈 결론

- 모의고사 그룹에서 두 항목을 빼면 **남는 5개가 전부 "시험 보기·훈련" 표면**이라 그룹이 더 순수해진다(현재는 "내 결과/기록" 2개가 섞여 있음).
- 두 항목은 **이미 더 적합한 합류처**가 있다: 시험결과=대시보드 입력 허브(ResultBlock, `/me/exam-results` 전체관리 링크 보유), 정오 이력=약점 탭(이미 OX 약점 진단 매트릭스가 있음). → **"합치기"가 자연스럽다.**
- nav SSOT(`nav-groups.ts`) 한 곳에서 2줄 제거 → 상단바·사이드바·하단탭·AreaTabs 자동 반영. **라우트는 유지**(`/me/exam-results`·`/me/ox-sessions`) → redirect 불요·딥링크 보존·죽은 링크 0.
- 위험 2개: ①시험결과 **발견성**(허브 뒤로 들어감) ②약점 탭 **과부하**(이미 큼+defer). 둘 다 설계로 흡수(허브 노출 유지+contextual CTA / 이력은 compact 섹션+전체는 /me 유지).

## 2. 시험결과 입력 일원화 (허브 주 통로)

### 2.1 현황
- **대시보드 입력 허브**(`dashboard/components/student-input-hub.tsx`) `ResultBlock`: `<fetcher.Form action="/me/exam-results">` + `ResultFields`(빠른 입력) + 우상단 **"전체 관리 →"** `Link to="/me/exam-results"`. 트리거 = 대시보드 헤더 밑 "내 정보 설정" 버튼(+차수·시험일 미설정 시 자동 오픈).
- **`/me/exam-results`**(`exam-results/screens/my-exam-results.tsx`): 전체관리 — 연도×차수 이력, **합격증 업로드·검증**, 차기 응시 계획, 결과 차수 필터. 헤더에 "빠른 입력은 대시보드 '내 정보 설정'에서도" 역링크 보유.
- **입력 폼 단일화 완료**: `ResultFields`(exam-results/components)를 허브·`/me` 신규폼이 공유(드리프트 0, 학생입력허브 단계1~3).

### 2.2 정리안
- **주 통로 = 대시보드 허브**(상시 노출 버튼+자동 오픈) — 시험결과 빠른 입력의 1차 동선.
- **전체관리 = `/me/exam-results` 유지** — 합격증·검증·이력은 Sheet에 못 담음. 허브 "전체 관리 →"로 진입.
- **모의고사 nav "응시 결과" 항목 제거.**

### 2.3 ★발견성 보존 (위험 ①)
- `/me/exam-results` 진입 경로(현재, nav 외): 허브 "전체 관리 →" · 추천카드 CTA(`recommendations.ts:409` ctaUrl) · 합격자 추이/후기/선택과목 가이드 카드(`passer-trend`·`passer-summaries`·`passer-cases-components`·`electives-guide`) · 온보딩 안내 · 회수 cron 이메일. → **nav 항목 빼도 다중 경로 생존.**
- 단, **유일한 "상시 메뉴" 진입점이 사라진다** → 합격증 업로드 같은 가끔 작업은 "대시보드 → 내 정보 설정 → 전체 관리" 3스텝. **수용 가능하나 발견성 저하**. 완화: (a) 허브 "전체 관리 →" 라벨·위치 명확 유지 (b) 시험 직후 추천카드가 이미 /me로 CTA — 적시 노출. (선택) 합격자 비교 게이트 OFF 카드에서 "결과 입력" 링크 강조.
- **죽은 링크 0**: nav `/me/exam-results` 참조는 `nav-groups.ts` **한 곳뿐**(grep 확인). 인라인 링크는 컴포넌트 레벨이라 무관. 라우트 유지 → 직접 URL·딥링크 생존.

## 3. 정오 이력 → 학습현황 약점 탭 편입

### 3.1 약점 탭 현황 (`stats.tsx` `WeaknessTab` 1376)
순서: ① KPI 그리드(오답 큐[객관식+정오문제] 등 4카드) → ② 약점 테이블(어려운 글로벌+내 오답, 상위 5) + ReflectedInTodayNote → ③ **OX 정오문제 약점 진단 매트릭스**(단원×지식종류, `OxDiagnosisView`, **streaming defer**: `<Suspense fallback={OxDiagnosisLoading}><Await resolve={oxDiagnosis}>`). loader가 `computeOxDiagnosis`를 **await 안 하고** 스트리밍(가장 무거운 헬퍼). 탭 전체가 `hasMyAnalysisConsent`(A동의) 게이트.

→ **이미 길고 무겁다(매트릭스 defer).** 여기 OX 이력 "전체 리스트"를 통째로 넣으면 과부하.

### 3.2 편입안 — compact 섹션(전체는 /me 유지)
- **약점 탭에 "정오문제 응시 이력" compact 섹션** 추가: **최근 3~5 회차**(팩·정답률·일시) + **"전체 이력 →"** `Link to="/me/ox-sessions"`. 위치 = **OX 진단 매트릭스 바로 아래**(둘 다 정오문제 → 진단=집계 분석 / 이력=회차 기록, 자연스러운 한 묶음).
- **데이터**: stats loader에 `listMyOxSessions(client, user.id, {limit: 5})` 추가(경량 1쿼리). 매트릭스처럼 defer 불필요(가벼움). A동의 게이트 안에 들어가므로 OFF면 미표시(일관 — "내 분석"). 
- **`/me/ox-sessions` 전체 화면 유지**: 기간·과목 필터·진입 CTA·회차 결과 뷰(`/me/ox-sessions/:sessionId`)는 백로그까지 방금 만든 자산 → 폐기 금지. 약점 탭은 **진입(preview)만 흡수**, 전체는 /me.
- 행/링크 → **결과 뷰**(`/me/ox-sessions/:sessionId`) 또는 "전체 이력"으로. (방금 만든 결과 뷰 링크 유지.)

### 3.3 과부하 회피 (위험 ②)
- compact(최근 N건)만 → 탭 길이 증가 최소. 전체 리스트는 한 클릭(/me).
- 매트릭스는 defer 유지(변경 0) — 이력 preview는 loader 데이터(즉시)라 매트릭스 스트리밍과 독립.
- (대안, 더 가벼움) 리스트 대신 **요약 스트립** 1줄("정오문제 응시 N회 · 최근 정답률 X% · 전체 이력 →"). 과부하가 우려되면 이쪽. — **권장: 최근 3건 + 링크**(편입 의미 살리되 bounded).

### 3.4 메뉴 처리
- 모의고사 nav "정오문제 응시 이력" 제거(약점 탭 preview가 새 진입점). **`/me/ox-sessions` 라우트 유지** → 약점 탭·대시보드 OxRecentCard·결과뷰 back-link에서 도달. **redirect 불요**(페이지가 살아 있음 — /goals 사례와 다름: /goals는 폼이 이전돼 빈 페이지라 redirect했지만, /me/ox-sessions는 전체관리 페이지로 존속).

### 3.5 발견성 보존
- nav 제거 후 OX 이력 진입: **대시보드 OxRecentCard**(`dash-ox`, 이미 /me/ox-sessions 링크) + **약점 탭 preview**(신규) + 결과뷰 back-link. → 다중 경로 생존.
- 단 약점 탭 preview는 A동의 게이트 안 / 대시보드 카드·/me 전체는 비게이트 → preview만 동의 OFF 시 안 보임(수용 — 전체 페이지는 항상 접근).

## 4. nav SSOT · churn

- **SSOT = `nav-groups.ts` `NAV_GROUP_POOL.mock.items`**. 6·7 **2줄 제거**가 유일 변경 → `topbarDropdownItems`/`areaTabItems`/사이드바/하단탭/AreaTabs 전부 파생이라 **자동 일관**(드리프트 불가, 통폐합 설계 패턴).
- **라우트 유지**: `routes.ts`의 `/me/exam-results`·`/me/ox-sessions`(+`:sessionId`)는 그대로. nav에서만 빠짐 → **직접 URL·외부 딥링크·인라인 링크 전부 생존, redirect 0.**
- **죽은 링크 0**: 두 to(`/me/exam-results`·`/me/ox-sessions`)의 nav 참조는 `nav-groups.ts` 단일(grep). 제거해도 컴포넌트 인라인 링크 무관.
- **남은 모의고사 그룹 churn**: 항목 7→5. 라벨·순서·area 변경 없음. 모바일 단축 라벨(`MOBILE_TAB_LABELS.mock="모의"`) 무관.
- (선택) 약점 탭 preview용 stats loader에 `listMyOxSessions(limit:5)` 1줄 추가 — nav와 무관한 데이터 배선.

## 5. 설계 + 단계안

### (1) 시험결과 일원화
- 허브 ResultBlock = 주 입력 통로(현존) · `/me/exam-results` = 전체관리(현존, 유지) · nav "응시 결과" 제거. 발견성 = 허브 노출 유지 + 추천/합격자 카드 contextual CTA(현존).

### (2) 정오 이력 약점탭 편입
- 약점 탭 OX 진단 매트릭스 아래 **compact 이력 섹션**(최근 3 + "전체 이력 →") 신설(loader `listMyOxSessions(limit:5)` 추가) · `/me/ox-sessions` 전체 유지 · nav "정오문제 응시 이력" 제거.

### 단계안 (독립 출하)
| 단계 | 내용 | 규모 | 위험 |
|---|---|---|---|
| **A. 정오 이력 편입** | 약점 탭 compact 섹션(loader 1쿼리 + WeaknessTab 섹션) → 동작 확인 → **그 다음** nav "정오문제 응시 이력" 제거 | S | 과부하(→compact로 회피) |
| **B. 시험결과 nav 정리** | nav "응시 결과" 제거(허브·/me는 이미 존재라 코드 거의 0) + 발견성 점검(허브 버튼·CTA 노출 확인) | XS | 발견성(→다중 경로 확인 후 제거) |

- **순서 = A → B**(A는 새 진입점을 먼저 만들고 메뉴 제거; B는 진입점이 이미 있어 메뉴만 제거). **각 단계: 새 진입점/대체 경로 먼저 확인 → 그 다음 nav 항목 제거**(발견성 공백 0).
- nav 제거는 **prod 배포**(통폐합=학생 표면 변경)이므로 단계별 로컬 확인 후 커밋.

### 위험 요약
- **발견성**: 시험결과·정오 이력 모두 nav 단일 진입점이 사라짐 → 허브/약점탭/대시보드 카드/contextual CTA로 분산 보존(확인 필수). 
- **과부하**: 약점 탭 → compact(최근 N + 링크)로 제한, 전체는 /me.
- **딥링크**: 라우트 유지라 0(redirect 불요). nav SSOT 2줄이라 churn 최소.
