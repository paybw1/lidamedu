## 1. 현재 타이포 현황

- **패밀리**: 랜딩 전 섹션이 인라인 `font: "<weight> <size>/<lh> Pretendard, sans-serif"` 숏핸드. `home.tsx` 루트 `fontFamily`도 Pretendard. **단일 family.** (`--font-sans` 토큰은 안 씀 — 숏핸드에 "Pretendard" 하드코딩.)
- **위계 = weight+size+tracking만**:
  - hero H1 `800 clamp(34,5vw,56)/1.15` ls −0.025em
  - 섹션 H2(`section-header.tsx`) `800 clamp(24,3.4vw,34)/1.25` ls −0.022em
  - eyebrow `600 12px/1` uppercase ls 0.12em (영문: WHY LIDAM·INTEGRATED FLOW·DASHBOARD…)
  - 본문/부제 `400 16~17px/1.7`, 칩/메타 `500~600 11~13px`
  - 숫자(D-day·통계) Pretendard `800` tabular-nums
- **로딩**(`root.tsx` links): Geist(100–900)·**Noto Sans KR(400–700)**·**Noto Serif KR(400–600)**·Caveat(400,600) + Pretendard Variable(jsdelivr). → 명조·라틴 디스플레이 후보가 **이미 네트워크에 있음**.
- **`--font-*` 토큰**(`app.css`): `--font-sans`=Pretendard 우선, `--font-serif`=Pretendard로 별칭(주석: "단일 family 요청"). **`--font-display` 슬롯 없음**(신설 쉬움 — @theme에 1줄).
- **테마 기본 = 다크**(`root.tsx` specifiedTheme "dark"). → 디스플레이 폰트는 다크 배경에서 얇으면 약하므로 **≥600 weight** 권장.

## 2. 디스플레이 적용 지점

- **적용(큰 글자·첫인상)**: hero H1, `SectionHeader` H2(7섹션 공용), `preview`·`final-cta` H2. = 제목 ~4종 `font:` 숏핸드의 family만 교체(또는 `--font-display`/`landing.tsx` `FONT` 상수 참조).
- **유지(가독성)**: 본문·부제·칩·버튼·UI = Pretendard. 숫자는 Pretendard tabular 유지(또는 Geist 라틴 tabular = 테크 느낌, 선택).
- **eyebrow(영문)**: Pretendard 유지 or 디스플레이 small-caps/Geist — 선택지(§4).
- **구현 용이성**: 인라인 숏핸드라 family만 바꾸면 됨. `landing.tsx`에 `FONT = { display, body }` 상수(PALETTE 옆) 두고 제목에서 `FONT.display` 참조 = 색 SSOT(PALETTE)와 같은 패턴, 한 곳 관리.

## 3. frontend-design 타이포 가이드 (이 환경)

- **페어링 권장**: "distinctive **display** + refined **body**". → 제목 디스플레이 × 본문 Pretendard 정확히 부합.
- **회피**: generic(Inter/Roboto/Arial/system) + **★특정 폰트로 수렴 금지(Space Grotesk 명시)**. → 트렌디 라틴 그로테스크(Geist 포함) 남용 주의.
- **한글 디스플레이 가용성**: Google Fonts 한글은 **unicode-range 동적 서브셋** — 쓰는 글자만 로드(제목만 적용 시 매우 경량). Noto Serif KR은 **이미 로드**. Gowun Batang·Song Myung 등은 +1 링크(동적 서브셋).
- **성능 원칙**: 디스플레이는 제목에만 + weight 1~2종 제한 + `display=swap`(이미 적용). 첫인상 페이지라 로드 경량 유지.

## 4. 폰트 방향 (선택용 — 페어링·위계·tradeoff·성능)

### A. 명조 디스플레이 (격조·법률 적합) — ★추천
- **폰트**: 기본 **Noto Serif KR**(이미 로드, 0 추가) / 개성형 **Gowun Batang**(고운바탕 — 모던·우아) · **Song Myung**(송명 — 에디토리얼·강한 개성) [+1 링크, 경량].
- **페어링**: 명조 제목 × Pretendard 본문 = **serif×sans 강한 위계**, 판결문·법전 톤의 신뢰·격조.
- **위계 스케일**: H1/H2 = 명조 **700**(다크 대응) ls −0.01~0em(명조는 음수 트래킹 과하면 뭉침), 본문 Pretendard 400~500, eyebrow Pretendard 유지.
- **tradeoff**: 도메인 최적·위계 최강·(Noto는)0 추가. 단 Noto Serif KR은 **안전하나 다소 표준적**(개성 원하면 Gowun/Song). 작은 글자엔 명조 가독성↓ → **큰 제목에만**.
- **성능**: Noto Serif KR=0(이미). Gowun/Song=+1 링크·동적 서브셋(제목 글자만).

### B. 모던 디스플레이 산세 (현대적·강한 위계)
- **폰트**: 한글 디스플레이 산세 — **Gmarket Sans**(기하·강함) / **Wanted Sans**(랜딩의 Wantedly 톤과 결). (Geist는 **라틴 전용 — 한글 미렌더**라 한글 제목엔 부적합.)
- **페어링**: 디스플레이 산세 제목 × Pretendard 본문 — 현대적·테크.
- **위계**: H1/H2 = 디스플레이 산세 700~800, 본문 Pretendard.
- **tradeoff**: 현대적이나 **sans×sans라 대비 약함**(디스플레이가 충분히 distinctive해야), frontend-design "generic sans 회피"·Wanted Sans는 Pretendard와 유사 계열이라 차이 미미할 수 있음. **추가 로딩** 발생.
- **성능**: +1 링크(한글 서브셋, 산세라 Noto Serif보다 약간 큼).

### C. 영문 eyebrow·숫자만 디스플레이 (절충·저위험)
- **폰트**: 영문 eyebrow(WHY LIDAM 등)·숫자(D-day·통계)에 **Geist**(이미 로드) 또는 라틴 세리프(Newsreader/Fraunces, +1 경량). 한글 제목·본문은 Pretendard 유지.
- **페어링**: 한글 Pretendard + 라틴 악센트.
- **tradeoff**: **매우 경량·저위험**(라틴 서브셋 소형), 에디토리얼 악센트. 단 **한글 H1(첫인상 핵심)은 그대로** → 차별성 제한적. Geist는 트렌디(수렴 주의).
- **성능**: 거의 0(Geist 이미 로드 / 라틴만).
