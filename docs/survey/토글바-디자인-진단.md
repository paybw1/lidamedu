# 영역별 화면 토글 바(SectionTabs) 디자인 정합성 진단 (읽기 전용)

> 대상: 학습관리(StudyMgmtTabs)·학습지원(StudyAidsTabs)·학습정보(LatestTabs)·학습과목(신설 SectionTabs) + SectionTabs 사용처.
> 기준: frontend-design(응집·일관·의도성). 코드 변경 0.
> **결론(먼저)**: **네 영역 모두 공용 `SectionTabs` 프리미티브를 쓴다(좋음 — 자체 구현·다른 래퍼 없음).** 기본 스타일(활성 색·탭 크기·타이포·폭)도 프리미티브 덕에 이미 동일. 갈리는 건 **호출 props·렌더 위치 두 가지**: ① **위치/sticky**(레이아웃 최상단 고정 vs 셸 내 헤더 아래 비고정) ② **탭 장식**(아이콘 / 색 dot / 아무것도 없음 3종). 즉 "다른 컴포넌트"가 아니라 **같은 컴포넌트에 다른 props·다른 배치**.

---

## ① 공용 토글 컴포넌트 공유 여부 — 전부 `SectionTabs` (자체 구현 없음)

| 영역 | 토글 함수 | 렌더러 | SectionTabs 호출 |
|---|---|---|---|
| 학습관리 | `StudyMgmtTabs` | study-management.layout (`<StudyMgmtTabs/><Outlet/>`), srs-review·srs-stats 직접 | `ariaLabel="학습관리"`, **sticky 기본(true)**, items=icon |
| 학습지원 | `StudyAidsTabs` (study-aids-shell 내부) | StudyAidsShell 헤더 아래 | `ariaLabel="학습지원"`, **sticky={false}**, items=icon+count |
| 학습정보 | `LatestTabs` (latest-shell 내부) | LatestShell 헤더 아래 | `ariaLabel="학습정보"`, **sticky={false}**, items=dotClass(아이콘 없음) |
| 학습과목 | (subjects.layout 직접) | subjects.layout (`<SectionTabs/><Outlet/>`) | `ariaLabel="학습과목"`, **sticky 기본(true)**, items=장식 없음 |

→ 기반은 단일 프리미티브. **활성 스타일(`bg-primary text-primary-foreground`)·비활성(`text-ink-soft hover`)·탭 크기(`text-sm font-medium px-3 py-1.5`)·폭(`mx-auto max-w-screen-xl`)·가로 스크롤은 전부 SectionTabs 소유 → 이미 동일.** 차이는 props·위치뿐.

## ② 영역별 토글 바 시각 감사

- **학습관리**: study-management.layout 이 `<StudyMgmtTabs/>` 를 **Outlet(=화면) 위에** 렌더 → 화면 자체 헤더보다 **위**, 화면 **상단 고정(sticky)**. 탭에 **아이콘**(Sparkles/Repeat/Layers/Target/ListChecks/ClipboardList/MessageSquare). srs-review·srs-stats 도 동일 토글을 직접 렌더.
- **학습지원**: StudyAidsShell 이 `<header>`(eyebrow "STUDY AIDS·학습지원" + h1 `text-[28px]` + 설명 + PDF버튼) **다음에** 탭(`mb-[18px]`, **비고정**). 탭에 **아이콘 + count 배지**(본인 보유 건수).
- **학습정보**: LatestShell 이 `<header>`(eyebrow "LATEST·학습정보" + h1 `text-[28px]` + 설명) **다음에** 탭(**비고정**). 탭에 **아이콘 없음 — 대신 카테고리 색 dot**(emerald/violet/amber/rose/sky/갈색/teal).
- **학습과목(신설)**: subjects.layout 이 Outlet 위에 탭(**상단 고정**). **아이콘·dot 둘 다 없음**(라벨만).

## ③ ★ 비교 대조표

| 시각 항목 | 학습관리 | 학습지원 | 학습정보 | 학습과목 |
|---|---|---|---|---|
| 컴포넌트 | SectionTabs | SectionTabs | SectionTabs | SectionTabs |
| **렌더 위치** | 레이아웃 최상단(화면 헤더 **위**) | 셸 내 **헤더 아래** | 셸 내 **헤더 아래** | 레이아웃 최상단(콘텐츠 **위**) |
| **sticky** | **true**(고정) | **false** | **false** | **true** |
| **탭 장식** | **아이콘** | **아이콘** | **색 dot**(아이콘 ✗) | **없음** |
| **count 배지** | ✗ | **있음** | ✗ | ✗ |
| 활성 스타일 | bg-primary | (동일) | (동일) | (동일) |
| 탭 크기/타이포 | text-sm font-medium | (동일) | (동일) | (동일) |
| 정렬/폭 | mx-auto max-w-xl, 좌측, 가로스크롤 | (동일) | (동일) | (동일) |

**가장 갈리는 2항목**:
1. **위치/sticky** — 관리·과목 = 레이아웃 최상단 고정(화면 헤더보다 위), 지원·정보 = 셸 안 헤더 아래 비고정. **시각 위계가 정반대**(토글 먼저 vs 제목 먼저).
2. **탭 장식** — 아이콘(관리·지원) / 색 dot(정보) / 없음(과목) **3종**. ★사용자 지적 지점.
(활성·크기·폭은 이미 일치 — 프리미티브 공유 덕.)

## ④ 근본 원인

**"같은 SectionTabs인데 다른 props + 다른 렌더 위치"** — 다른 래퍼도, 미사용도 아님.
- **위치**: 관리·과목은 **레이아웃에서** 토글을 렌더(화면 위·sticky), 지원·정보는 **셸 컴포넌트 안에서** 헤더 다음에 렌더(비sticky). 두 패턴이 따로 자라남.
- **장식**: SectionTabs 가 `icon`·`dotClass`·`count` 를 **옵션**으로 지원 → 영역마다 다른 선택. 관리·지원은 아이콘, 정보는 dot(랜딩 색 계열 일관 의도), 과목(신설)은 아무것도 안 줌.
- **count**: 지원만 데이터(보유 건수)가 있어 배지 사용.
→ 정책(아이콘 줄지·sticky 둘지)이 **한 곳에 표준화돼 있지 않아** 호출처마다 갈림.

## ⑤ 통일 기준 + 방향

### 결정거리 (사용자 판단)
1. **아이콘 정책** (3안):
   - (a) **전부 아이콘** — 관리·지원 현행. 스캔성↑, SectionTabs 지원. 단 과목 6개·정보 6개에 적절한 lucide 아이콘 지정 필요.
   - (b) **전부 색 dot** — 정보 현행. 절제된 톤, 카테고리 색 구분.
   - (c) **전부 없음(라벨만)** — 과목 현행. 가장 미니멀.
   - 권장: **(a) 전부 아이콘** (이미 2영역 사용 + 의미 전달). 정보의 색 dot 은 보조로 유지 가능(아이콘+dot 병행) 또는 제거.
2. **위치/sticky** (2안):
   - (a) **레이아웃 최상단 sticky**(관리·과목 현행) — "영역 네비"로서 항상 보임. 지원·정보도 셸의 헤더 위로 토글을 올리고 sticky 통일.
   - (b) **셸 내 헤더 아래 비sticky**(지원·정보 현행) — 페이지 제목 먼저, 토글은 그 아래.
   - 권장: **(a) 최상단 sticky 통일** — 영역 이동 토글은 스크롤해도 보이는 게 일관·강력. (지원·정보 헤더는 토글 아래로.)
3. **활성 스타일**: 이미 동일 — **조정 불요**.
4. **count 배지**: 데이터 있는 지원만 유지 — 무해, 표준화 불요(옵션 유지).

### 방향 (단계적)
- **ⓐ 정책 표준화**: SectionTabs 위에 얇은 공용 래퍼(예: `AreaTabs`) 또는 호출 규약을 정해 **sticky·아이콘 정책을 한 곳에서 고정**. 네 영역이 같은 규약으로 렌더 → 드리프트 방지(토글 SSOT 파생과 같은 원리).
- **ⓑ 적용**: 결정된 아이콘 정책으로 4영역 통일 → 결정된 위치/sticky 로 통일. 영역 하나씩, 시각만(기능 무변경).
- 권장 순서: **아이콘 정책 먼저(가장 눈에 띄는 차이) → 위치/sticky.** 가장 작은 영역(학습과목·신설)으로 먼저 적용·확인 후 확대.

코드 0 — 진단·기준 후보 제시까지.
