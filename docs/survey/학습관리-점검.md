## 2. "오늘 할 일"(`/study/today`) 정밀 점검

### 2.1 화면 구성 (학생이 보는 것)
`today.tsx` 렌더 순서(`StudentShell width="narrow"`):
1. **헤더** — KST 날짜(요일 포함) + "오늘 할 일" 제목.
2. **진행률 바**(`ProgressBar`, `today.tsx:112-136`) — "오늘 할 일 N개 중 **0**개 완료 · 0%". (★아래 2.5 참조: completed 하드코딩)
3. **① 복습 카드**(`ReviewCard`, 최우선, 빨강 "최우선" 칩) — `review.totalToday`>0일 때만. v1·v2 둘 다 있으면 "문제 복습 X개 · 암기 카드 Y개 [베타]" 부가 표기, primary 버튼은 `hasV1?/study/srs:/srs`.
4. **② 오늘의 학습**(`RecommendationsCard`) — 추천 항목 리스트(슬롯별 1줄: 우선/권장/추가 칩 + 예상 분 + 제목 + 본문 + CTA 링크). 합계 예상 시간 표기.
5. **③ 종합반 과제**(`AssignmentsCard`) — cohort 멤버만. 미완 top 3(진척% · D-day) + "전체 과제함 보기". 0건이면 "모두 완료" 점선 카드.
6. **푸터** — "학습 추세·통계는 학습 통계에서 · 추천 슬롯 설정은 통계 하단으로 이동했어요"(★stale, 2.5).

설계 의도가 주석에 명시: "순수 행동 화면 — 4가지 외 항목 금지, 통계·도구·추세는 두지 않음"(`today.tsx:1-3`). 이 절제는 잘된 점.

### 2.2 "오늘 할 일"을 정하는 로직
산출 단일 소유 = `getTodaySummary()`(`today-summary.server.ts:76`), 5개 병렬:

**(A) 복습 = 2종 SRS 합산**
- v1 객체별 SM-2: `getProblemSrsCounts`(`study/srs.server.ts`) → `problemDue`. 기준 `user_problem_srs.next_due_at <= now`.
- v2 능동 플래시카드: `getReviewQueue`(`srs/srs.server.ts`) → `flashcardDue`+`flashcardNew`(일일 상한 `maxReviewsPerDay` 적용 후).
- `totalToday = problemDue + flashcardDue + flashcardNew`. `hasBacklog`는 **추정**(표시값 ≥ 상한이면 backlog로 간주, `today-summary.server.ts:94-95`).

**(B) 추천 = 7슬롯 합성**(`composeDailyMenu`, `daily-menu.server.ts:96`) — KST 하루 단위 스냅샷 캐시(`user_daily_recommendations`), 슬롯별 ON/OFF(`recommendation_prefs`) 후 병렬 평가:
| 슬롯 | 기준(우선순위) | 데이터 |
|---|---|---|
| weak_problem | 문제 SRS due 우선, 없으면 weak areas(글로벌 정답률↓) | `getDueProblems`/`getWeakAreas` |
| weak_article | 약점 문제의 미열람 근거 조문(importance순) | `problems.primary_article_id` + `study_sessions` |
| unread_case | importance≥3 미열람 판례(최신순) | `cases` |
| blank_due | 빈칸 SRS due 우선, 없으면 미시도 세트 | `getDueBlankSets`/`article_blank_sets` |
| gap_problems | 응시 과목 미풀이 객관식 랜덤 5 | `profiles.next_exam_round` + `user_problem_attempts` |
| cohort_track | 이번 주 트랙 미완 1개 | `getCurrentWeekTrack` |
| article_review | 조문 정독 복습 due | `getDueArticleReviews` |
→ `sortDailyMenu`로 priority(high/medium/low) 정렬. 슬롯당 **최대 1개** → 추천 최대 7개.

**(C) 과제** — `listStudentAssignments` 결과에서 미완(status≠completed) 필터, 마감 ≤3일 임박 카운트, top 3. cohort 비멤버는 전부 0.

**무엇이 "오늘 과업"인가**: 복습 due + (조건 충족 슬롯의) 추천 + 종합반 과제. **포함 안 되는 것**: 오답노트 backlog, 2차 주관식 첨삭 대기, OX 시험 due(추천 외), 미열람 상담 코멘트, 그리고 **학습 목표 자체**(2.5).

### 2.3 데이터 출처 / 다른 기능과의 연결
- 테이블: `user_problem_srs`·`srs_review_states`·`user_daily_recommendations`·`assignments`/`assignment_submissions`·`cohort_members` + 추천 슬롯들이 읽는 `study_sessions`·`user_problem_attempts`·`cases`·`article_blank_sets` 등.
- 연결: **복습**(SRS 큐)·**과제**(cohort)·**진도/약점**(추천 슬롯이 weak areas·study_sessions 소비)와는 잘 엮임. 대시보드 상단 카드와 `getTodaySummary` 공유로 숫자 일관(잘된 점).
- 단절: **목표(`study_goals`)와는 완전 비연결**(grep 0). `gap_problems`만 `profiles.next_exam_round`(목표 화면이 쓰는 필드와 별개)를 참조.

### 2.4 엣지 케이스
| 상황 | 동작 | 평가 |
|---|---|---|
| 신규(복습0·추천0·과제0) | `isEmptyForNewUser=true` → `EmptyStateCard`("아직 복습할 항목이 없어요" + 과목 시작 CTA) | 의도대로 |
| **오늘 다 끝냄**(베테랑이 큐를 비움) | 역시 `isEmptyForNewUser=true` → **신규용 문구** 노출("첫 학습을 시작하면…") | ★**버그성**: "완료"와 "신규"가 같은 카드로 뭉쳐 베테랑에게 엉뚱한 안내 |
| 비종합반 | 과제 카드 `null` 반환(숨김) | OK |
| 복습만 있고 추천/과제 0 | 복습 카드만, 진행률 바는 여전히 "0개 완료" | 진행률 결함 노출 |

### 2.5 ★빈틈·부실 (솔직)
1. **진행률 바가 항상 0%** — `completed = 0` 하드코딩(`today.tsx:114-116`, 주석 "정밀 측정은 후속"). 화면 맨 위 위젯이 무엇을 해도 안 움직인다. **가장 먼저 고칠 1순위.**
2. **신규/완료 상태 혼동** — `isEmptyForNewUser`가 "한 번도 안 한 학생"과 "오늘 다 끝낸 학생"을 구분 못 함(2.4). 완료 축하 대신 신규 가이드가 뜸.
3. **목표 미연동** — `study_goals`(시험유형·목표점수·시험일)를 today/추천이 안 읽음. 1차/2차 수험생 구분조차 추천에 반영 안 됨(`gap_problems`만 `next_exam_round` 사용). 목표가 "오늘 할 일"을 바꾸지 못한다.
4. **추천 설정 토글 UI 고아** — feat-2-021의 API(`/api/study/recommendation-prefs`)와 엔진(prefs 읽음)은 살아있으나 **토글 패널을 렌더하는 화면이 없음**(grep 0). 푸터는 "통계 하단으로 이동"이라 안내하지만 `stats.tsx`에 그 패널 없음 → **안내 stale + 슬롯을 끌 방법 없음**(기본 전부 ON이라 기능 손상은 아님).
5. **두 SRS 합산의 모호함** — "오늘 복습 N개"가 어느 시스템인지 학생이 알기 어렵다. 게다가 `암기 카드`는 카드가 없어 대개 v2=0 → 사실상 v1만인데도 "암기 카드 [베타]" 표기가 노출될 수 있다. primary 버튼 분기(`/study/srs` vs `/srs`)도 내부 구현이 새는 지점.
6. **`hasBacklog` 부정확** — 표시값이 상한과 정확히 같을 때 backlog로 오판 → "밀린 항목 우선" 칩이 거짓 표시될 수 있음.
7. **누락 과업 종류** — 오답노트·2차 첨삭 대기·미열람 상담 코멘트는 "오늘 할 일"에 안 뜸(추천 슬롯이 일부만 커버). "오늘만 보면 충분"이라 말하기엔 빠진 게 있다.
8. **성능 잠재** — 추천 슬롯들이 `study_sessions limit(5000)`·`problems limit(500)` 전량 스캔(`daily-menu.server.ts:213,397`). 하루 1회 캐시라 체감은 낮으나 첫 합성은 무겁다.
9. 모바일: narrow shell + 카드 스택으로 무난(주요 결함 없음).

**잘된 점(오늘 할 일)**: 절제된 4블록 설계, `getTodaySummary` 단일 소유로 대시보드와 숫자 일관, 7슬롯 우선순위·예상시간·하루 1픽 캐시, `runAfterResponse`로 viewed_at 마킹(서버리스 정합), 신규 빈 상태 가이드 존재.

## 3. 종합 — 어디부터 보면 좋은가
- **즉효(작은 수정, 큰 체감)**: ①진행률 실제 완수 측정 ②신규/완료 빈상태 분리(완료 축하 카드) ④추천 설정 패널 복원 or 푸터 안내 제거.
- **구조(중간 작업, 개인화 도약)**: ③목표→추천 연결(examType·시험일을 슬롯 필터/우선순위에 반영). 이게 "오늘 할 일"을 진짜 개인화로 끌어올림.
- **결정 필요**: ②암기 카드(`/srs`) — 카드 생성 경로를 만들어 살릴지, nav에서 내려 혼동을 없앨지. 현 상태(빈 베타 노출)가 가장 나쁨.
- **부채(여유 시)**: 과제 N+1·service-role, 복습 페이지 분할/죽은 합격자 카드, 상담 마크다운 파싱, A동의 게이트 비대칭(응시이력).

> 코드 변경 없음. 본 문서는 보완 우선순위 판단 재료.
