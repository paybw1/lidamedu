# 학습관리 목적지 7화면 디자인 정합성 진단 (읽기 전용)

> 대상: 오늘 할 일(/study/today)·복습(/study/srs)·암기 카드(/srs)·목표 진도(/goals)·학습 통계(/study/stats)·과제(/assignments)·상담 코멘트(/me/consult).
> 기준: `frontend-design` 스킬 원칙(응집된 디자인 시스템·CSS 변수 토큰·일관·세부 정제, generic 회피) + 프로젝트 키트(shadcn New York + `~/core/components/student`).
> 코드 변경 0.
> **결론(먼저)**: 공용 디자인 시스템은 **존재하지만(있음)** ① **공용 PageHeader가 없어** 헤더를 7화면이 제각각 손조립하고, ② **3개 화면(stats·consult·srs)이 공용 셸을 안 쓰고 자체 `<div>` 셸**을 굴리며, ③ **카드 프리미티브가 이원화**(공용 `Surface` vs shadcn `Card` vs 자체 div)됐다. → **"시스템 부재"가 아니라 "있는데 미준수 + 키트 불완전(PageHeader 결손)".**

---

## ① 공용 디자인 시스템 유무 — 있음(단, 불완전 + 미준수)

**공용 학생 키트** `~/core/components/student/`: `Shell`(StudentShell, `width` prop)·`Surface`(tone/pad=카드 역할)·`Eyebrow`(상단 라벨)·`Chip`(배지 역할)·`EmptyState`·`SectionTabs`·`Stat`. + shadcn/ui(`Card`·`Badge`·`Button`·`Table`·`Tabs`·`Input`).

**그러나**:
- **공용 PageHeader 없음** — `student/` 에 헤더 컴포넌트가 없다. 7화면 전부 `<header>` 안에 eyebrow + `<h1>` + 설명 `<p>` 를 **손으로 조립** → 제목 굵기·eyebrow 방식·설명 톤이 화면마다 갈림(아래 ③).
- **카드 프리미티브 이원화** — 새 키트 `Surface`(today.tsx만) vs shadcn `Card`(나머지 다수) vs 자체 div(consult). [[design-handoff]] reskin 으로 `Surface` 가 도입됐으나 대부분 화면이 아직 shadcn `Card` 잔존.
- **셸 미채택 3건** — stats·consult·srs(암기)는 `StudentShell` 을 안 쓰고 자체 `<div mx-auto max-w-… px-… py-…>`.

## ④ 근본 원인 — "있는데 안 지킴 + 키트 결손"

세 갈래가 겹침:
- **(A) 셸 미준수**: `StudentShell` 이 있는데 **stats·consult·srs(암기)** 는 자체 `<div>` 셸(서로 폭·패딩 제각각). → 옛 화면이 키트 도입 전 마크업을 유지.
- **(B) 키트 불완전(PageHeader 결손)**: 헤더 공용 컴포넌트가 없어 **7화면 전부 손조립** → 공용 `Eyebrow` 를 쓴 화면조차 h1 굵기·설명 톤이 갈림. 시스템이 헤더를 강제하지 못함.
- **(C) 카드 프리미티브 과도기**: reskin 으로 `Surface` 가 들어왔으나 **today.tsx 만** 채택, 나머지는 shadcn `Card`(consult는 자체 div). 두(세) 카드 계열 공존.

**공용 쓴 곳 / 자체 구현한 곳**:
- 공용 셸+Eyebrow 계열(라인 A): **today·goals·assignments·srs(복습)** — 헤더/셸은 키트, 카드만 today=Surface·나머지=Card.
- 자체 셸 계열(라인 B): **stats·consult·srs(암기)** — 셸·헤더 전부 손수.

→ 즉 **디자인 시스템은 있고 절반은 따르나, ① 헤더 공용화가 안 됐고 ② 3화면이 셸을 안 쓰며 ③ 카드가 과도기**라 표면이 갈린다.

## ⑤ 기준(reference) 후보 + 통일 방향(단계적)

**기준 후보**:
- **today.tsx** = 새 키트(`StudentShell`+`Eyebrow`+`Surface`+`Chip`+`EmptyState`)를 가장 충실히 쓴 화면 → **reskin 의도에 가장 부합. 1순위 기준.** (단 설명 문단이 없어, 설명 패턴은 goals/assignments 참고.)
- **goals·assignments** = `StudentShell`+공용 `Eyebrow`+설명 문단까지 갖춘 정돈된 구조 → 2순위(카드만 `Surface` 로 전환하면 today 와 합치).
- 토큰: 본문 톤은 **새 키트 `text-ink-soft`/`text-ink-faint`** 로 통일(현 muted-foreground 혼용 해소).

**통일 방향(선택지 — 단계적, 결정은 사용자)**:
1. **기준 확정 + 공용 PageHeader 신설**: `student/` 에 `PageHeader`(eyebrow+제목+설명+우측 액션 슬롯) 추가, h1 규격 1종 고정(예 `text-2xl font-semibold tracking-tight md:text-3xl`). 카드 프리미티브 **택일**(권장: `Surface`). → 헤더·카드 divergence 의 근원 제거.
2. **셸 미채택 3화면 이주(셸+헤더 레이어 먼저 — 최대 격차)**: **consult(가장 작음) → stats → srs(암기)** 순으로 자체 `<div>` 셸 → `StudentShell`, 자체 eyebrow → `PageHeader`. 폭 정책 결정(통계는 표가 많아 wide 예외 허용할지).
3. **채택군 내부 정리**: srs(복습)·goals·assignments 의 카드 `Surface` 전환 + 본문 톤 `ink-soft` 통일 + h1 규격 일치(extrabold/bold → 기준 굵기).

> 권장 순서: **①PageHeader 신설·기준 확정 → ②비채택 3화면 셸/헤더 이주(consult→stats→srs) → ③카드·톤 통일.** 화면 하나씩, 기능 무변경(시각만). 가장 작은 consult 로 패턴을 검증한 뒤 확대.

코드 변경 0 — 위는 진단·방향 제시까지.
