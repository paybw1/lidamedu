# 수험생 진단·통계 분석 — 데이터/기능 현황 조사

> **목적**: 진단·통계(특히 "이론 vs 판례 약점") 분석 시스템 설계용 사실 정리. **코드·DB 변경 없음(읽기 전용)**.
> **조사일**: 2026-06-14 · **대상**: 운영 DB `mcgdoplo`(read-only SQL) + 코드(`database.types.ts` SSOT).
> **표기**: 사실만. 미구현="미구현", 불명="확인 안 됨". (`docs/db-schema.md`는 계획 문서라 실제와 불일치 — 예: `user_progress`·`daily_study_stats` 미존재.)

## 0. 결론 한 줄
**이론 vs 판례 약점 분석의 부품(분류축 `choice_type` + 지문별 OX 정오 기록 메커니즘)은 존재**하나,
① 분류가 `related_case_id` FK가 아니라 `choice_type`(조문/판례/이론) 기반이고 box-item은 48% 미입력,
② 지문별 정오는 **OX 모드에서만** 기록(일반 풀이엔 미기록), ③ 누적 글로벌 집계는 없음(세션 결과에 일부),
④ **실사용 데이터가 거의 0**(전체 98 시도·5명, OX 32응답·3명, 모의고사 0, 합격결과 0) → **인프라는 준비됐으나 현재는 분석 불가**(표본).

## 1. OX 지문(박스형) 데이터 — ★ 분석의 열쇠

### 1.1 박스형 구조 (`problem_box_items`, 1,357행)
컬럼: `box_item_id, position_index, marker, choice_type(enum), ox_truth(enum), ox_ineligible, related_article_id, related_article_number, related_case_id, related_case_number, related_node_id`.
(`problem_choices`도 동일 분류 컬럼 보유 — 47,432행.)

### 1.2 이론 vs 판례 "분류"가 실제로 채워져 있나 — **부분. 그리고 축이 다르다.**
사용자가 가정한 "related_article_id→이론 / related_case_id→판례"는 **실제 구현과 다름**. 실제 분류축은 **`choice_type` enum(조문 statute / 판례 precedent / 이론·실무 theory)** 이다(집계 코드 `getPackResultStats`가 이걸 씀).

| 분류 신호 | box_items(1357) | choices(47432) |
|---|---|---|
| **`choice_type`** statute(조문) | 496 | 19,474 |
| `choice_type` precedent(판례) | **93** | 7,316 |
| `choice_type` theory(이론) | 123 | 5,555 |
| `choice_type` **null(미분류)** | **645 (48%)** | 15,087 (32%) |
| related_article_id 채움 | 471 (35%) | 8,099 (17%) |
| **related_case_id 채움** | **0 (0%)** | 8 (~0%) |
| related_node_id 채움 | **0** | **0** |
| ox_ineligible | 613 | 1,472 |

- **핵심**: 판례 분류는 `choice_type='precedent'`로 표현되지, `related_case_id`(uuid FK)로는 **거의 안 채워짐(box 0건)**. 즉 "관련 판례 entity 연결"은 미완(텍스트 `related_case_number`/`choice_type`만). 노드(`related_node_id`)도 0건 — 지문은 부모 문제 `primary_node_id`를 상속해 배치(`getOxQuestionsForArticle`의 `placed()` 로직).
- choice_type은 box 52%/choice 68% 입력 → **분류축으로 쓸 수는 있으나 미입력분(특히 box 48%) 존재.** "이론(theory) vs 판례(precedent) vs 조문(statute)" **3분류**임에 유의(사용자가 말한 "이론(조문)"은 데이터에선 조문/이론으로 분리됨).

### 1.3 지문별 정오가 학생별로 남나 — **남는다(메커니즘 존재). 단 OX 모드 한정 + 데이터 거의 0.**
- 저장처: **`user_problem_attempts`** (append-only 시도 로그). 컬럼: `user_id, problem_id, selected_choice_id, selected_box_item_id, ox_answer(enum O/X), is_correct, mode, time_spent_ms, attempted_at, session_id`.
- **지문별 OX 1행** = `ox_answer IS NOT NULL` + (`selected_box_item_id` 또는 `selected_choice_id`로 지문 식별) + `is_correct`. → **`(user, box_item, is_correct)` 직접 조회 가능**(`listMyOxWrongNoteItems`, queries.server.ts:650).
- **기록 경로(중요)**: OX 1행은 **OX 전용 화면에서만** 생성 — `ox-questions-panel.tsx`(조문 페이지 OX 지문, refType choice/box), `mcq-pack-ox-exam.tsx`(OX 시험, bulk). **일반 문제 뷰어(`problem-viewer.tsx`)는 박스형도 "문제 전체 1행(MCQ)"만 기록**(`selected_box_item_id`/`ox_answer` 미설정) → 일반 풀이에선 지문별 정오 **미기록**.
- 파생 상태: `user_ox_ref_srs`(per `(user, ref_type, ref_id)` SRS 스케줄 — is_correct 로그 아님). 원시 정오 로그는 `user_problem_attempts`.
- **데이터 볼륨(★ 현실)**: `ox_answer` 보유 시도 **32건 / 3명 / 11개 지문**뿐. 분석 표본으로는 **사실상 0**.

## 2. 기존 약점·통계 분석 — 이미 있는 것

### 2.1 약점 분석 (3종, 집계 단위가 다름)
| 함수 | 파일 | 단위 | "약점" 판정 |
|---|---|---|---|
| `getWeakAreas` | study/queries.server.ts:1754 | **개별 문제** | 본인 최근시도 오답 문제를 글로벌 정답률 낮은 순 |
| `getWeakNodes`(전역, 대시보드) | subjects/lib/weak-nodes.server.ts:35 | **체계노드(단원)** | 노드 직속 article 시도 합산, `MIN_ATTEMPTS=5`, `weaknessScore=(100-정답률)*log10(시도+1)` |
| `getSessionWeakNodes`(세션) | study/queries.server.ts:2600 | **체계노드(단원)** | 한 응시 내 노드별 정답률 오름차순 |
- 노드 귀속 우선순위: **`problems.primary_node_id` → `article_systematic_links`(article→node) → `primary_article_id`** → 기타(null). 지문은 `related_node_id`(0건이라 사실상 부모 문제 노드 상속).
- **순수 조문(article) 단위 약점 화면은 확인 안 됨**(node-progress 내부 중간 단위로만).

### 2.2 이론/판례/조문 split 집계 — **있다(단, 좁다)**
- `getPackResultStats`(mcq-packs/queries.server.ts:701)의 **`byChoiceType`**: 본인이 고른 choice의 `choice_type`별 정답률(`statute/precedent/theory` = 조문/판례/이론). 본인 vs 전체. 라벨 `problems/labels.ts:97`.
- **한계**: ① **세션(pack 결과) 단위만** — 누적/글로벌 이론·판례 정답률 화면 없음. ② **choices만** 집계(선택한 `selected_choice_id`) — **box-item 선택은 choice_type 집계에서 빠짐**(box는 format `mc_box`로만 잡힘). ③ per-box-item 개별 누적 정답률 통계는 **확인 안 됨**.
- 동시 `byFormat`(mc_short/mc_box/mc_case/ox/blank/subjective)도 집계 = **유형별 정답률**.

### 2.3 성장·합격선·정오이력 화면 (무엇을 보여주나)
- `/study/stats`(study/screens/stats.tsx, 16쿼리·4탭): 조문/판례 **열람%**, 문제 **정답률**, 주별 정답률 추이, **합격 진단 점수 추이**, 1차 약점표(문제·조문·글로벌 정답률·내 시도), 과목별 표, 2차 자기채점. (조문/판례는 정답률이 아니라 **열람률+주석 수**.)
- `/dashboard`(dashboard/screens/dashboard.tsx): **PASS FORECAST**(`predictPassScore`), **WEAK SPOTS**(`WeakReviewCard` 문제별 + `WeakNodesCard` 단원별 — **합격자 평균 비교** `passerAvg*`, 게이트 ON/OFF), 진도·히트맵·오답큐.
- `/latest/mcq/:pack/result`(가장 풍부): **합격선까지 N점**(`distanceToPass`), 지난 회차 대비 ±, 등수/백분위/z, **WeakNodesPanel(단원별)**, **AccuracyTable(유형별+지문별 조문/판례/이론)**, 오답 근거(조문/판례 chip + AI 청크).
- `/latest/mcq/exam/.../result`: 교시별 점수·**과락**(`fail_floor`)·합격(`pass_average`)·**등수**(RPC `mcq_exam_attempt_stats`).
- `/me/ox-sessions`: OX 회차별 정답률만(약점/노드 분석 없음). `/subjects/.../quiz/result`: 문항 나열(약점 집계 없음).
- `/me/exam-results`: **실제 국가시험 합격/불합격 자기보고**(앱 채점 아님 — 벤치마크 원천).

### 2.4 OX 지문 단위 분석이 이미 있나 — **거의 없음**
오답노트(`listMyOxWrongNoteItems`)가 ref(choice/box) 단위로 최신 정오를 dedup하지만 **이론/판례 split·정답률 누적은 안 함**. 지문별 정답률·이론/판례 집계 화면은 **미구현**.

## 3. 분석 데이터 소스 인벤토리

| 소스 | 테이블 | granularity | group-by(student/단원/이론판례) | 비고 |
|---|---|---|---|---|
| 객관식 시도 | `user_problem_attempts` | per-event(append) | 학생O·문제O·노드는 join | is_correct·time·mode |
| **지문 OX 정오** | `user_problem_attempts`(ox_answer≠null) | per-지문 event | 학생O·지문O·choice_type join O | **OX 모드 한정, 데이터 32건** |

| 진도(방문) | `study_sessions`(scope jsonb) | per-view event | 학생O·과목O·article/case O | **회독수 미구현**(distinct 방문만) |
| 조문 반복학습 | `user_recitation_attempts`,`user_(auto_)blank_attempts` | per-event | 학생O·article O | 회독 대용 신호 |

| SRS | `srs_review_states`/`_logs`, `user_problem_srs`, `user_ox_ref_srs`, `user_blank_srs` | per-user-item(+이력) | 학생O·cohort O | due/lapses/ease로 약점 |

## 5. 분석 설계 관점 (조사 기반 판단)

### 5.1 "이론(조문) vs 판례 적용" 약점 분석 — **구조 가능 / 현재 불가(데이터)**
- **가능 근거**: 분류축 `choice_type`(조문/판례/이론) + 지문별 OX 정오(`user_problem_attempts.ox_answer`)가 둘 다 존재 → `attempt → ref(choice/box) → choice_type` group-by로 산출 가능.
- **불가/제약 근거**: (a) **실데이터 거의 0**(OX 32응답·3명·11지문). (b) 지문 정오는 **OX 모드에서만** 기록(일반 풀이 미기록) → 데이터 유입 채널 좁음. (c) box-item `choice_type` 48% 미입력. (d) 판례는 `choice_type='precedent'`로만 구분(entity `related_case_id` 0% — "어느 판례"까진 못 감). (e) 누적/글로벌 이론·판례 집계 미구현(세션 결과 choices만).
- **판정**: **부분 가능(설계는 가능, 즉시 의미 있는 분석은 불가)**. 우선 데이터 유입(OX 풀이 유도)·box choice_type 채우기가 선행.

### 5.2 2축 교차(축1 주제별 단원/조문/판례 × 축2 지식종류 이론vs판례) — **데이터는 지원, 구현 미존재**
- 각 attempt → ref → `choice_type`(축2) + node(`primary_node_id`/ASL, 축1) 동시 보유 → **단원 × 지식종류 교차 집계는 데이터상 가능**.
- 현재는 두 축이 **따로** 존재(노드 약점 `getSessionWeakNodes` / choice_type `getPackResultStats`). 교차 집계·box 포함·글로벌 누적은 **새로 구현**해야.

### 5.3 새로 만들 것 vs 기존에 얹을 것
- **얹기**: 노드 약점(`getWeakNodes`/`getSessionWeakNodes`), choice_type split(`getPackResultStats`), 합격예측(`predictPassScore`), SRS 약점(due/lapses).
- **신규**: ① 노드×choice_type 교차, ② box-item 포함 choice_type 누적 집계(세션 무관), ③ 지문별(이론/판례) 약점 뷰, ④ 강사용 학생 단원/지식종류 드릴다운, ⑤ box `choice_type`/`related_node_id` 보강(데이터 품질).

### 5.4 표본 부족 (★ 가장 큰 제약)
- 전체 `user_problem_attempts` **98건 / 활동 학생 5명**(가입 26명), OX **32건/3명**, **모의고사 응시 0**, **합격결과 자기보고 0**. → **현재 어떤 개인 약점도 통계적으로 단정 불가**. 기존 `MIN_ATTEMPTS=5` 게이트조차 대부분 충족 못 함. 합격자 벤치마크도 `exam_results=0`이라 비어 있음.
- 신뢰 집계엔 **(노드/지식종류별) 최소 수십 시도·다수 사용자**가 필요한데 아직 축적 전. 데이터 축적이 1순위 전제.

### 5.5 "공부 방향 제시(처방)" 근거 — **현재 빈약, 신중 필요**
- 데이터로 뒷받침되는 것: 문제 **글로벌 정답률**(import 메타 + 소수 시도), 분류축(choice_type), 노드 매핑, 합격예측 휴리스틱(`predictPassScore`). 
- 뒷받침 **안 되는** 것: 개인별 이론/판례 약점(표본 0~수십), 합격자 대비(벤치 비어있음), 회독수 기반 학습량(미구현). → **개인 처방은 현재 근거 부족**. 처방 전 데이터 축적 + 표본 게이트(예: 종류·노드별 N≥k일 때만 단정) 필수.
