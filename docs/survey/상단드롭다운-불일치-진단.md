# 상단바 드롭다운 불일치 진단 (내용 desync · 디자인 정합) — 읽기 전용

> 두 축: ① 내용이 SSOT와 어긋나나 · ② 디자인이 드롭다운마다 다른가. 코드 변경 0.
> **결론(먼저, 솔직히)**: **현재 코드와 배포본(origin/master)에는 desync가 없다.** 상단바 6 드롭다운은 전부 SSOT(`nav-groups.ts`) 파생이고(하드코딩 잔존 0), **상담 코멘트는 학습관리 드롭다운 SSOT에 포함돼 렌더되며**, 6 드롭다운 모두 **같은 컴포넌트·같은 스타일**(`SimpleDropdown` + `CHIP_CLASS`)을 쓴다. → 사용자가 관찰한 "상담 코멘트 누락 + 드롭다운별 디자인 차이"는 **nav 리팩토링 배포 이전 상태**(또는 배포 전파/브라우저 캐시)로 보인다. 코드는 이미 통일·배포돼 있다.

## 1. 상단바가 SSOT 파생인가 — **YES (하드코딩 잔존 0)**

`navigation-bar.tsx`:
```
{TOPBAR_DROPDOWNS.map((d) =>
  d.subjects
    ? <SubjectsDropdown ... />                                  // 학습과목 = SUBJECT_NAV_ITEMS
    : <SimpleDropdown items={topbarDropdownItems(d.groupIds ?? [])} ... />  // 나머지 5 = 풀 파생
)}
```
- 드롭다운 항목 배열을 컴포넌트 안에 박은 곳 **없음**. `leadingFlats`(대시보드)·`trailingFlats`(운영관리)만 flat 상수이고 이는 드롭다운이 아님.
- 모바일 시트(`:524-534`)도 동일하게 `TOPBAR_DROPDOWNS` + `topbarDropdownItems` 파생.
- 사이드바·하단탭도 같은 풀(`useNavLayout`/`NAV_GROUP_POOL`) → **상단바·사이드바·하단탭 단일 소스.**

## 2. ★ 상담 코멘트 — 코드상 누락 아님

- SSOT: `manage` 그룹(`nav-groups.ts:73-85`)에 `상담 코멘트 → /me/consult` 포함.
- 매핑: `TOPBAR_DROPDOWNS` 학습관리 = `["today","review","manage"]`(`:166-169`) → manage 포함.
- 렌더: `SimpleDropdown`(`:297-332`)은 `items.map`으로 **전 항목을 필터 없이** chip 렌더. 영역 잠금(`locked`)은 **트리거를 흐리게만**(`LOCKED_DIM_CLASS`) 할 뿐 항목을 숨기지 않음.
- ⇒ **학습관리 드롭다운에 상담 코멘트가 7번째 chip으로 렌더된다.** 사이드바도 manage(secondary 그룹)의 items로 렌더 → **두 표면 모두 표시.**
- origin/master 배포본 nav-groups.ts에도 line 82 확인 → **배포 코드에 존재.**

**그럼 왜 "안 보임"으로 관찰됐나(가설, 우선순위순)**:
1. **배포/캐시 지연(가장 유력)** — 상담 코멘트(`12bf459`)·SSOT 파생(`dafba2b`)이 적용되기 *이전* 배포본을 봤거나, Vercel 배포 전파/브라우저 캐시. (사이드바엔 보이고 상단바엔 안 보였다면, 당시 상단바만 옛 하드코딩본이었을 때와 부합.)
2. **(부차) 가로 오버플로 클리핑** — 드롭다운이 `flex w-max … overflow-x-auto`(가로 1줄·좌측정렬, `:317`)라, 항목 총폭이 `max-w-[calc(100vw-2rem)]`를 넘으면 **마지막 chip(상담 코멘트)이 우측으로 잘려** 스크롤해야 보일 수 있음. 학습관리는 7항목으로 가장 길어 좁은 화면에서 위험. (데스크톱 표준 폭에선 대개 들어맞아 가능성 낮음 — 라이브 확인 필요.)

## 5. ★ 디자인 정합성 — **통일됨(스타일 1종, 폭만 가변)**

모든 드롭다운의 스타일 출처는 **단일**:
- 비-과목 5개 = `SimpleDropdown`(`:297-332`), 학습과목 = `SubjectsDropdown`(`:335-361`) — **둘 다 동일** `NavigationMenuContent > div.flex.w-max…overflow-x-auto.p-3 > Link.CHIP_CLASS`.
- chip 스타일 = 공용 상수 `CHIP_CLASS`(`:58-59`) 한 곳.

| 시각 속성 | 6 드롭다운 | 비고 |
|---|---|---|
| 배경·테두리·그림자·글꼴·padding·항목높이·hover·아이콘유무·구분선·정렬·애니메이션 | **동일** | 전부 `CHIP_CLASS` + 같은 컨테이너 클래스 |
| **너비** | **가변** | `w-max`(내용폭) + `max-w-[calc(100vw-2rem)]` — 항목 수·라벨 길이에 따라 다름. 넘치면 `overflow-x-auto` 가로 스크롤 |

→ **드롭다운마다 다른 "디자인"은 없다.** 유일한 차이는 **내용 길이로 인한 폭**(의도된 `w-max`)과, 넘칠 때의 가로 스크롤. (과거엔 컬럼형↔chip형 churn이 있었으나 `5c71e94`에서 "모든 상단 드롭다운 가로 1줄"로 통일됨 — 적용·배포 완료.)

**기준 디자인 재료**: 현재 6개가 이미 동일 기준(가로 1줄 chip). 다만 §2-2의 **가로 오버플로 클리핑**이 실제 UX 문제라면, "가로 스크롤" 대신 **flex-wrap(여러 줄)** 으로 바꾸는 것이 후보(마지막 항목 잘림 방지). 이건 통일성 문제가 아니라 **레이아웃 정책 선택**(스크롤 vs 줄바꿈) — 결정은 사용자.

## 6. desync 근본 원인 (종합) + 수정 방향

**근본 원인**: 코드 레벨엔 desync가 **없다**. 내용=SSOT 단일 파생(하드코딩 잔존 0), 디자인=공용 컴포넌트 1종. nav 리팩토링(`dafba2b`~`05cfd5c`)+상담코멘트(`12bf459`)가 전부 커밋·푸시됨. ⇒ 관찰된 desync의 원인은 **코드가 아니라 배포/표면 시점**:
- **(가장 유력) 배포 전파/캐시** — 리팩토링 적용 *이전* 상단바(옛 하드코딩·옛 디자인)를 본 것. 사이드바는 먼저/따로 SSOT화돼 보였을 수 있음.
- **(부차) 가로 오버플로** — 마지막 chip(상담 코멘트)이 좁은 폭에서 잘림.

**수정 방향(선택지)**:
1. **배포 확인(우선)** — 라이브(lidamipedu.com)가 origin/master(`f6f11fe` 이상)를 반영하는지 + 강력 새로고침. 반영돼 있으면 상담 코멘트·통일 디자인이 보여야 함. 안 보이면 Vercel 배포 상태 점검.
2. **(옵션) 오버플로 → 줄바꿈** — 드롭다운 컨테이너를 `overflow-x-auto`(가로 스크롤) 대신 `flex-wrap`(여러 줄)으로. 긴 드롭다운(학습관리 7항목)에서 마지막 항목 잘림 방지. 통일성 유지(전 드롭다운 동일 적용).
3. **코드 수정 불요** — 내용·디자인 desync는 코드상 존재하지 않으므로, ①을 먼저 확인 후 ②만 UX 개선으로 고려.

> 한 줄 요약: **"상단바가 SSOT를 안 따른다/디자인이 제각각이다"는 코드상 사실이 아니다 — 이미 통일·배포됨.** 라이브에서 여전히 어긋나 보이면 배포/캐시부터 확인하고, 그래도 마지막 항목이 안 보이면 가로 스크롤→줄바꿈 레이아웃만 손보면 된다.
