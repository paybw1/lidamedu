## 0. 한눈 결론

- **설득 순서가 뒤집혀 있다**: 지금 실제로 작동하고 차별화된 **(1) 약점 진단·SRS·정오 매트릭스**는 랜딩에서 거의 안 보이고(조연), **데이터 누적 전인 (2) 합격자 비교**가 hero 바로 아래 **prime spot(섹션 2)**을 차지. → (1)을 주연으로 끌어올리는 게 최대 ROI.
- **합격자 섹션은 "비었다"기보단 "납작해졌다"**: 수치 제거 후에도 4 축카드 + 3 기능카드 + CTA가 남아 내용은 있으나, 카운트업 수치라는 시각 펀치가 빠지고 **비슷한 텍스트 카드 2줄**이 쌓여 단조로움. 채울 거리 = 예시-라벨 비교 미리보기·아이콘·누적 진행 표시.
- **시각 시스템은 브랜드 정합 O / 토큰 정합 X**: 같은 브랜드 블루(#2D5BA8)·Pretendard지만, 인앱 `app.css` CSS 변수 토큰(`--surface-*`·`--card`·dark)을 **안 쓰고 inline `PALETTE` 고정 복사본**(light 전용). nav(토큰·다크 대응) + 본문(light 고정) 사이 다크모드 seam 위험.
- **frontend-design 기준**: AI-slop은 아님(보라 그라데이션 없음·실제 모션·커스텀 hero = 의도된 Wantedly-clean). 다만 **Pretendard 단일(디스플레이 폰트 페어링 없음)·중앙정렬 SectionHeader 7회 반복·거의 평면 #fff 배경** = 첫인상 차별성(타이포 위계·분위기/깊이)이 약함.

## 3. 합격자 섹션 현황 (수치 제거 후)

**남은 것**: SectionHeader(eyebrow+title+조건 subtitle) + **4 비교축 설명카드**(분석 합격자 풀·학습 시간·풀이량·정답률, 수치 없음) + 누적 고지 1줄 + **3 기능카드**(평균 대비 비교·자동 추천·12주 곡선) + CTA.

- **허전함의 정체 = "빈 칸"이 아니라 "단조"**: 카운트업 큰 숫자(시각 펀치)가 빠지면서, **라벨+설명 텍스트 카드가 위(4축)·아래(3기능) 두 줄**로 거의 같은 모양 반복 → 밋밋·중복.
- **채울 거리(향후/조건 프레이밍 유지하며)**:
  1. **예시 라벨 비교 미리보기** — 합격자 분포 곡선 + 본인 위치 마커를 **"예시(미리보기)" 워터마크**로. 시각 펀치 복구 + 정직(가짜 수치 아님).
  2. **4축 카드에 아이콘** + 4축·3기능 **한 줄로 통합**(중복 줄 제거).
  3. **누적 진행 표시** — "현재 N명 누적 중 · 목표 시 자동 공개"(데이터게이트와 직결, 정직한 기대감).
- ⚠️ 예시 미리보기는 **반드시 "예시" 라벨** — 안 그러면 방금 제거한 오버프로미스 재발.

## 4. 시각 시스템 (인앱 정합 · frontend-design 대비)

**랜딩 토큰/룩**: inline `PALETTE`(브랜드 블루 `#2D5BA8`·ink `rgba(0,0,0,.84)`)·**Pretendard 단일**·**light 전용 #fff**·Tailwind/CSS변수/다크 **미사용**·자체 모션(Reveal·useCountUp·useInView·SVG)·**중앙정렬 SectionHeader(eyebrow+title+subtitle) 7회 반복**.

**인앱 토큰**(`app.css`): CSS 변수(`--primary: #2d5ba8` = **같은 블루**, `--surface-1/2/3` subtle 표면, `--link`, `--card`) + **다크모드** + Tailwind v4 + shadcn + chart-colors SSOT.

**정합 판정 = 브랜드 O / 토큰 X**:
- ✅ 같은 브랜드 블루·같은 Pretendard → 로그아웃 light 사용자에겐 nav~본문 매끈.
- ❌ 랜딩 PALETTE는 **토큰의 고정 복사본** — `--surface-*`·`--card`·dark를 안 먹음. ⇒ (a) **다크 선호 사용자**: nav(토큰·다크 대응) 어두워지는데 **본문은 흰색 고정** = seam. (b) 향후 토큰 톤 조정이 랜딩에 **전파 안 됨**(드리프트).

**frontend-design 기준 대비**:
- ✅ **AI-slop 아님**: 보라 그라데이션 onWhite 없음. 의도된 Wantedly-clean·실제 staggered 모션·커스텀 hero 미리보기·SVG 커넥터·히트맵 = "committed aesthetic".
- ⚠️ **약점**: ① **Pretendard 단일** = 가이드가 지적하는 generic 폰트(디스플레이×본문 페어링 없음 → 타이포 위계·개성 부족). ② **중앙정렬 헤더 7회 반복** = "predictable pattern". ③ **거의 평면 #fff 배경**(그라데이션은 카드 2개·FinalCta뿐) = 분위기/깊이 부족(가이드: gradient mesh·texture·layered). ④ **비대칭/오버랩/그리드 브레이킹 거의 없음**(대부분 중앙 그리드) → "unforgettable" 한 방 부재.
- **종합**: 깔끔·유능하지만 기억에 남는 첫인상은 아님. 가장 큰 갭 = **타이포 위계 + 배경 분위기**.

## 5. 개선 방향 (선택지 · tradeoff · 규모)

> 세 방향은 독립. 조합 가능. 권장 순서는 §6.

### A. (1) 전면화 — 라이브 차별점을 주연으로
- **무엇**: "약점 진단·보완" **전용 섹션 신설**(OX 정오 매트릭스 단원×지식종류 mock + SRS 복습 큐 + 보완 전략 카드)을 **hero 직후**로. (2) 합격자는 그 뒤로 강등(정직한 향후 프레이밍 유지). Hero 미리보기 카드에 **약점 매트릭스 뷰** 추가/교체(현재 todo+stats만). 중복 섹션(3·4·9) 일부 통합.
- **tradeoff**: 지금 **작동 + 차별화된 것**으로 설득 → 정직하고 강함. 단 (2)를 뒤로 미루면 종합반 핵심 훅이 약해질 수 있음(보강 §B로 상쇄). 새 mock 1~2개 제작 필요.
- **규모**: **M** (신규 섹션 컴포넌트 1 + `home.tsx` 순서 + Hero 카드 수정).

### B. 합격자 섹션 보강 — 납작해진 섹션을 정직하게 채움
- **무엇**: §3의 채울 거리 — 예시-라벨 비교 미리보기(분포 곡선+본인 마커) + 4축 아이콘 + 4축·3기능 한 줄 통합 + 누적 진행 표시.
- **tradeoff**: 가짜 수치 없이 시각 매력 복구. ⚠️ 예시 mock "예시" 라벨 필수(오버프로미스 재발 방지). 직전 문구 보정과 톤 일관.
- **규모**: **S–M** (`passer-stats-section.tsx` 1파일).

### C. 시각 개선 — 첫인상답게(frontend-design 적용)
- **무엇**: ① **디스플레이 폰트** H1/H2 페어링(본문 Pretendard 유지) → 위계·개성. ② 중앙정렬 헤더 7회 단조 깨기(좌정렬/비대칭 교차). ③ 배경 분위기(섹션별 subtle gradient mesh·texture, 평면 #fff 탈피). ④ **토큰 정렬 결정** — 인앱 `app.css` 토큰 소비(다크 대응·미래 안전) vs 마케팅 브랜드로 의도적 동결 중 택1, 최소한 nav(다크)+본문(light) seam 해소.
- **tradeoff**: 첫인상 이득 최대지만 가장 주관적·산발적·스코프 커지기 쉬움. 디스플레이 폰트 = 웹폰트 1개 추가 로드. 토큰 정렬은 결정(브랜드 표현 vs 일관성)이 선행.
- **규모**: **M–L** (cross-cutting: `landing.tsx` 토큰/폰트 + 섹션 다수).

## 6. 권장 순서 (제안)

1. **B 먼저(S–M)** — 방금 만든 "납작함"을 즉시 메움. 단일 파일·저위험.
2. **A 다음(M)** — 전략적 최대 ROI: 라이브 차별점(1)을 주연으로, (2)는 B로 보강된 채 뒤로.
3. **C 마지막(M–L)** — 타이포 위계·배경 분위기·토큰 seam. 폭이 크니 별도 단계·하드스톱.

각 방향은 착수 전 구체안(섹션 mock 스케치)부터 확인 후 진행. **본 문서 = 점검·방향 제시(코드 0).**
