## ① 디자인 이주 현황 (stats·srs)

**공용 키트 기준** (consult가 검증한 본): `StudentShell`(컨테이너 max-w·padding) > `PageHeader`(area eyebrow + h1 + desc + 우측 `actions`, **비sticky·밴드 슬롯 없음**) > `Surface`(카드 primitive, `CardHeader/Content` 서브없는 plain div). 토글은 **레이아웃이 위에서** sticky 렌더(화면이 직접 X).

### (가) stats `/study/stats` — 자체 셸, 가장 까다로움
- **셸**: `StudentShell` 미사용. 자체 `<div className="mx-auto w-full max-w-screen-xl px-5 py-6 md:px-10 md:py-8">` (stats.tsx:506). + **myAnalysisOff 분기에 두 번째 자체 wrapper**(stats.tsx:442, `space-y-4` + GoalSummaryBar + Notice) — **dual wrapper**. `MyAnalysisOffNotice`가 자체 `max-w-screen-md`라 Shell 안에 넣으면 폭 이중 제약.
- **헤더**: `PageHeader` 미사용. 자체 `<header className="mb-6 space-y-2">`(:507) = AreaEyebrow + (h1 `text-2xl font-bold` + desc) + 대시보드 버튼. ★ h1이 `font-bold`(PageHeader는 `font-semibold md:text-3xl`) → 이주 시 **제목 굵기·크기 변함**.
- **★ 목표 띠 공존 (핵심 결정)**: 현재 DOM = `header`{ eyebrow → h1+desc → 대시보드btn → **GoalSummaryBar(띠)** → **range band** } → `Tabs`. 띠·range는 **제목 아래 풀폭 밴드**. 그런데 **`PageHeader`엔 풀폭 밴드 슬롯이 없다**(eyebrow/title/desc + 우측 actions뿐). → 이주 시 띠·range는 **PageHeader 형제로 그 아래** 배치(actions 슬롯 아님 — 풀폭이라):
  ```tsx
  <StudentShell width="wide">
    <PageHeader area="manage" title="학습현황" description="…" actions={<대시보드/>} />
    <GoalSummaryBar … />        {/* 형제 밴드 */}
    <div className="…range…">…</div>
    <Tabs>…</Tabs>
  </StudentShell>
  ```
  현재 `space-y-2`/`mt-3` 간격이 사라지므로 **간격 수동 재부여** 필요. = stats 이주의 load-bearing 결정.
- **카드**: shadcn `Card` **51곳**, `Surface` 0곳. KpiCard·Milestones·각 추세·합격자보정·약점·1/2차 표 전부 `Card`+`CardHeader/Content`(표는 `CardContent px-0` 풀폭). `Surface`엔 서브컴포넌트가 없어 51곳 전부 header/content 수동 재표현 = **이주 작업의 대부분이자 셸 교체와 대체로 독립**.
- **난이도**: **높음** — 띠 공존 + dual wrapper + 51 Card.

### (나) srs(암기) — ★대상은 `srs.tsx`가 아님
[[study-mgmt-srs-two-systems]]: **/study/srs=복습**(`srs.tsx`) vs **/srs=암기 카드**(`srs-review.tsx`)·**/srs/stats=암기 통계**(`srs-stats.tsx`). 사용자가 말한 "srs(암기) 자체 셸" = **후자(/srs 계열)**.

- **`srs-review.tsx`(/srs 암기 러너)**: 동일 계열 — 자체 셸 추정(확인 필요).
- **난이도**: 중하 — 화면 작고 카드 적음. 단 **어느 srs인지 사용자 확인 필요**(복습 srs.tsx는 거의 됨 / 암기 srs-review·srs-stats가 자체 셸).

## ② 토글 sticky 현황 — ★ 이미 완료 (전제 stale)

**결론: 학습지원·학습정보 토글은 이미 코드상 최상단 sticky다.** 전제("아직 셸 내 비sticky")는 **stale**.

- `AreaTabs`는 항상 `<SectionTabs … sticky />`(AreaTabs.tsx:26) — `sticky=false` 전달 불가. 전 코드베이스 `sticky={false}` grep = **.tsx 0건**, 유일 2건은 **untracked 진단 문서**(`docs/survey/토글바-디자인-진단.md`, 리팩토링 전 기록).
- **학습지원**(`StudyAidsShell`): `StudyAidsTabs`→`AreaTabs ariaLabel="학습지원"`(sticky), **셸 첫 자식·헤더 위**(study-aids-shell.tsx:148-153). git log 2026-06-19 변경.
- **학습정보**(`LatestShell`): `LatestTabs`→`AreaTabs ariaLabel="학습정보"`(sticky), **셸 첫 자식·헤더 위**(latest-shell.tsx:81-91).
- `SectionTabs`가 `sticky top-0 z-10` + `-mx-* px-*` 풀폭 bleed(SectionTabs.tsx:75-77). 스크롤 컨테이너=document(`navigation.layout` 콘텐츠 wrapper에 `overflow` 없음) → 레이아웃이든 셸이든 document 기준으로 붙음.

**유일한 실제 차이**(sticky 여부 아님): 토글 렌더 **위치**.
| 영역 | 토글 렌더 | StudentShell |
|---|---|---|
| 학습관리·학습과목 | **레이아웃**(Outlet 위) | 화면이 StudentShell 사용 |
| 학습지원·학습정보 | **셸 본문 첫 자식**(StudyAidsShell/LatestShell) | **StudentShell 미사용**(자체 max-w div) |

→ ② "sticky로 만들기"는 **이미 됨**. 라이브에서 안 붙어 보이면 소스가 아니라 **navbar(`sticky top-0 z-50`)와 토글의 `top-0` 겹침 / stale 빌드** 의심(전 영역 공통, 학습지원·정보 한정 아님). **먼저 실측 확인** 후 ②를 닫거나(코드 0) 범위 재정의.

> 따라서 ②의 진짜 잔여는 sticky가 아니라 **학습지원·학습정보 셸을 키트(StudentShell/PageHeader)로 이주**할지 = ①과 같은 성격(아래 ④에서 맞물림).

## ③ 탭 지연 로드 현황 (stats loader)

- **현황**: loader가 A-동의 early-return(2쿼리) 후 **단일 `Promise.all` 22 헬퍼**(stats.tsx:251-308) 전 탭 일괄 fetch. 탭 전환은 `?tab=` 클라 전용 + `shouldRevalidate`가 tab 변화엔 false → loader 재실행 안 함(전환 즉시).
- **탭 전용(deferrable) 헬퍼**:
  - **ox_diagnosis 전용**: `computeOxDiagnosis`(#17, **최重** — 4단계 순차 RT·6+쿼리·5만행 스캔) + 게이트(#18). **카운트 배지 없음 → defer 가장 깔끔**.
  - **blanks 전용**: `getUserBlankStats`+`getUserAutoBlankStats×2`+`getUserRecitationStats`(#11-14, ~10쿼리). 단 **TabsList 카운트 배지가 이 데이터를 첫 페인트에 읽음**(stats.tsx:562-567) → defer 시 배지도 `<Await>` 처리/제거 필요(blocker).
  - first/second_exam 전용 진짜 단독은 거의 없음(overview와 공유).
- **옵션**:
  - **(a) RR `defer`+`<Suspense>/<Await>`** — 사내 선례(navigation.layout). `?tab=` 모델과 호환. **단 초기 로드에 쿼리는 실행됨**(TTFB만 절감, DB비용 아님). **ox_diagnosis가 무배지·최重 → 최적 1순위, 저위험.**
  - **(b) per-tab resource route + `useFetcher`** — 탭 첫 진입 시만 fetch = **진짜 lazy**(미진입 시 쿼리 0). 최대 효과·최다 작업(새 라우트 2개 + 메인 loader에서 분리 + 배지 처리). ★ "뮤테이션/페치 경로 동결"(CLAUDE.md)이라 별도 리팩토링 태스크.
  - **(c) 조건부 loader + tab 재검증** — 비권고. 공유 13헬퍼(히트맵 2만행×2 등)가 **탭마다 재실행** → 기존 최적화 역행.
- **독립성**: **loader/데이터 레이어** 변경이라 셸/헤더/토글(JSX/CSS)과 **다른 코드 영역**. 유일 co-edit seam = **blanks 카운트 배지**(TabsList) — ①이 TabsList를 restyle하고 ③이 blanks를 defer하면 인접 JSX 충돌(논리적 의존 아님, 병행 시 조정점).

## ④ 맞물림 맵

| | stats 상단(header/띠) | aids/info 셸 | stats loader |
|---|---|---|---|
| **① stats 이주** | ✅ 건드림(self-div→Shell, header→PageHeader, 띠 형제밴드, 51 Card) | — | — |
| **① srs 이주** | — (srs-review/stats 자체 셸) | — | — |
| **② 토글 sticky** | — (stats 토글은 **레이아웃**=이미 sticky, 미접촉) | ✅ **하지만 이미 sticky**(잔여=셸 키트 이주뿐) | — |
| **③ lazy** | TabsList 배지만(co-edit seam) | — | ✅ Promise.all·return·shouldRevalidate·TabsContent |

**판정**:
- **① stats ⟂ ② ⟂ ③ — 대체로 독립.** 사용자가 우려한 "stats 상단 ↔ 토글 sticky 겹침"은 **약함**: stats 토글은 **레이아웃에서** 렌더(이미 sticky), stats 자체 header 이주가 토글을 안 건드림. 상단 3겹은 `토글(레이아웃·불변) → StudentShell(PageHeader → 띠 → range) → Tabs`로 깔끔히 쌓임.
- **진짜 접점은 aids/info**: ② 잔여(셸 키트 이주)와 ①(디자인 이주)이 **같은 셸**(StudyAidsShell/LatestShell)에서 만남. 단 ②의 sticky는 이미 됐으니 "셸 이주 시 기존 sticky 토글 보존"만 주의.
- **③ co-edit seam**: blanks 배지 1곳뿐(①이 TabsList 손대면 그 후 ③).

## ⑤ 권고 순서 + 단계안

> 맞물림이 약해 대부분 독립이지만, **패턴 검증 → 확대 → 성능** 흐름 + co-edit seam 회피로 순서를 정함.

1. **② 실측 확인 먼저 (코드 0 예상)** — 라이브에서 학습지원·학습정보 토글이 실제로 sticky인지 확인. **이미 sticky면 ② 종료**(소스 변경 0, 문서 stale 정리만). 안 붙으면 navbar `top-0` 겹침/빌드 의심 = **별도 진단 태스크**(학습지원·정보 한정 아님). → ②를 목록에서 치우거나 재정의.
2. **① stats 디자인 이주 (가장 까다로움 = 패턴 확립)** — StudentShell(wide)+PageHeader+Surface. 핵심: **목표 띠·range를 PageHeader 형제 밴드로**(간격 수동), **dual wrapper(myAnalysisOff) 정리**, **51 Card→Surface**. "큰 화면 + 띠 공존" 패턴을 여기서 확정. *검증: 4표면 헤더 톤·띠·탭·합격자보정·약점 CTA 시각 확인, typecheck.*
3. **① srs 이주 (확대, 쉬움)** — 대상 확정 후: `srs-review.tsx`·`srs-stats.tsx`(암기) 자체 셸 → 키트. stats에서 검증한 Surface 변환 재사용. *(`srs.tsx` 복습은 이미 거의 됨 — 헤더 drop-in만.)*
4. **(옵션) 학습지원·학습정보 셸 키트 이주** — StudyAidsShell/LatestShell → StudentShell/PageHeader. **②와 유일 접점**: 기존 sticky 토글을 보존(레이아웃으로 올리거나 셸 첫 자식 유지). 전 학생 영역 키트 일관을 원할 때.
5. **③ lazy 마지막 (독립·성능)** — `ox_diagnosis` **defer(option a)** 부터(무배지·최重·저위험). 더 필요하면 `blanks`도(배지 처리) 또는 **resource route(option b)** 로 진짜 lazy. UI 작업 후 안정화 뒤(특히 TabsList co-edit seam 회피). *별도 성격이라 ①②와 분리.*

### 단계별 위험
- stats(②단계)가 가장 위험 — 통폐합으로 막 커진 화면(띠+5탭+51 Card). 한 번에 말고 **셸/헤더/띠 재배치 → Surface 변환(탭 단위)** 분리 권장.

- 각 단계 시각 작업 → 사용자 화면 확인 게이트.
