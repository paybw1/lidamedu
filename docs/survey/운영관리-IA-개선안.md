# 운영관리(/admin) IA·UX 고도화 개선안

> **목적**: 운영자가 "편히·쉽게" 관리하도록 — 분류(내비게이션) 일관성 + 역할 맞춤 + UI 표준화.
> **성격**: 사전조사 기반 제안서(구현 전 검토용). 2026-07-13.
> **전제**: 허브(경영 KPI·워크큐·시드 진행률)와 AdminShell 셸은 이미 충실 — 이 문서는 **그 위의 분류·발견성·일관성**을 다룬다.

---

## 1. 사전조사 요약 (근거)

| 영역 | 현재 상태 | 진단 |
|---|---|---|
| 규모 | `/admin/*` UI 화면 **~120개**, 사이드바 노출 **~91개**(16클러스터), `/api/admin/*` ~40 | 화면이 많다 — 발견성이 관건 |
| 라우터 | `routes.ts`에 **`prefix("/admin")` 그룹 없음** — 120개가 학생 라우트와 평면 나열 | 구조적 그룹핑 부재 |
| 허브 | 경영 KPI(6)·**오늘 처리할 항목 워크큐**(7~9)·내 콘텐츠(7)·시드 진행률·클러스터 그리드 | 좋음. 단 워크큐 집계가 **부분적** |
| 가드 | 레이아웃 net(instructor+) + 화면별 loader. **SSOT `admin-guard.server`는 ~27파일**, 인라인 `getStaffRole`은 **~128파일**, 지역 재정의 `requireAdmin` 1건 | 접근통제는 되나 **메커니즘 파편화** |
| 셸 | `AdminShell` **~131파일 채택**(거의 전 화면) | 셸 일관성 우수 |
| 공용 컴포넌트 | `admin-ui.tsx` 7종(Chip·StatusChip·Bar·FilterBar·FilterGroup·IndexTable·Field·AdminSelect)뿐 | **StatCard·WorkQueue·EmptyState·DataTable 없음** → 손수 구현 다수(허브 SeedTable조차 IndexTable 우회) |

### 분류 누수 4종 (전부 확인됨)
1. **커머스 분산** — 상품·요금·할인·쿠폰·수강권(products), 주문·결제·정산·배분(sales)은 **"수강생 운영"** 섹션인데, 강의 수강권·도서몰·배송(lms)은 **"콘텐츠 제작"** 섹션. 커머스가 **3클러스터 / 2섹션**에 흩어짐.
2. **`comms` 과적재 (14화면)** — 공지+랜딩(배너·일정·소식·강사소개·가이드)+Q&A(현황·답변자)+감사+알림함+커뮤니티 신고. 4개 관심사 혼재.
3. **강사 분산 (3곳)** — 강사 담당·권한(students) / 강사소개(comms) / 강사 배분·정산(sales). 라우트 이름 충돌까지 있었음(`admin-instructors.tsx` 2개).
4. **점검(health) 분산** — 완성도·체계도 배치·고아 하이라이트·연결 누락·PDF 미적재·데이터 가져오기가 콘텐츠 클러스터마다 흩어짐. 통합 "점검" 면 없음(허브 '미배정 점검' 타일만 부분 집계).

### 편의성 공백
- **사이드바가 역할 필터링 없음** — 강사도 커머스·시스템 클러스터 16개를 다 봄(클릭 시 loader 차단 → 헛클릭·혼란).
- **운영자 화면 검색 없음** — 전역 ⌘K는 학습 콘텐츠(조문·판례·문제)만 검색. 120개 운영 화면은 "어느 클러스터인지" 알아야 도달.
- **워크큐 부분 집계** — 문의(CS)·등업 신청·커뮤니티 신고·무통장/배송 대기는 화면만 있고 허브에 안 뜸.
- `/admin/bug-reports`는 라이브인데 **내비에 미등록**(고아).

## 2. 제안 — 분류 재설계 (5섹션)

> 원칙: **도메인 = 축**. 사람/콘텐츠/판매/시험/시스템을 섞지 않는다. 한 멘탈모델은 한 곳.

### 섹션 A. 콘텐츠 (제작·점검)
- 법령·개정 · 판례 · 객관식·정오문제 · 암기 자료 · 연관관계 · **강의 영상 제작**(시리즈·에디션·영상 *만*)
- **🆕 데이터 점검** — 완성도·체계도 배치·고아 하이라이트·연결 누락·PDF 미적재·가져오기 점검을 **한 클러스터로 통합**

### 섹션 B. 커머스 (판매·정산) · manager+
- 상품·요금·할인·쿠폰 · 수강권·구독 · 주문·결제·환불 · **정산**(강사 배분·정산·도서 배분·정산·Q&A 적립) · **도서몰·배송** · 매출/구독 통계
- → lms의 수강권·도서·배송을 여기로, products·sales를 여기로 **통합**

### 섹션 C. 수강생·반 (사람)
- 회원 관리(전환·접속·탈퇴·위험군·등급 테스트) · 종합반(게시판·커리큘럼·등업 신청)
- **🆕 강사 관리** — 담당·권한 + 강사소개 프로필 통합(배분·정산은 커머스로 링크)

### 섹션 D. 시험·분석
- 주관식(GS: 회차·시리즈·첨삭·포인트·사용량) · 학습·합격 분석(전체 학습현황·합격 결과·시험일·합격자 사례·패턴)

### 섹션 E. 운영·시스템
- 공지·커뮤니티·CS(공지·대량 안내·팝업·고객센터·커뮤니티 신고)
- **🆕 Q&A 운영 통합** — 강사 답변 SLA·답변자 지정 + AI(피드백·지표·평가·사용량·색인·한도)
- **🆕 강의 플랫폼 콘텐츠** — 히어로 배너·현장강의 일정·리담소식·이용 가이드
- 시스템 — 감사 기록·로그인 설정·받은 알림함·관리자 관리·**버그 리포트(내비 등록)**

**효과**: comms 14 → 3~4개 관심사로 분리, 커머스·강사·Q&A·점검이 각각 단일 클러스터로 수렴, 섹션 이름과 내용 일치.

## 3. 제안 — 편의성 (발견성)

1. **역할 맞춤 사이드바** — `ADMIN_NAV` 각 클러스터에 `minRole`(staff/manager/admin) 또는 `duty` 메타 추가 → 뷰어 역할·duty로 필터. 강사는 콘텐츠·시험만, manager+는 커머스, admin은 시스템까지. (헛클릭 제거·인지부하 감소)
2. **운영자 화면 검색(⌘K within /admin)** — `ADMIN_NAV`의 91개 화면(label+path)을 인덱스로 하는 커맨드 팔레트. 이름으로 어느 화면이든 점프. (기존 CommandPalette 확장 또는 admin 전용)
3. **워크큐 완성** — 허브 "오늘 처리할 항목"에 문의·등업 신청·커뮤니티 신고·무통장/배송 대기 타일 추가 → **단일 '오늘 할 일'** 면(역할·duty 필터).
4. **클러스터 그리드 슬림화** — 전체 chip 나열 대신 역할 관련 클러스터 + "자주/최근" 바로가기.

---

## 4. 제안 — UI·가드 일관성

1. **공용 컴포넌트 추출** — `StatCard`(KPI 타일)·`WorkQueueCard`·`EmptyState`·`DataTable`(정렬·페이지·필터 내장)을 `admin-ui`에 추가. 허브 KPI/워크큐/SeedTable부터 이관. 신규 화면은 손수 표 금지.
2. **가드 SSOT 일원화** — 전 화면을 `admin-guard.server`(requireStaff/Manager/Admin/Duty)로 이관. 인라인 `getStaffRole`·지역 `requireAdmin` 제거 → 보안+일관성. (점진: 신규는 SSOT 강제, 기존은 클러스터 단위 배치 전환)
3. **라우터 그룹핑** — `prefix("/admin", [...])`로 감싸 학생 라우트와 분리(가독성·향후 레이아웃 가드 일원화 용이).

## 5. 우선순위 로드맵

| 단계 | 항목 | 근거 | 리스크 |
|---|---|---|---|
| **P0** | ① 분류 재설계(ADMIN_NAV 5섹션 재편) + ② 역할 맞춤 사이드바 + ③ 운영자 화면 ⌘K 검색 | 체감 즉효·발견성. ADMIN_NAV는 단일 SSOT(허브·사이드바가 여기서 파생) | 낮음(데이터/필터 변경) |
| **P1** | ④ 워크큐 완성(문의·등업·신고·배송) + ⑤ 강사·Q&A·점검 통합 클러스터 + ⑥ bug-reports 등록 | 워크큐=단일 할일, 통합=멘탈모델 정합 | 낮~중(쿼리 추가) |
| **P2** | ⑦ 공용 컴포넌트(StatCard·DataTable 등) 추출·이관 + ⑧ 가드 SSOT 일원화 | 신규 개발 속도·보안 일관성 | 중(광범위·점진) |

**권장 착수**: **P0의 ①+②** — `ADMIN_NAV` 재편(순수 데이터)과 역할 필터는 리스크가 낮고 분류·발견성 문제를 한 번에 해결한다. ③(⌘K 화면 검색)은 P0 마지막에 얹으면 발견성 완성.
