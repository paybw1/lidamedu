# 특허 객관식 정답·해설 오배정 — 원인, 정정, 전수 대조 (2026-08-15)

## 1. 근본 원인

`scripts/parse-problems.mjs` 는 문제편·해설편을 `(장, 단원명, 문항번호)` 키로 맞춘다.
키가 성립하지 않으면 **"챕터 안에서 N번째 문제 ↔ N번째 해설"** 순번 fallback 으로 붙인다(L577~600).
`applyAnswer()` 가 정답(`correctIndex`)과 선지별 해설(`perChoice`)을 **같은 객체에서 함께** 꺼내므로,
순번이 한 칸만 어긋나도 정답과 해설이 **세트로** 다른 문제 것이 된다. 파서는 fallback 사용을 `seq=N` 으로 집계만 하고 **경고하지 않는다.**

fallback 이 발동한 두 경우:

- **(A) 단원 헤더 파싱 전멸** — 2026-06-24 누락분 백필에 쓴 `tmp/merged-full.json` 은
  section 이 `’15 변형`·`’24` 처럼 **연도 표기**로 잡혀 있다(정상 산출물 `source/_converted/problems-merged.json` 은 `출원인`·`직무발명`).
  키 매칭 0건 → 전량 순번 fallback. 그 파일의 "출원인 4번(2018)" 이 정답 ③ + 확대된선출원 해설을 달고 그대로 적재됐다.
  P-9494 가 가져온 해설의 원 주인은 P-5835(2017년 13번), P-9495 는 P-5844(2018년 5번) — 해시 대조로 확인.
- **(B) 같은 단원명이 문제집에 두 번 등장** — 예: `실시권 일반` 이 2012·2014·2015 묶음과 2003·2003·2004 묶음으로 두 번 나온다.
  키 중복 → 키 매칭에서 제외 → 순번 fallback. P-6061 은 이후 **해설만 바로잡는 보정 패스**가 돌아 해설은 제자리인데 정답만 옛 값이 남았다.
  선지 ⑤ 해설 끝의 `…록된 권리자이므로 통상실시권을 가진다…` 잔재가 그 흔적.

## 2. 감사 도구

`scripts/mcq-audit/audit.mjs` — 해설편 paragraph JSON 에서 `(장, 단원, 번호) → {정답, 선지별 해설}` 을 만들고
DB `publication_content_map(toc_path, sort_key)` 와 조인해 **정답 + 선지별 해설을 함께** 비교한다.

이번에 보완한 것:
1. **단원 헤더 3형태** 인식 — `| 특허료의 납부 |  | 79-86 |` / `| 직무발명 |  | 발진법2, 10-19, 58 |`(조문참조에 한글) / `| 실용신안법 |`(1칸).
   해설 본문의 표는 가운데 칸이 비어있지 않아 걸러진다.
2. **앞머리 표기 차이 무시** — 원본 `✕, ~` `○, ~` `는 ~` ↔ DB 는 그 접두가 없다. 이걸 안 걸러 4건이 오탐이었다.
3. **단원명 대응표** — `특허권 > 소멸` ↔ `특허권의 소멸 및 특허권자의 의무` 등 4쌍.
4. **해설 앵커링** — 단원명·번호로 못 붙는 구간(DB `정정심판/특허의 정정` = 교재 `정정심판`+`정정청구`, `국제조약` = `조약일반` 등)은
   책 전체에서 선지별 해설이 가장 잘 맞는 엔트리를 찾아 3/5 이상일 때만 인정. 앵커 단원이 DB 단원과 무관하면 따로 표시.

★한계: 앵커링은 '해설이 통째로 남의 것'인 경우 그 남의 엔트리에 붙어 정상처럼 보인다.
그래서 앵커된 34건은 단원 일치 여부를 별도 점검했고, 23건은 단원명 표기 차이(번호는 동일, 해설 5/5)로 정상 확인.

5. **페이징** — `publication_content_map` 조회가 PostgREST 기본 상한 1000행에 걸려 **107행이 조용히 잘려 있었다**.
   페이징을 넣자 그 구간에서 정답 오류 1건(P-8070)이 추가로 나왔다. ★대량 조회는 반드시 `.range()` 페이징.

## 4-1. 추록·정오표 발행은 하지 않는다 (2026-08-15 결정)

**추록·정오표는 인쇄된 책이 실제로 바뀐 경우에만 발행한다.** 이번 정정은 파서의 순번 fallback 때문에
**적재만 틀렸던 것**이고 교재 원본은 정상이므로 발행 대상이 아니다. 추록은 수험생이 자기 책에 손으로 반영하는
문서라, 책이 안 바뀐 건을 실으면 고칠 게 없는 지시를 주게 되고 추록 자체의 신뢰가 떨어진다.

정정분은 원장(`content_revisions`)에 `notice_status='none'` 으로 기록만 남긴다(35건).
★부작용: `admin-errata-sheets` 의 "발행 대기" 카운터가 이 건들까지 세어 부풀어 보인다(51 중 35).
