# 생성 해설 문체·표기 규칙

대상은 1차 객관식 해설(`problems.explanation_md`)입니다. 2차 모범답안은 5절에서 따로 다룹니다.

---

## 0. 파이프라인 순서

```
① 재구조화 (모델)      본문 → 필드. 표기 보존. 내용 불변
② 표기 정규화 (정규식)  조문·판례·용어 표기 통일. 모델 미사용
③ 문체 검증 (정규식)    금지 패턴 검출
④ 표본 육안 확인        자동으로 볼 수 없는 것만
```

①과 ②를 합치면 안 됩니다. 재구조화 검증은 표기 집합이 입력과 완전히 일치하는지를 봅니다. 같은 패스에서 표기를 통일하면 그 검증이 무력해집니다. 정규화는 결정론적이라 모델이 필요 없고, 정규화 후에는 입력·출력 양쪽을 같은 정규화 함수에 넣어 비교하면 됩니다.

---

## 1. 필드별 문체

### `conclusion`

정답 번호와 그 판단 근거. 2~3문장.

단정형으로 씁니다. 객관식 해설의 첫 줄이 할 일은 판별 기준을 주는 것이고, 유보적 서술은 그 일을 못 합니다.

- 씀: `전세금 반환의무는 전세권설정자에게 있고, 목적물의 양수인이 이를 승계하지 않는다.`
- 안 씀: `전세금 반환의무의 귀속에 관하여는 견해가 나뉠 수 있으나 …`

정답 번호는 본문에 넣지 않고 별도 값으로 둡니다. 선지 번호가 개정으로 바뀔 수 있습니다.

### `reasoning`

법리와 적용. 서술 순서를 고정합니다.

```
근거 조문 → 요건 → 사안 적용 → 판례 확인
```

이 순서가 답안 작성 순서와 같아서, 1차 해설을 읽으며 2차 골격이 몸에 익습니다. 문체는 다르지만 논리 순서는 공유합니다.

문단은 3개 이내입니다. 실측 p95가 3입니다.

### `distractor` (구 `pitfall`)

**필드명을 바꿉니다.** `pitfall`이 모델을 「함정」이라는 낱말로 유도했고, 검증기도 그 낱말을 찾다가 정상 출력 6건을 실패로 처리했습니다. 실제 내용은 오답 선지 분석입니다.

이름을 바꾸면 낱말 매칭 검증이 필요 없어집니다. 선지 번호가 있는지만 보면 됩니다.

- 형식: `선지 ②는 … 라고 서술한다. 실제로는 … 이다.`
- 오답 선지가 특정되지 않으면 `null`. 지어내지 않습니다

### `statute_refs` · `case_refs`

서술 없이 표기만. 본문에 등장한 것과 같은 집합이어야 합니다.

## 2. 표기 규칙 (정규화 대상)

### 조문

판결문 관습을 따라 **띄어 씁니다.**

| | |
|---|---|
| 씀 | `제33조 제1항 제3호` |
| 안 씀 | `제33조제1항제3호` · `33조 1항` · `제33조 ①항` |
| 가지조문 | `제29조의2` (`의` 앞뒤 붙임) |

법제처 법령 인용은 붙여쓰기가 표준이라 관행이 갈립니다. 판결문과 수험 교재가 띄어쓰기 쪽이므로 그쪽을 택했습니다. 둘 중 하나로만 고정하는 것이 중요합니다.

법명은 본문 첫 등장에만 붙이고 이후 생략합니다. 과목이 이미 맥락을 줍니다.

### 판례

본문은 짧게, 각주는 짧게, 상세는 링크로.

| 위치 | 형식 |
|---|---|
| 본문 | `2001다4981` |
| 각주 칩 | `2001다4981` + 검증 상태 표시 |
| 상세 (호버·링크) | `대법원 2001. 5. 8. 선고 2001다4981 판결` |

본문에 선고일 전체를 넣지 않습니다. 300자 해설에 `대법원 2001. 5. 8. 선고` 20자를 다섯 번 넣으면 본문의 3분의 1이 인용 형식에 먹힙니다.

병합 표기는 원형을 보존합니다. `2002다31803·31810`을 쪼개지 않습니다. 재구조화 검증이 별칭으로 처리합니다.

### 용어

| 쓸 것 | 쓰지 말 것 |
|---|---|
| 오인혼동 | 오인·혼동 / 오인 혼동 |
| 통상의 기술자 | 당업자 |
| 진보성 | 비자명성 |
| 요부 | 주요부 / 핵심부 |

같은 개념을 두 낱말로 쓰면 검색과 태깅이 갈립니다. 목록은 과목별로 늘려 가세요.

## 3. 금지 패턴 (정규식 검출)

| 패턴 | 이유 |
|---|---|
| `할 것이다` · `사료된다` · `봄이 상당하다` | 구식 판결문투. 해설은 판결문이 아님 |
| `~인 것으로 보인다` | 객관식 해설에서 유보는 판별 기준이 못 됨 |
| `주의해야 한다` · `유의하라` | 지시 대신 근거를 씀 |
| `쉽게` · `간단히` · `단순히` | 난이도를 대신 판단함 |
| `위에서 본 바와 같이` | 필드로 쪼개면 「위」가 없음 |
| 느낌표 | |
| `제\d+조제\d+항` (붙여쓰기) | 표기 규칙 위반 |
| `대법원 \d{4}\. .* 선고` (본문 내) | 본문에는 짧은 형식만 |

## 4. 자동으로 볼 수 없는 것

아래는 정규식으로 판정할 수 없습니다. 전량 실행 후 표본 육안 확인만 가능합니다.

- `conclusion`이 실제로 정답 근거를 담고 있는지
- `distractor`가 지목한 선지가 실제 오답인지
- 서술 순서(조문→요건→적용→판례)를 지켰는지
- 법리 서술이 정확한지

**마지막 항목이 가장 중요하고 가장 자동화가 안 됩니다.** 인용 집합 보존은 표기가 안 바뀐 걸 보증할 뿐이고, 법리가 맞는지는 보증하지 않습니다. 재구조화는 내용을 새로 만들지 않으므로 원본이 틀렸으면 틀린 채로 통과합니다.

## 5. 2차 모범답안은 다릅니다

`model_answer_md`는 논술이고 문체 규칙이 반대입니다.

| | 1차 해설 | 2차 답안 |
|---|---|---|
| 목적 | 선지 판별 | 논점 포착과 서술 |
| 길이 | 300자 내외 | 답안 분량 기준 |
| 결론 위치 | 맨 앞 | 맨 뒤 |
| 문체 | 단정, 압축 | 논증, 목차 구조 |
| 조문 인용 | 최소 | 적극 |

**1차 해설 가이드를 2차에 그대로 적용하지 마세요.** 결론을 앞에 두는 규칙이 논술에서는 감점 요인이 됩니다.

2차는 채점기준(`grading_rubric_md`)이 이미 문체를 규정하고 있을 가능성이 높습니다. 별도 가이드를 쓰기 전에 기존 채점기준을 먼저 읽어야 합니다.

---

## 6. 적용 순서

1. `pitfall` → `distractor` 필드명 변경. 프롬프트와 검증기 양쪽
2. 표기 정규화 함수 작성. `content-rules.mjs`에 두고 단일 소스로
3. 금지 패턴 검출을 3절 표대로 추가. 실패가 아니라 경고
4. 민법 30건 재실행 후 경고 분포 확인
5. 경고가 특정 패턴에 몰리면 프롬프트에 반영, 흩어지면 원본 문체 문제

2번은 `CASE_MARKS`가 두 곳에서 어긋난 것과 같은 위험이 있습니다. 정규화 함수는 처음부터 한 곳에 두세요.
