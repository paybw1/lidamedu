# 지시: 특허 예상문제 해설편 적재

`scripts/mcq-audit/parse-expected-haeseol.mjs`의 dry-run이 매칭률 99.7%(590/592)로 나왔다. 적재 전에 지표를 확정하고, 그다음 적재한다.

**순서를 지킬 것. 3단계 결과를 보고할 때까지 `--apply`를 실행하지 마라.**

## 1. dry-run 결과를 파일로 뽑고 구조를 파악

```bash
npx tsx scripts/mcq-audit/parse-expected-haeseol.mjs --json /tmp/haeseol.json
```

출력 JSON의 최상위 구조와 매칭 항목 한 건의 키를 확인하고, 아래 이름에 대응하는 실제 필드명을 정한다.

- 문항 식별자 (`problem_id` 등)
- 기존 해설 본문 (적재 전 DB 값)
- 새 해설 본문 (해설편에서 파싱한 값)

이후 단계의 `jq`·SQL에서 이 이름을 실제 값으로 치환한다. 추측하지 말고 파일에서 확인한 이름을 쓸 것.

## 2. 적재 전 지표 측정 (가장 중요)

**적재하면 기존 값을 잃는다. 반드시 적재 전에 찍을 것.**

### 2-1. 현재 DB 지표 — origin별

읽기 전용 SQL. 기존 경로(`scripts/run-prod-sql.mjs`)로 실행한다.

```sql
SELECT origin,
       count(*) AS n,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY length(explanation_md))::int AS p50,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY length(explanation_md))::int AS p95,
       round(100.0*count(*) FILTER (WHERE explanation_md ~ '제\s*\d+\s*조')/count(*),1) AS pct_article,
       round(100.0*count(*) FILTER (WHERE explanation_md ~ '\d{2,4}\s*(후|허|다|두|도|나|누|마|그|스)\s*\d+')/count(*),1) AS pct_caseno,
       round(100.0*count(*) FILTER (WHERE explanation_md ~ '[「『"“][^」』"”]{40,}[」』"”]')/count(*),1) AS pct_longquote,
       round(100.0*count(*) FILTER (WHERE length(explanation_md) < 100)/count(*),1) AS pct_thin
  FROM public.problems
 WHERE deleted_at IS NULL AND explanation_md IS NOT NULL
   AND law_code = 'patent'
 GROUP BY origin
 ORDER BY count(*) DESC;
```

### 2-2. 새 해설 지표 — 같은 정규식으로

`/tmp/haeseol.json`의 새 해설 본문에 2-1과 **동일한 정규식**을 적용해 같은 항목을 산출한다. 정규식이 다르면 비교가 무의미하니 반드시 일치시킬 것.

산출 항목: 건수, p50, p95, 조문 보유율, 사건번호 보유율, 긴인용 보유율, 100자 미만 비율.

### 2-3. 대조표로 보고

```
| 구분 | n | p50 | p95 | 조문 | 사건번호 | 긴인용 | 100자↓ |
| 예상문제 (현재) | | | | | | | |
| 예상문제 (해설편) | | | | | | | |
| 기출 (현재) | | | | | | | |
| 변형 (현재) | | | | | | | |
```

**기출 53건이 비교 기준이다.** 새 해설이 기출과 비슷하면 교재 문체가 일관된 것이고, 크게 다르면 예상문제 해설이 다른 필자에게서 나온 것이다.

조문 보유율은 현재 예상문제가 20.9%다. 이 값이 적재 후 어디로 가는지가 특허의 기준선을 결정하고, 앞으로 생성 해설 품질을 판정하는 잣대가 된다. 지금 안 찍으면 「원래 얼마였는지」를 영구히 잃는다.

## 3. 짧아지는 20건 목록화

새 해설이 기존보다 짧은 건을 전부 뽑아 `scripts/mcq-audit/skip-shorter.tsv`로 저장한다. 컬럼은 문항 식별자, 기존 길이, 새 길이, 차이. 축소폭 큰 순으로 정렬.

그다음 축소폭 상위 3건의 **기존 본문과 새 본문을 나란히 출력**한다. 요약하지 말고 전문을 그대로 보여줄 것.

판정 기준:

- 기존 본문이 교재 본문을 포함하면서 더 쓴 것 → 사람이 보강한 것. 건너뛴다
- 내용이 아예 다르면 → 오매칭이거나 다른 경로로 들어온 값. **보고하고 멈춘다**

P-7505가 기존 1,071자 대 교재 515자로 두 배 차이다. 여기부터 볼 것.

## 5. 적재 (승인 후)

### 적용 범위

- 대상 590건 중 **짧아지는 20건 제외 → 570건**
- 미매칭 2건(벌칙 1, 정정심판/특허의정정 1)은 제외하고 적재 후 개별 확인

### 방식

기존 해설 134건을 **덮어쓰지 않는다.**

- 새 해설은 새 행으로 적재
- 기존 목차 조각·정답줄 값은 soft-delete
- `CLAUDE.md`의 append-only 원칙에 따른다

각 행에 역추적 정보를 남긴다. 매칭 키(단원명·문항번호·offset)와 해설편 소스 위치. 570건 일괄 작업이라 오매칭 발견 시 어느 절 어느 문항에서 온 값인지 되짚을 수 있어야 한다.

### 절차

```
백업 → dry-run → --apply → 적재 후 재확인
```

`--apply` 직후 **2-1 SQL을 그대로 다시 실행**해 2-2 예측과 일치하는지 확인한다. p50, 조문 보유율, 100자 미만 비율 세 값을 대조할 것. 어긋나면 적재가 일부만 반영된 것이므로 즉시 멈추고 보고한다.

## 6. 적재와 별개로 남는 일

보고에 함께 적을 것. 지금 하지는 말 것.

**노드 없는 9건.** 분할출원#11(1), 조약일반(5), 실용신안법(3)은 `primary_node_id`가 비어 있어 `display_no` 구간으로 매칭했다. 적재는 되지만 체계도 태깅 누락은 그대로 남는다. 커리큘럼 노드가 SSOT인 구조에서 노드 없는 문항이 9건 있다는 뜻이므로 별도 처리가 필요하다.

**`paired_with_doc_id` 점검.** 이번 누락은 문서 쌍 중 해설편만 0건 적재된 경우였다. 같은 패턴이 다른 과목에도 있는지 확인해야 한다. 콘텐츠 상태와 무관한 파이프라인 점검이며 민법·자연과학도 대상이다.
