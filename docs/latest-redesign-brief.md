## 0. 산출물 한 줄

> 변리사 수험생이 **"오늘 무엇이 새로 올라왔는지"** 를 한 영역에서 확인하는 최신 정보 자동 집계 화면군. 법 개정 · 신규 판례 · 객관식/주관식 문제 · 논문 · 도서 추록·정오표 — 6종 정보가 카테고리별로 모이고, 각 항목은 곧바로 학습으로 이어진다. 리담변리사학원의 USP 3("최신 정보 자동 추적")을 담는 영역.

## 2. 핵심 목적 — 학습정보가 지켜야 하는 3원칙

리디자인의 모든 레이아웃 결정은 아래 3원칙을 따른다.

1. **"오늘 뭐가 새로 올라왔지?"에 즉답** — 학습정보의 존재 이유는 *최신성*이다. 매일 들어와 새 항목을 즉시 알아챌 수 있어야 한다. 최신순 정렬을 기본으로, 최근 항목은 상대 시각·NEW 마커로 또렷하게.
2. **흩어진 6종을 한 영역으로** — 법 개정·판례·문제·논문·도서 추록은 출처가 제각각이다. 학습정보는 이를 카테고리별로 모은 단일 집결지. 6개 화면이 서로 단절되지 않게 탭 strip 으로 묶는다.
3. **정보에서 학습으로 바로 연결** — 발견으로 끝나면 안 된다. 법 개정 → 영향 조문, 판례 → 판례 뷰어, 문제 → 즉시 응시, 논문 → 관련 조문·판례. 모든 항목은 학습 진입점이다.

## 4. 디자인 방향

### 4.1 톤

> "잘 정리된 학술 게시판 / 관보 색인" — 정보가 매일 쌓여도 어수선하지 않게. 차분·정돈·신뢰. 새 항목이 반갑게 눈에 들어오되, 과시하지 않는다.

### 4.2 색 · 타이포 · 형태 (디자인 시스템 SSOT 그대로)

- **색**: `colors_and_type.css` 의 Wantedly 토큰. 전경 black-with-alpha, 브랜드 딥 블루 `#2D5BA8`(strong `#1E4789`, deep `#3B6FC4`). 중성 배경 흰색 / `#FAFAFA` / `#EEEEEE`.
- **타이포**: Pretendard 단일. 색인 테이블의 헤더는 uppercase mono eyebrow. 숫자(건수·연도·날짜·정답률·타이머)는 `tabular-nums` 필수. 판례·문제 본문 발췌는 가독성 우선.
- **형태**: 8pt 그리드. 카드 radius `R12`, 색인 테이블 카드 `R12`, chip·pill `R100`. 2-layer 중성 그림자.
- **모션**: in-view reveal, 인라인 패널 펼침 120~240ms. `prefers-reduced-motion` 존중.

### 4.3 카테고리 색 · 의미색

- **6 카테고리 색 dot** — 각 카테고리를 옅은 색 dot 으로 식별 (랜딩 LatestSection 과 동일 계열): 법 개정=초록 · 판례=바이올렛 · 객관식=앰버 · 주관식=코랄 · 논문=블루 · 도서=브라운. 탭 strip·카드 accent 에 절제해 사용.
- **의미색**: 중요도 별 = 앰버 `#F7B500`. 정답 = 에메랄드 `#10A37F`, 오답 = 코랄 `#F65948`(응시 화면). 그 외 강조·링크·활성은 blue 단색.
- **NEW 마커**: 최근(예: 7일 이내) 등록 항목에 작은 blue/emerald pill. 과용 금지 — 정말 새 것에만.

## 5. 공통 패턴 — 9개 화면이 공유하는 셸

학습정보 화면들은 **같은 셸·필터·리스트 패턴**을 공유한다. 한 번 디자인해 재사용한다.

### 5.1 페이지 셸

- 가운데 정렬. **색인 테이블 화면**(법 개정·객관식 문제·응시 결과)은 넓은 폭(최대 ~1200px) — 표 컬럼이 많다. **피드 카드 화면**(판례·주관식·논문·추록)은 읽기 좋은 중간 폭(~1040px). **MCQ 응시 시험지**는 한 컬럼(~720~800px) 독서 폭.
- 좌우 거터 데스크톱 24~40px / 모바일 20px.

### 5.2 학습정보 탭 strip (신규 — 영역 연결 조직)

> **현재의 문제**: 6개 카테고리가 형제인데 서로 오갈 길이 네비게이션 드롭다운뿐이다.

- 화면 헤더 아래에 **6-segment 탭 strip**: `법 개정` · `최근 판례` · `객관식 문제` · `주관식 문제` · `논문` · `추록·정오표`. 각 세그먼트는 카테고리 색 dot + 라벨.
- 현재 화면 세그먼트 = blue 활성. 나머지는 `<Link>` 로 형제 라우트 이동. 데스크톱 가로 정렬, 모바일 가로 스크롤 strip.
- MCQ 팩 상세·시험지·결과는 `객관식 문제` 세그먼트가 활성(하위 화면) — 상단에 별도 뒤로가기 링크로 색인 복귀.

### 5.3 화면 헤더

- **eyebrow**: 작은 아이콘 + `LATEST · 학습정보` (uppercase 라틴).
- **제목**: 화면명 (법 개정 / 최근 판례 / …). Pretendard 800.
- **한 줄 설명**: 무엇을 모으는지 + **건수** + 적용된 필터 상태. 정렬 기준(최신순)을 명시.
- 운영자(staff) 화면은 헤더 우측에 `추가` 버튼 (객관식 문제·논문·추록). 학생에겐 미노출.

### 5.4 필터 바

> **현재의 문제**: 화면마다 native `<select>` 묶음 + `[적용]` 버튼. 폭이 들쭉날쭉하고 답답하다.

- **통일된 한 줄 필터 바** — 검색 인풋(아이콘 inset) + 필터 컨트롤(과목·연도·유형·구분·중요 등 화면별) + `초기화` 링크.
- 필터는 **chip 또는 정돈된 select** 로 — 화면 간 시각 일관. 검색은 디바운스 즉시 반영을 권장. 페이지네이션이 있는 화면(판례·논문·추록)은 GET 폼 유지도 허용하되 시각은 통일.
- 필터가 하나라도 걸리면 `초기화` 노출.

### 5.5 두 가지 리스트 패턴

**(A) 색인 테이블** — 법 개정 · 객관식 문제 · 응시 결과 통계
- `R12 border` 카드 안의 테이블. 헤더 행 = `bg-muted` + uppercase mono 컬럼명. 행 hover 강조, 충분한 행 높이.
- 셀 안의 chip(과목 약칭·구분·상태)·링크·O/— 첨부 마커를 일관 스타일로.

**(B) 피드 카드** — 최근 판례 · 주관식 문제 · 논문 · 추록·정오표
- 카드 1장 = 항목 1건. **헤더 메타 행**(카테고리/타입 badge + 분류 badge + 우측 날짜) + **제목/본문 발췌** + **태그·관련 chip** + **액션**(외부 링크·PDF·풀어보기).
- hover 시 카드 lift + 그림자 강화. 카드 전체 또는 제목이 원문 viewer 진입점.

### 5.6 최신성 표현

- 모든 항목에 **상대 시각** — "오늘" · "3일 전" · "2주 전". 정확 날짜는 보조로.
- 최근 등록 항목엔 **NEW 마커**(작은 pill). 최신순이 항상 기본 정렬.

### 5.7 인라인 확장 패널 (법 개정 전용)

- 법 개정의 첨부 4종(개정이유=마크다운, 신구조문대비표·개정해설=PDF, 동영상=YouTube/Vimeo 임베드)은 **행 아래 인라인 패널**로 펼친다. 펼침/접힘 부드러운 전환, 닫기 버튼.

### 5.8 운영자 인라인 편집

- staff 에게만 보이는 추가·수정·삭제. **추가/수정 폼은 행 위 카드로 펼침**(좁은 행 inline 금지 — 가독성 우선). 삭제는 확인 후.
- 학생 화면엔 편집 흔적 0. 운영자 UI 도 디자인 시스템 톤으로 정돈하되, 학생 경험을 가리지 않게 secondary 위계로.

### 5.9 페이지네이션 · 빈 상태 · 로딩

- 페이지네이션(판례 50/p, 논문·추록 20/p): 이전/다음 + `N / M`. 일관 스타일.
- **빈 상태**: 현재는 회색 점선 박스 한 줄 — 화면별로 제대로. 아이콘 + "아직 새 항목이 없습니다" + (운영자라면) 추가 안내. 데이터 0 vs 필터 0 카피 구분.
- 상태 렌더 순서: `에러 → 로딩 스켈레톤 → 빈 상태 → 콘텐츠`.

## 6. 화면별 명세

### 6.1 법 개정 (`/latest/laws`)

**색인 테이블** — 관보식 색인표. 컬럼: No · 구분(과목 약칭 badge) · 명칭 · 법률 등의 번호 · 개정일 · 시행일 + **첨부 4열**(개정이유 · 신구조문대비표 · 개정해설 · 동영상).
- 첨부 셀: 자료가 있으면 **`O` chip 버튼**(클릭 시 행 아래 §5.7 인라인 패널), 없으면 `—`. 펼친 셀은 활성 표시.
- 명칭 셀: 법명 링크(→ 과목 페이지) + `영향 조문 N건` + `★ 내 즐겨찾기 N`(앰버 — 내가 즐겨찾기/메모한 조문이 개정됨) + `보러가기 →`.
- 필터: 검색(법명·개정 번호) + 과목.
- **과제**: 10열 표가 빽빽하다. 컬럼 폭·행 높이를 숨 쉬게, 첨부 `O/—` 를 명료하게, 인라인 패널 전환을 깔끔하게.

### 6.2 최근 판례 (`/latest/cases`)

**피드 카드** + 페이지네이션(50/p).
- 카드: 법원 badge · 사건번호(mono) · 사건유형 · `전합` badge · 과목 badge · 우측 선고일 → 요지 제목(굵게) → 기출연도 chip(1·2차) → `판례 본문 보기 →`.
- 필터: 검색(사건번호·사건명·요지) + 과목 + 기출(1차/2차 보유) + 중요만(★3+).
- 카드 클릭 → 판례 뷰어(`/subjects/{과목}/cases/{id}`, 학습과목 영역 소관).

### 6.3 객관식 문제 — 색인 · 팩 흐름

#### 6.3.1 객관식 문제 (`/latest/mcq`)

**색인 테이블** — 문제집(pack) 목록. 컬럼: No · 과목 · 구분(기출/전체 모의/진도별 모의/기타 badge) · 명칭 · 출제일 · 문항 수.
- **명칭 = 클릭 즉시 응시 시작** — 기출은 학습 모드, 모의는 시험 모드로 자동 진입(아이콘으로 모드 구분). 별도 `상세` 링크 → 6.3.2.
- 운영자: `문제집 추가`(카드 폼) · 행별 수정/삭제 · `기출 자동 재생성`.
- 필터: 검색 + 과목 + 구분 + 연도.

#### 6.3.2 MCQ 팩 상세 (`/latest/mcq/:packId`)

- 뒤로가기 + 헤더(과목·구분·비공개 badge · 제목 · 설명 · 메타: 출제일·연도·회차·문항·제한시간).
- **2 카드**: `응시 시작`(학습 시작 / 모의는 모의고사 시작 버튼) · `참고 자료`(풀이 동영상 · 시험 결과 자료 링크).
- **문제 목록**: 번호 리스트 — 각 행 = 연도/문항번호·유형·출처 badge + 지문 발췌. 클릭 시 그 문제부터 응시 시작.
- 운영자: `problem_id` 입력으로 문제 추가 / 행별 제거.

#### 6.3.3 MCQ 응시 시험지 (`/latest/mcq/:packId/sheet/:sessionId`)

- 한 페이지에 모든 문제. 상단 **sticky 진행 바**: `응답 N/M` + (시험 모드) 타이머 + `채점하기`(학습) / `끝내기`.
- **학습 모드**: 선지 선택 → `채점하기` → 인라인 정오 표시 + 선지별·박스별 해설 + 종합 해설 reveal.
- **시험 모드**: 선택만, 채점 비공개. 타이머 만료/제출 시 결과로.
- 문제 블록 = 카드(헤더 badge 행 + 본문 + 박스형 항목 박스 + 선지 리스트 + 채점 후 해설 블록). 선지 상태: 선택/정답(에메랄드)/오답(코랄).

#### 6.3.4 MCQ 응시 결과 (`/latest/mcq/:packId/result/:sessionId`)

- 뒤로가기 + 헤더(구분 badge · 응시 완료/진행 중) + **KPI 4카드**(본인 정답률 · 총 문항 · 오답 · 소요 시간).
- 동영상 풀이 배너(있을 때) + **2 테이블**: 유형별 정답률(단답/박스/사례 — 본인 vs 전체) · 지문별 정답률(조문/판례/이론 — 본인 vs 전체).
- **문제별 결과 테이블**: No · 정오 아이콘 · 출처 · 본문 · 본인 선택 · 전체 정답률 · 시간.

### 6.4 주관식 문제 (`/latest/essay`)

**피드 카드**.
- 카드: 과목 badge · 출처(기출/기출변형/예상/모의) · 연도·문항번호 · 주관식 유형(사례형/논점형/혼합형) badge · 우측 등록일 → 논점(subjectiveTopic) → 지문 발췌 2줄 → `지금 풀어보기 →`.
- 필터: 검색(본문) + 과목 + 연도 + 출처 + 유형 + 키워드(정확 일치).

### 6.5 논문 (`/latest/papers`)

**피드 카드** + 페이지네이션(20/p).
- 카드: `논문` badge · 중요도(★) · 과목 badge · 우측 발행일 → 제목(파일 아이콘) → 메타(저자 · 출처 · 발행일) → 초록 3줄 → 태그 → **관련 조문/판례 chip 박스**(muted 박스 안에 조문·판례 chip — 학습과목으로 deep-link) → `외부 링크` · `PDF 열기` 버튼.
- 운영자: 추가/수정/삭제 + **링크 관리**(관련 조문·판례 추가·삭제 인라인).
- 필터: 검색(제목·저자·출처·초록) + 과목 + 연도 + 중요만.

### 6.6 추록·정오표 (`/latest/book-updates`)

**피드 카드** + 페이지네이션(20/p).
- 카드: 유형(추록/정오표/기타) badge · 중요도(★) · 과목 badge · 우측 발행일 → 자료 제목 → 책 제목·판쇄·출판사 → 내용/설명 → 태그 → `외부 링크` · `PDF 열기`.
- 운영자: 추가/수정/삭제.
- 필터: 검색(책·자료 제목·출판사·내용) + 유형 + 과목 + 연도 + 중요만.

## 7. 애니메이션

- **카드/행 진입**: in-view fade-up stagger. `IntersectionObserver` 한 번만, 긴 리스트는 상위 N개만.
- **인라인 패널**(법 개정 첨부): 펼침/접힘 height 트랜지션 + chevron rotate.
- **탭 strip**: 활성 인디케이터 slide.
- **필터 chip**: 토글 색 transition.
- **응시 시험지**: 채점 후 해설 블록 fade-in. 타이머는 단순 갱신(과한 모션 금지).
- **hover**: 카드 lift, 테이블 행 강조.
- 전 구간 `prefers-reduced-motion: reduce` 시 모션 사실상 정지. transform/opacity 만.

## 10. 기술 제약 (코딩 단계 참고)

실제 구현은 React Router 7 (SSR) + TypeScript strict + Tailwind v4 + shadcn(New York) + lucide-react + Vercel (Node SSR).

- 신규 npm 패키지·이미지/폰트 자산 도입 금지. 외부 스크립트 금지.
- 학습과목·학습보조와 같은 구현 방식 — **Tailwind 유틸리티 클래스** 기반, 블루는 디자인 시스템 토큰(`bg-primary` 등)으로.
- **다크 모드 지원** — 현 화면들이 light/dark 둘 다 렌더(`dark:` 변형 사용 중). 디자인 시 두 모드 모두 제공.
- 모바일 반응형 필수 — 색인 테이블은 가로 스크롤, 탭 strip 가로 스크롤, 필터 바 wrap.
- PDF는 `<iframe>`, 동영상은 YouTube/Vimeo 임베드 변환(그 외는 외부 링크) — 현 구현 유지.
- 파일 길이 목표 300줄 — 현재 화면 일부가 초과(논문·추록 600줄+). **§5 공통 셸·필터·카드·테이블·운영자 폼을 컴포넌트로 추출**(`app/features/latest/components/`)해 각 화면 entry 를 분할할 것.
- 컴포넌트는 표시 + 이벤트 연결만. `console.log` 잔류 금지. `any` / `@ts-ignore` 금지.
- 접근성(WCAG AA): 탭 strip·카드 링크는 `<Link>`/`<button>`, 필터는 `<button>`. 카테고리·정오 색은 색 + 라벨/아이콘 병기. 응시 타이머는 `aria-live` 적절히.

## 11. 우선순위 — 디자이너가 시간을 어디에 쓸지

1. **공통 셸 1벌** (§5) — 페이지 셸 · 학습정보 탭 strip · 헤더 · 필터 바 · **색인 테이블 패턴 + 피드 카드 패턴** · 페이지네이션 · 빈 상태. 9화면이 공유하므로 가장 공들일 부분.
2. **법 개정** — 가장 복잡한 표 + 인라인 확장 패널.
3. **피드 카드 4종** — 최근 판례 · 주관식 · 논문 · 추록. 카드 패턴 1벌로 반복.
4. **객관식 문제 + MCQ 팩 상세**.
5. **MCQ 응시 시험지 + 응시 결과** — 학습과목 문제 풀이와 시각 언어 일관.
6. **운영자 인라인 편집** — 추가/수정 폼 카드.
7. **빈 상태 / 로딩 스켈레톤**.
