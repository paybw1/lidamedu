# 학습 플랫폼 운영관리 — 사용설명서 (관리자 테스트 가이드)

> 이 문서는 **원장·매니저·강사(staff)** 가 학습 플랫폼(법령·조문·판례·문제·암기·2차 주관식·종합반·합격분석)의 운영 기능을
> **직접 눌러 보며 테스트하고 익히도록** 안내합니다. 강의 플랫폼(영상 강의·도서몰·주문·결제·정산·랜딩) 운영은 별도 문서
> `강의플랫폼-운영관리-사용설명서.md` 를 참고하세요.
>
> - 진입: 로그인 후 상단 **운영관리** → `/admin`
> - 화면 찾기: 운영관리 사이드바 상단 **화면 찾기…(⌘K / Ctrl+K)** 로 91개 화면을 이름으로 점프

## 0. 시작하기 전에 — 가장 중요한 규칙

### ★ 콘텐츠는 "승인·발행"해야 학생에게 노출됩니다

학습 플랫폼 콘텐츠는 거의 전부 **초안(draft) → 검토 → 승인/발행** 단계를 거칩니다. **승인 전에는 학생에게 보이지 않습니다**(서버에서 차단). 이 한 가지가 학습 플랫폼 운영의 핵심입니다.

| 콘텐츠 | 노출되는 순간 |
|---|---|
| 객관식 문제 | 검토 대기에서 **검토완료(approve)** |
| 기출 해설 · 지문 텍스트 | 검수에서 **승인(approve)** → 운영본으로 복사 |
| 정오문제(OX) | 검수에서 **활성(active) 토글** |
| 모의고사 문제집 | **과목 공개(release_to_subjects)** |
| 판례 쟁점훈련 | 항목·쟁점 **승인(approve)** |
| 빈칸(판례/조문 후보) | 승인 큐에서 **승인(approve)** |
| 암기 카드(SRS) | 미리보기(dry-run) → **생성(generate)** |
| 법 개정 조문 | **발행(apply)** + 시행일 도래(자동 승격) |
| 2차 주관식 채점 | 채점에서 **마무리(finalize)** |
| 공지 | **발행(publish)** |

> **테스트 시 주의**: 모든 액션은 **실제 운영 DB에 즉시 반영**됩니다. 승인·발행·삭제는 리허설 후 신중히. 삭제는 대부분 soft-delete지만 일부(탈퇴 완전삭제)는 **비가역**입니다.

### 역할별 접근

- **강사(instructor/staff)**: 콘텐츠 CRUD. 단 **담당 과목**(`/admin/instructors`에서 지정)만 문제·판례·조문개정 쓰기 가능.
- **매니저(manager)+**: 전체 학습현황, 대량 발송, 등업 승인, 커뮤니티 신고, Q&A SLA 등.
- **원장(admin)**: 전부 + 회원/역할/탈퇴/감사/관리자 지정.

> 사이드바에 화면이 안 보이면 **역할 권한(minRole) 문제**입니다.

### 운영관리 지도 (학습 플랫폼)

| 섹션 | 클러스터 | 다루는 일 |
|---|---|---|
| **콘텐츠** | 법령·개정 / 판례 / 객관식·정오문제 / 암기 자료 / 연관관계 / 데이터 점검 | 조문·판례·문제·빈칸 제작과 데이터 무결성 |
| **시험·분석** | 주관식 문제 / 학습·합격 분석 | 2차 GS 출제·채점, 전체 학습현황·합격 분석 |
| **수강생·반** | 내 활동 / 회원 관리 / 종합반 관리 / 강사 관리 | 수강생·반 운영, 과제·출결·상담, 강사 권한 |
| **운영·시스템** | 공지·커뮤니티 / Q&A 운영 / 시스템 | 공지·모더레이션, 강사/AI Q&A, 감사·가이드 |

# 콘텐츠

## 1. 법령·조문

### 1-1. 법령 허브 · 개정 워크스페이스
- **화면**: 콘텐츠 → 법령·개정 → **법령 허브** (`/admin/laws`) → 법 선택 → 개정 워크스페이스
- **무엇을**: 법령 원문(조문)은 **읽기 전용 불변**. 수정은 반드시 **개정 흐름**으로만 합니다.

**워크플로우 (법 개정)**
1. draft 개정본 생성 → 개정 워크스페이스 진입 (`/admin/laws/:law/revisions/:id`)
2. 조문 추가/수정/삭제 (수동 또는 AI 초안), 전문 PDF 업로드
3. 시행일(effective_date) 지정 후 **발행(apply)**
4. **시행일이 도래하면** 크론(promote-law-revisions)이 현행 조문으로 자동 승격

> ⚠ 기존 `article_revision`은 **절대 수정하지 않습니다**(불변 스냅샷). 개정은 항상 새 리비전으로.

### 1-2. 단원 체계도
- **화면**: 콘텐츠 → 법령·개정 → **단원 체계도** (`/admin/systematic-tree`)
- **무엇을**: `systematic_nodes` 트리를 JSON으로 export/import. 과목 → 과목 구조 이식용.

### 1-3. 강의노트 위치 확인
- **화면**: 콘텐츠 → 법령·개정 → **강의노트 위치 확인** (`/admin/lecture-locations`)
- **무엇을**: 강의노트 페이지 위치·진척도 확인, 옆 패널 pdfjs 열람, 페이지 수정/추가/삭제·라벨 보강·확인 표시.

### 1-4. 콘텐츠 완성도 (데이터 점검)
- **화면**: 콘텐츠 → 데이터 점검 → **콘텐츠 완성도** (`/admin/laws/health`)
- **무엇을**: 5법 × 8지표 헬스 매트릭스(0~100). 최저 지표를 추천하고 해당 작업 화면으로 딥링크.

## 2. 판례

### 2-1. 판례 등록
- **화면**: 콘텐츠 → 판례 → **판례 등록** (`/admin/cases/edit`, 수정 `/:caseId`)
- **무엇을**: 판례 등록/수정. 전문 PDF·이미지 업로드, 체계도 배치.
- **주의**: 식별 필드(사건번호·법원·선고일)는 보존. 요지·이유·평석은 교재 기반 편집물이라 in-place 수정 가능.
- **액션**: 생성 · 삭제 · 전문 PDF 업로드/제거 · 대표 배치 설정 · 체계도 추가/제거 · 이미지 업로드/메타.

### 2-2. 판례·조문 매칭 / 판례·기출 매칭
- **판례·조문 매칭** (`/admin/cases`): 판례↔조문 매핑(카드·검색). 추가/제거.
- **판례·기출 매칭** (`/admin/relations/exam-cases`): 1차 객관식 기출↔판례 수동 매칭(자동 스캔 미연결 보정). 재스캔·연결·해제·해설 편집.

### 2-3. 판례 쟁점훈련 출제 (2차 앞단)
- **화면**: 콘텐츠 → 판례 → **판례 쟁점훈련 출제** (`/admin/case-training`, 신규 `/new`, 편집 `/:itemId`)
- **무엇을**: 판례 기반 쟁점추출 훈련(항목 = 판례 + 사실관계 + 쟁점들). AI 초안 + 강사 검토·승인.

**워크플로우**
1. 항목 생성(판례 지정) — "전문 없음" 판례는 선택 불가.
2. **사실관계 요약** 작성(AI 초안 가능). ⚠ 쟁점·판단·결론이 들어가면 **누출 lint 경고** — 사실 위주로.
3. **쟁점 목록** 편집(AI 초안/행 단위, 핵심·부차 지정) → 각 쟁점 **승인**.
4. **항목 승인**(사실관계 50자+ · 승인 쟁점 2건+) → 학생 응시(`/case-training`) 노출.

> 결론·강약(③④)은 같은 편집 화면 하단 섹션에서 함께 출제(선택).

## 3. 객관식 문제 · 정오문제

> 출제 흐름 순서: **AI 초안 → 검토 승인 → (직접 출제) → 팩·통합 시험**. 검토 승인 전에는 학생 미노출.

### 3-1. AI 문제 초안 만들기
- **화면**: 콘텐츠 → 객관식 문제·정오문제 → **AI 문제 초안 만들기** (`/admin/problems/ai-gen`)
- **무엇을**: 과목 + 조문 + 유형(단답형/박스형) + 개수 + 모델을 지정해 AI 초안을 일괄 생성 → 검토 큐로.

### 3-2. 검토 대기 문제
- **화면**: **검토 대기 문제** (`/admin/problems/review`)
- **무엇을**: 검증 대기 큐(필터·다중선택·bulk) + 상세(본문·선지·근거 청크).
- **액션**: 승인 · 반려 · 일괄 승인/반려 · 빠른 수정.
- **노출**: **승인(reviewed)** 시 학생 노출.

### 3-3. 기출 해설 검수 / 지문 텍스트 검수
- **기출 해설 검수** (`/admin/problems/explanations`): AI 해설 초안 ↔ 문제 이미지 대조 승인/반려. **승인 시 RPC가 explanation_md로 복사 → 노출**.
- **지문 텍스트 검수** (`/admin/problems/text-conversion`): 자연과학 지문 전사(발문+선지) 검수. **승인 시 body_md 운영 반영 → 텍스트 노출**.

### 3-4. 직접 출제 · 목록 · 시험번호
- **문제 직접 만들기** (`/admin/problems/new`): 최소 메타+본문 INSERT → 상세 편집.
- **전체 문제 보기** (`/admin/problems`): 출처·유형·극성·연도·조문 필터, 체계도 정렬. 상세에서 검토·수정·삭제·불일치 플래그.
- **기출 시험번호 매칭** (`/admin/problems/exam-number`): P-코드로 찾아 실제 시험 문항번호 지정/정정.

### 3-5. 정오문제(OX) 검수
- **화면**: **정오문제 검수** (`/admin/problems/ox`)
- **무엇을**: 과목별 OX 후보(선지/박스항목) 일괄 검토·인라인 수정.
- **노출**: **활성(active) 토글** 시 학생 노출.

### 3-6. 모의고사 · 통합 모의고사
- **모의고사 문제집 관리** (`/latest/mcq?kind=mock`): 모의/가상통합 문제집. 생성·수정·문제 추가/제거·기출 자동 재생성 · **과목 공개(release_to_subjects) 시 학생 공개**.
- **통합 모의고사(3교시)** (`/admin/mcq-exams`): 교시(paper) 구성. 공개/비공개 플래그.

### 3-7. 정답률·통계
- **정답률·통계** (`/admin/problems/stats`): 객관식+OX 풀이 시도 서버 집계(읽기).

## 4. 암기 자료

### 4-1. 빈칸 자료 세트
- **화면**: 콘텐츠 → 암기 자료 → **빈칸 자료 세트** (`/admin/blanks`)
- **무엇을**: 빈칸 세트 목록·편집(조문 빈칸 인라인 추가/제거). 세트 발행.

### 4-2. 판례 빈칸 승인 / 조문 빈칸 승인 (승인 큐)
- **판례 빈칸 승인** (`/admin/blanks/cases`): OX 기출 유래 판례 빈칸 후보 큐. **승인 시** 판례 '기출 유래' 세트에 blank 기록.
- **조문 빈칸 승인** (`/admin/blanks/article-candidates`): OX 거짓지문 유래 조문 함정 키워드 후보 큐. **승인 시** 승인자 '내 세트'에 기록.
- 각 큐: 승인 / 반려 / 되돌리기(+승인 시 정답 인라인 수정).

### 4-3. 암기 카드 생성 (SRS)
- **화면**: 콘텐츠 → 암기 자료 → **암기 카드 생성** (`/admin/srs-cards`)
- **무엇을**: 조문·판례에서 전역 SRS 카드 생성. **미리보기(dry-run) → 생성(generate, 멱등)**. 학습은 학생 `/srs`.

### 4-4. 빈칸 정답률
- **빈칸 정답률** (`/admin/blanks/stats`): 빈칸 시도 통계(읽기).

## 5. 연관관계 · 데이터 점검

- **연결 일괄 등록** (`/admin/relations/bulk`): 조문↔판례 연관관계 TSV/CSV 붙여넣기 → 존재 검증 → **적용(apply)**.
- **데이터 점검** (콘텐츠 → 데이터 점검):
  - **데이터 가져오기 점검** (`/admin/seeds/preview`): 시드 CSV import **dry-run(preview) → 승인 후 apply**.
  - **전문 PDF 미적재** (`/admin/cases/pdf-missing`): 공식 전문 PDF 미적재 사건번호 목록.
  - **체계도 배치 점검** (`/admin/cases/violations`): 단일 배치 위반 판례 → 대표 노드 확정.
  - **고아 하이라이트 점검** (`/admin/cases/orphan-highlights`): 재배치 불가 하이라이트 정리.
  - **연결 누락 점검** (`/admin/relations/gaps`): 법별 미매핑 조문/판례/문제 일람 + 즉시 매핑 진입.

# 시험·분석

## 6. 2차 주관식 (GS)

### 6-1. 주관식 회차
- **화면**: 시험·분석 → 주관식 문제 → **주관식 회차** (`/admin/gs`, 신규 `/new`, 편집 `/:roundId`)
- **무엇을**: 회차 목록(draft 포함) + 편집(메타·문제·시험지/모범답안 업로드).
- **액션**: 회차 저장 · 기본 세팅 · 시험지/모범답안 업로드 · 문항 저장/삭제 · 회차 삭제 · **객관식 풀 승격(promote-to-problems)**.

**워크플로우 (주관식)**
1. 회차 생성(시험지·모범답안 업로드) → **발행**
2. 학생 응시(답안지 페이지 업로드)
3. **채점 큐**(`/admin/gs/:roundId/grade`) → 문항별 점수·피드백 → **마무리(finalize) 시 학생 공개**
4. (선택) 동료채점 배정 · 분쟁 문항 검토 · 우수답안 선정
5. 논점추출은 별도 **논점 검증**(`/:roundId/issues`) 승인 흐름 — 승인 시 학생 논점추출 훈련 노출

### 6-2. 주관식 시리즈 · 포인트 · 사용량
- **주관식 시리즈** (`/admin/gs/series`): 회차 묶음 시리즈.
  (2026-08-18 기출 경로 강사 첨삭 폐지 — `/admin/subjective-reviews` 제거. 기출 주관식은 학생이 논점·목차·포섭 3단계를 훈련하고 AI 초안 채점만 받는다. GS 회차의 강사·동료·AI 채점은 그대로.)
- **포인트 관리** (`/admin/gs/points`): 학생 잔액 조회 + 수동 지급/차감.
- **AI·OCR 사용량** (`/admin/gs/usage`): 사용량·cap 잔여·추이(읽기).

# 수강생·반

## 8. 종합반 운영

### 8-1. 반 관리 · 등업 신청
- **반 관리** (`/admin/cohorts`): 반/기수 + 멤버 관리(강사=본인 반, 원장=전부). 생성·수정·삭제·멤버 추가/제거.
- **등업 신청** (`/admin/cohort-requests`, 매니저+): pricing 종합반 등업 신청 접수 → **반 배정 승인(=등업)/반려**.

### 8-2. 반별 게시판 · 커리큘럼
- **반별 게시판 관리** (`/admin/cohort-boards`): 게시판 생성/수정/삭제 + write_scope(공지형/소통형) + 접근 반 다중 선택.
- **커리큘럼 관리** (`/admin/curricula`): 주차·항목 편집 + 반 적용.

### 8-3. 과제 · 오프라인 테스트 · 출결
- **과제** (`/admin/cohorts/:id/assignments`): 반 과제 목록·편집·학생 진척. 커리큘럼 주차 자동 변환, **약점 개인과제 자동 생성**.
- **오프라인 테스트** (`.../tests/:testId`): 시험지 빌더·인쇄·성적 입력. 문항 정오는 학습 신호로 합류.
- **출결 대장** (`.../attendance`): 회차 추가 + 학생별 누계 출석률·체크. (결석만 감점)
- **성적·진척·통계**: 테스트 시리즈 성적추이·월간 성적표 인쇄·반 통계.

**워크플로우 (종합반)**: 등업 승인(반 배정) → 커리큘럼 적용 → 주차→과제 변환·약점 개인과제 → 오프라인 테스트·출결 → 성적추이·월간 성적표 → 상담(내 활동).

### 8-4. 내 활동 (상담·과제)
- **내 활동** (`/admin/my-activity`): 내가 한 상담 코멘트·과제 부여 + 상대 반응(열람·완수)을 한 타임라인.

## 13. 테스트 체크리스트

- [ ] **AI 문제 초안** 생성 → **검토 대기**에서 승인 → 학생 화면(과목)에서 노출 확인
- [ ] **기출 해설/지문 검수** 승인 → 해당 문제에서 해설/텍스트 노출 확인
- [ ] **정오문제(OX)** 활성 토글 → OX 패널에 노출 확인
- [ ] **판례 등록** → 조문·기출 매칭 → 판례 뷰어에서 연결 확인
- [ ] **판례 쟁점훈련** 항목·쟁점 승인 → 학생 `/case-training` 노출 확인
- [ ] **빈칸 승인 큐**(판례/조문) 승인 → 세트에 반영 확인
- [ ] **암기 카드** dry-run 미리보기 → 생성 → 학생 `/srs`에서 확인
- [ ] **모의고사 문제집** 과목 공개 → 학생에게 노출 확인
- [ ] **법 개정** draft → 발행 → (시행일 도래 시) 현행 승격 확인
- [ ] **2차 회차** 발행 → 응시 → 채점 마무리 → 학생 점수·피드백 공개 확인
- [ ] **종합반**: 등업 승인(반 배정) → 커리큘럼→과제 → 출결 → 성적표 확인
- [ ] **강사 담당·권한** 지정 → 그 강사가 담당 과목만 쓰기 가능한지 확인
- [ ] **공지 발행** → 학생 알림 노출 확인
- [ ] **데이터 점검**: 콘텐츠 완성도·연결 누락에서 결손 파악
