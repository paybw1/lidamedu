> **앞선 작업과의 관계** — 같은 프로젝트의 랜딩(`ui_kits/lidam-web/`)·대시보드(`ui_kits/lidam-dashboard/`)·학습과목(`ui_kits/lidam-subjects/`)은 이미 Wantedly 기반 **딥 로열블루 `#2D5BA8`** 디자인 시스템으로 진행됐다. 학습보조 영역도 **같은 디자인 시스템**으로 통일한다. 콘텐츠·네비게이션·voice 규칙은 `uploads/landing-redesign-brief.md` 와 이 문서를 따른다.

## 0. 산출물 한 줄

> 변리사 수험생이 조문·판례·문제 viewer 곳곳에 남긴 학습 흔적 — **틀린 문제 · 즐겨찾기 · 메모 · 하이라이트** — 을 한 곳에 모아 보고, 필터로 좁히고, 다시 학습으로 되돌리는 4개 화면군. 작성(write)이 아니라 **모아보기 · 재진입(collect & re-enter)** 이 핵심이다.

## 2. 핵심 목적 — 학습보조가 지켜야 하는 3원칙

리디자인의 모든 레이아웃 결정은 아래 3원칙을 따른다.

1. **흩어진 흔적을 한 곳에** — annotation 은 조문·판례·문제·OX viewer 곳곳에서 생성된다. 학습보조는 과목·콘텐츠 타입을 가로질러 모은 **단 하나의 집결지**. "내가 표시해 둔 게 어디 있더라"가 사라져야 한다.
2. **다시 학습으로 되돌린다** — 모아보기로 끝나면 안 된다. 모든 항목은 원문 viewer 로 가는 진입점이고, 오답·즐겨찾기 문제는 "묶어 풀기"로 한 세션 즉시 재학습. 화면의 목적은 보관이 아니라 **복습 재개**다.
3. **빠르게 좁힌다** — 수험 후반엔 항목이 수백~수천 건. 과목·타입·색상·별점 필터와 본문 검색으로 "지금 복습할 그것"만 1~2 클릭에 남긴다.

## 4. 디자인 방향

### 4.1 톤

> "공부하다 접어 둔 책갈피로 다시 돌아오는 자리" — 차분 · 정돈 · 약간의 격려. 흔적이 쌓일수록 **든든해** 보여야지, 밀린 일거리처럼 보이면 안 된다. 학구적이되 부담스럽지 않게.

### 4.2 색 · 타이포 · 형태 (디자인 시스템 SSOT 그대로)

- **색**: `colors_and_type.css` 의 Wantedly 토큰. 전경은 black-with-alpha(`rgba(0,0,0,α)`), 브랜드는 딥 블루 `#2D5BA8`(strong `#1E4789`, deep `#3B6FC4`, soft/tint 는 alpha 단계). 중성 배경은 흰색 / `#FAFAFA` / `#EEEEEE`.
- **타이포**: Pretendard 단일. 카드 본문 발췌·메모는 가독성 우선(13~14px, line-height 1.6+). 숫자(건수·시도 횟수·별점·상대시간)는 `tabular-nums` 필수.
- **형태**: 8pt 그리드. 카드 radius `R12`, chip·필터 pill `R100`. 2-layer 중성 그림자(`--elev-4` 기본, `--elev-8` hover).
- **모션**: in-view reveal `cubic-bezier(0.22,1,0.36,1)`, 인터랙션 120~240ms. `prefers-reduced-motion` 존중.

### 4.3 의미색 (절제 — "좋음/나쁨" 신호와 사용자 데이터에만)

- **하이라이트 4색**(초록·노랑·빨강·파랑)은 **사용자가 직접 고른 데이터** — 그대로 다색 유지. blue 시스템으로 덮지 말 것.
- **별점**은 앰버 `#F7B500`. **오답 신호**(틀린 답·OX 오답 배지)는 코랄 `#F65948`.
- **콘텐츠 타입**(조문·판례·문제·OX)은 절제된 색 dot 또는 라벨로 구분 — 카드 안에서 과하지 않게. 그 외 모든 강조·링크·활성 상태는 blue 단색.

## 5. 공통 패턴 — 4개 화면이 공유하는 셸

학습보조 4화면은 **같은 셸 한 벌**을 쓴다. 한 번 디자인해 네 화면에 재사용한다.

```
┌──────────────────────────────────────────────┐
│  화면 헤더 — eyebrow · 제목 · 한 줄 설명         │
│  ┌────────────────────────────────────────┐  │
│  │ 학습보조 탭 strip — 오답/즐겨/메모/하이라이트 │  │  ← §5.2
│  └────────────────────────────────────────┘  │
│  카운트 요약 (전체 N · 타입별 N …)              │
├──────────────────────────────────────────────┤
│  [묶어 풀기 세션 CTA]  ← 오답노트·즐겨찾기만      │
│  필터 바 — 검색 + chip/select 필터             │
├──────────────────────────────────────────────┤
│  결과 리스트 — 카드 세로 stack                  │
│   · 빈 상태 / 로딩 스켈레톤                      │
└──────────────────────────────────────────────┘
```

### 5.1 페이지 셸

- 단일 컬럼, 가운데 정렬. 컨테이너 최대폭 **960~1040px**, 좌우 거터 데스크톱 24~40px / 모바일 20px.
- 사이드바 없음 — 학습보조는 "관리 화면"이라 넓은 본문보다 **편안한 한 줄 길이**가 우선.

### 5.2 학습보조 탭 strip (신규 — 영역 연결 조직)

> **현재의 가장 큰 문제**: 4화면이 형제인데 서로 오갈 길이 네비게이션 드롭다운뿐이다. 오답노트를 보다 즐겨찾기로 가려면 상단 메뉴를 다시 펼쳐야 한다.

- 화면 헤더 바로 아래에 **4-segment 탭 strip** 을 둔다. 세그먼트: `오답노트` · `즐겨찾기` · `메모` · `하이라이트`. 각 세그먼트는 lucide 아이콘 + 라벨 + (선택) 건수 뱃지.
- 아이콘: 오답노트 `NotebookPen`, 즐겨찾기 `Bookmark`, 메모 `StickyNote`, 하이라이트 `Highlighter`.
- 현재 화면 세그먼트 = blue 활성(채움 또는 굵은 underline). 나머지는 `<Link>` 로 형제 라우트 이동.
- 데스크톱은 가로 정렬, 모바일은 가로 스크롤 strip.
- **건수 뱃지는 권장**: 4탭에 각 화면 총 건수를 보여 주면 "어디에 뭐가 쌓였는지" 한눈에 인지된다. 형제 화면 건수는 가벼운 `count` 쿼리 3개로 충당 가능 — 신규 위젯이 아니라 네비게이션 보조이므로 허용. 디자인 mockup 에는 건수를 채워 그릴 것.

### 5.3 화면 헤더

- **eyebrow**: 작은 아이콘 + `학습보조` (uppercase 라틴 eyebrow 패턴도 가능 — `STUDY AIDS`).
- **제목**: 화면명 (오답노트 / 즐겨찾기 / 메모 / 하이라이트). Pretendard 800, 22~26px.
- **한 줄 설명**: 이 화면이 무엇을 모으는지 + 정렬 기준 (각 §6 참조).
- **카운트 요약**: 전체 건수 + 분류별 건수를 작은 stat chip 또는 inline 숫자로. 숫자는 진입 시 count-up.

### 5.4 필터 바

> **현재의 문제**: 작은 native `<select>` 가 다닥다닥 붙어 있고 `[적용]` 버튼을 눌러야 반영된다. 답답하고 한 박자 느리다.

- 필터를 **pill/chip** 으로 재설계 — 클릭 즉시 반영(별도 적용 버튼 없음). 활성 chip = blue 채움.
- 검색이 있는 화면(메모·하이라이트)은 **검색 인풋**을 필터 바 맨 앞에 — 아이콘 inset, 디바운스 즉시 반영.
- 필터가 하나라도 걸리면 **`초기화`** 링크 노출.
- 좁은 화면에서는 필터 바가 한 줄에서 자연스럽게 wrap. 필터 종류가 많은 화면(즐겨찾기·하이라이트)은 모바일에서 "필터" 토글 → 펼침도 허용(디자이너 재량).
- 구현 메모: 즐겨찾기·메모·하이라이트는 loader 가 전체 집합을 이미 불러오므로 클라이언트 즉시 필터링이 가능하다. 디자인은 "즉시 반영"을 전제로 하면 된다.

### 5.5 결과 리스트 & 카드

- 결과는 카드 세로 stack(간격 8~10px). 카드 1장 = 항목 1건, **전체가 원문 viewer 로 가는 링크**(클릭 가능 영역 = 카드 전체).
- 카드 공통 구조: **헤더 행**(타입·과목·부가 라벨 + 우측 메타) + **본문**(콘텐츠 발췌) + **푸터**(우측 정렬 진입 링크 — "다시 풀기 →" / "다시 학습 →" / "원문에서 보기 →").
- 타입은 색 dot 또는 라벨로, 과목은 조용한 텍스트로. **badge 를 5개씩 늘어놓지 말 것** — 위계를 만든다(가장 중요한 식별자 1~2개만 강조, 나머지는 메타로 축소).
- hover: 카드 lift(`translateY(-2px)` + 그림자 강화) + 진입 링크 화살표 `translateX`.
- 긴 리스트(최대 2000건)에 대비 — 행 높이 충분히, 스캔 가능하게.

### 5.6 "묶어 풀기" 세션 CTA — 오답노트 · 즐겨찾기 전용

- 오답노트(객관식 오답)·즐겨찾기(필터 결과 안 객관식 문제)는 상단에 **세션 시작 배너**를 둔다.
- 구성: 아이콘 + "N건을 한 세션으로 묶어 풀기" + `[학습 모드]`(즉시 해설) · `[시험 모드]`(타이머·일괄 채점) 두 버튼.
- 보조 정보(`<form>` POST)가 아니라 **이 영역의 핵심 행동** — blue tint 배경 + 또렷한 버튼으로 시각적으로 끌어올린다. 약하고 밋밋한 띠로 묻지 말 것.

### 5.7 빈 상태 · 로딩 스켈레톤

- **빈 상태**(현재는 회색 점선 박스 + 한 줄): 화면별로 제대로 디자인. 큰 아이콘 + "아직 없습니다" + **무엇을 하면 채워지는지** 안내(예: "조문을 학습하며 ♡ 별점을 매겨 보세요") + 학습 시작 CTA(`/dashboard` 또는 `/subjects/...`). 데이터가 0건 vs 필터 결과 0건은 **다른 카피**로 구분(이미 현 구현이 구분함).
- **로딩 스켈레톤**: 탭 strip 이동(클라이언트 navigation) 시 결과 리스트 자리에 카드 3~5개 형태의 스켈레톤.
- 상태 렌더 순서: `에러 → 로딩 스켈레톤 → 빈 상태 → 콘텐츠`.

## 6. 화면별 명세

### 6.1 오답노트 (`/study/wrong-note`)

**무엇을 모으나** — *가장 최근 시도가 오답인* 문제만. 다시 풀어 정답이면 큐에서 자동 제거된다(자기 정리형 — 빈 상태가 곧 성취). 객관식과 정오문제(OX) **2섹션**으로 나뉜다.

- **헤더 설명**: "전체 과목 오답 · 객관식 N건 · 정오문제 N건 · 가장 최근 시도가 오답인 항목만. 다시 풀어 정답이면 자동 제거됩니다."
- **필터**: 과목 1종(전체 / 특허법 / 상표법 / 디자인보호법 / 민법 / 민사소송법).
- **세션 CTA**(객관식 오답 ≥1): "객관식 오답 N건을 한 세션으로 묶어 풀기" + 학습/시험 모드 → §5.6.
- **섹션 1 — 객관식 오답** 카드: 타입/과목/대표 조문/연도·문항번호 + 우측 `시도 N회`, 본문 지문 발췌, `다시 풀기 →`. 진입 → 문제 viewer.
- **섹션 2 — 정오문제 오답** 카드: `OX` 코랄 배지 + 과목/대표 조문/연도 + `시도 N회`, OX 지문, **`내 답`(코랄) vs `정답`** 대비 표기, `조문에서 다시 풀기 →` 또는 `원문제 보기 →`.
- **빈 상태**: "오답이 없습니다 — 문제를 풀어 보세요." 부담이 아니라 **칭찬**처럼 보이게(긍정 톤 + 일러스트성 체크 아이콘).
- mock 예: `특허법 · 제29조 · 2024년 12번 · 시도 3회 — "다음 중 신규성 판단에 관한 설명으로 옳지 않은 것은?"`

### 6.2 즐겨찾기 (`/study/bookmarks`)

**무엇을 모으나** — viewer 우측 패널 ♡ 별점(1~5)으로 표시한 **조문 · 판례 · 객관식 문제 · OX 지문 · OX 박스** 전부. 별점 높은 순 → 최근 수정 순.

- **헤더 설명** + **카운트 요약**: 전체 / 조문 / 판례 / 문제 / OX 건수.
- **필터**: 과목 · 타입(전체 / 조문 / 판례 / 객관식 문제 / OX 지문) · 최소 별점(1↑ ~ 5). + 초기화.
- **세션 CTA**(필터 결과 안 객관식 문제 ≥1): "즐겨찾기 객관식 문제 N건 묶어 풀기" → §5.6.
- **카드**: 타입 라벨 + 과목 + 부가 라벨(secondaryLabel) + (OX 면 정답 O/X) + **별점 5칸 바**(채워진 칸 앰버). 본문 = primaryLabel(굵게) + bodySnippet + (있으면) `메모 · {notePreview}` 인용. `다시 학습 →`.
- **별점**은 이 화면의 시그니처 — 카드에서 또렷하게. 별점 = 학습 우선순위 신호.
- **빈 상태**: 0건이면 "조문/판례/문제 viewer 우측 패널의 ♡ 별점으로 추가하세요"; 필터 0건이면 "필터에 해당하는 즐겨찾기가 없습니다".
- mock 예: `조문 · 특허법 · 제29조 · ★★★☆☆ — 특허법 제29조 (특허요건) · 메모 · 신규성 핵심 정리`

### 6.3 메모 (`/study/notes`)

**무엇을 모으나** — 조문·판례·문제·OX viewer 에서 작성한 메모 전부. 최근 수정 순.

- **헤더 설명** + 카운트 요약(전체 / 조문 / 판례 / 문제 / OX).
- **필터**: 본문 검색(메모 내용·발췌·라벨 매칭) · 과목 · 타입. + 초기화.
- **카드**: 타입 라벨 + 과목 + 부가 라벨 + 우측 상대시간("3일 전"). 본문 = primaryLabel + (있으면) **발췌 `snippet`**(메모가 가리키는 본문 단어/구문 — 인용 박스, 회색) + 메모 본문 `bodyMd`(연필 아이콘 + 좌측 보더로 "내가 쓴 글" 표시). `원문에서 보기 →`.
- **발췌 vs 메모 본문** 두 텍스트의 위계를 명확히 — 발췌는 "무엇에 대한 메모인지"(인용), 메모 본문이 주인공.
- **빈 상태** / mock 예: `조문 · 특허법 · 제29조 · 3일 전 — 특허법 제29조 · 발췌 "특허를 받을 수 있다" · 메모 "신규성·진보성을 모두 충족해야…"`

### 6.4 하이라이트 (`/study/highlights`)

**무엇을 모으나** — 본문에서 색칠한 발췌 전부(초록·노랑·빨강·파랑 4색). 최근 작성 순.

- **헤더 설명** + 카운트 요약: 전체 + **색상별 건수**(색 dot + 라벨 + 수).
- **필터**: 본문 검색(발췌 텍스트) · 과목 · 타입 · **색상**(초록/노랑/빨강/파랑). + 초기화.
- **카드**: 타입 라벨 + 과목 + 부가 라벨 + **색상 chip**(dot + 라벨) + 우측 상대시간. 본문 = primaryLabel + bodySnippet + **색칠 발췌 `excerpt`**(해당 색의 부드러운 배경 박스로 — 실제 하이라이트처럼 보이게). 발췌가 없으면 "(발췌 텍스트 없음)" 회색 이탤릭. `원문에서 보기 →`.
- 색칠 발췌 박스가 이 화면의 시그니처 — 4색이 리스트에서 한눈에 구분되게.
- **빈 상태** / mock 예: `조문 · 특허법 · 노란색 · 5일 전 — 특허법 제29조 · 색칠 "공지되었거나 공연히 실시된 발명"`

## 7. 애니메이션

- **카드 진입**: in-view fade-up(opacity + translateY) stagger(카드당 ~50ms). `IntersectionObserver` 한 번만, `unobserve`.
- **헤더 카운트**: count-up (전체/타입별/색상별 건수). `prefers-reduced-motion` 시 즉시 최종값.
- **별점 바**(즐겨찾기): in-view 시 칸이 좌→우로 채워짐.
- **탭 strip 이동**: 활성 인디케이터가 세그먼트 사이를 slide. 결과 영역은 스켈레톤 → 콘텐츠 crossfade.
- **필터 chip**: 토글 시 배경 색 transition(140~160ms).
- **hover**: 카드 lift + 진입 화살표 `translateX(3px)`.
- 전 구간 `@media (prefers-reduced-motion: reduce)` 시 모션 사실상 정지. transform/opacity 만 애니메이션.

## 8. 데이터 (구현 참고 — 디자인 시 데이터 형태 파악용)

각 화면 loader 가 반환하는 데이터. 디자이너는 아래 필드로 채워질 자리에 **현실적인 mock 값**을 넣어 디자인하면 된다. 실제 연동·정렬·필터는 코딩 단계에서 처리하며 **로직은 고정**이다.

**오답노트** — `{ items, oxItems, subject }`
- `items` (객관식 오답): 각 항목 = `problemId · lawCode · primaryArticleLabel? · year? · problemNumber? · attempts · bodySnippet`
- `oxItems` (정오문제 오답): 각 항목 = `refType · refId · lawCode · articleNumber? · problemId · primaryArticleLabel? · year? · problemNumber? · attempts · bodySnippet · myAnswer(O/X) · oxTruth(O/X)`
- `subject`: 현재 과목 필터 (`null` = 전체)

**즐겨찾기** — `{ items, counts, filters }`
- `items` = `BookmarkListItem[]`: `bookmarkId · targetType · targetId · starLevel(1~5) · notePreview? · updatedAt · lawCode? · primaryLabel · secondaryLabel? · bodySnippet? · href · oxTruth(O/X|null)` — 정렬: 별점 desc → 최근수정 desc
- `counts`: `{ total, article, case, problem, ox }` / `filters`: `{ subject, type, minStar }`

**메모** — `{ items, counts, filters }`
- `items` = `MemoListItem[]`: `memoId · targetType · targetId · bodyMd · snippet? · createdAt · updatedAt · lawCode? · primaryLabel · secondaryLabel? · bodySnippet? · href` — 정렬: 최근수정 desc
- `counts`: `{ total, article, case, problem, ox }` / `filters`: `{ subject, type, q }`

**하이라이트** — `{ items, counts, filters }`
- `items` = `HighlightListItem[]`: `highlightId · targetType · targetId · color(green|yellow|red|blue) · excerpt · fieldPath · createdAt · lawCode? · primaryLabel · secondaryLabel? · bodySnippet? · href` — 정렬: 최근작성 desc
- `counts`: `{ total, green, yellow, red, blue }` / `filters`: `{ subject, type, color, q }`

> `targetType` 5종: `article` · `case` · `problem` · `problem_choice`(OX 지문) · `problem_box_item`(OX 박스). 화면 UI 에서는 뒤 두 개를 묶어 **"OX"** 로 표기한다.

## 9. 절대 수정 금지 / Out of scope

- ❌ 네비게이션 "학습보조" 메뉴의 라벨·링크, `navigation-bar.tsx` / `footer.tsx`.
- ❌ 라우트 추가·변경 — 4개 화면(`/study/wrong-note`·`/bookmarks`·`/notes`·`/highlights`) 고정. 학습보조 hub 같은 새 화면 신설 금지.
- ❌ DB 스키마 · loader 쿼리 로직 — 정렬 기준, 필터 의미, soft-delete(`deleted_at`) 규칙 그대로. 본 작업은 시각 디자인.
- ❌ viewer 안의 annotation **작성** UI — `BookmarkStars` · `MemoList` · `HighlightList` · `HighlightToolbar`(우측 패널/본문) 는 **학습과목 brief** 소관. 학습보조는 *모아보기*만.
- ❌ annotation **삭제** 기능 신설 — 현재 학습보조 화면에 삭제 UI 없음(삭제는 원문 viewer 에서). 추가하지 말 것.
- ❌ 화면별 정보·기능의 추가/삭제 — 재배치·시각 개선·정리는 OK, 새 데이터가 필요한 위젯 신설은 범위 밖.
- ❌ 기존 `data-testid` 속성 제거·변경 — E2E(Playwright) 의존(`wrong-start-study/exam`, `bookmark-start-study/exam`, `bookmarks-list`, `notes-list`, `highlights-list`, `ox-wrong-section` 등). 마크업이 바뀌어도 동일 testid 유지.
- ❌ shadcn 기본 톤 잔존 — 디자인 시스템 블루로 통일.

## 10. 기술 제약 (코딩 단계 참고)

실제 구현은 React Router 7 (SSR) + TypeScript strict + Tailwind v4 + shadcn(New York) + lucide-react + Cloudflare Workers.

- 신규 npm 패키지·이미지/폰트 자산 도입 금지 (Pretendard·lucide 는 이미 있음). 외부 폰트 CDN·외부 스크립트 금지.
- Cloudflare Workers 비호환 API(`fs`, Node `crypto.randomBytes`, `setImmediate` 등) 사용 금지.
- 학습과목 영역과 같은 구현 방식 — **Tailwind 유틸리티 클래스** 기반, 블루는 디자인 시스템 토큰/arbitrary value 로. (대시보드·랜딩의 inline-style 토큰 방식이 아님.)
- **다크 모드 지원** — 현 화면들이 이미 light/dark 둘 다 렌더. 디자인 시 두 모드 모두 제공.
- 모바일 반응형 필수 — 필터 바 wrap, 탭 strip 가로 스크롤, 카드 1열 유지.
- 파일 길이 목표 300줄 — 현재 4개 화면이 278~344줄로 한계 근처다. **§5 공통 셸을 컴포넌트로 추출**(`app/features/study/components/` 아래 셸·탭 strip·필터 바·카드·빈 상태)해 각 화면 entry 를 가볍게 분할할 것.
- 컴포넌트는 표시 + 이벤트 연결만, 계산 로직은 `lib/`. `console.log` 잔류 금지. `any` / `@ts-ignore` 금지.
- 접근성(WCAG AA): 탭 strip 은 `<Link>`, 필터는 `<button>`, 카드 전체 링크는 `<Link>`(클릭 가능 div 금지). 색상 필터·하이라이트 색은 색 + 텍스트 라벨 병기(색만으로 구분 금지). 카운트 count-up 은 sr-only 최종값 또는 `aria-hidden` 처리.

## 11. 우선순위 — 디자이너가 시간을 어디에 쓸지

1. **공통 셸 1벌** (§5) — 페이지 셸 · 학습보조 탭 strip · 화면 헤더 · 필터 바 · 결과 카드 · 빈 상태. 네 화면이 공유하므로 가장 공들일 부분.
2. **즐겨찾기 · 메모** — 정보 밀도가 가장 높음. 카드 패턴 1~2개를 여기서 확정.
3. **오답노트** — 2섹션 구조 + 세션 CTA + OX 오답 카드(내 답 vs 정답).
4. **하이라이트** — 4색 색칠 발췌 카드.
5. **빈 상태 4종 + 로딩 스켈레톤** — 0건 / 필터 0건 카피 구분.
