# 모의고사 "+문제집 추가" 고도화 (A picker UX + B 소스확장)

> 설계 문서(코드 0). 선행 점검: `docs/survey/모의고사-문제집추가-점검.md`.
> A(picker UX)와 B(소스 확장)는 **같은 picker**를 건드리므로 함께 설계. 작성 2026-06-22.
> SPEC ID는 그린라이트 시 부여(잠정 feat-10-006 — feat-10 모의고사 시리즈 연장).

## 0. 요약 · 핵심 결정

- **이번 범위 = 강사 출제 도구 강화.** 학생 노출 0. staff 3겹 보안(canEdit→action 403→RLS is_staff)·PK 멱등·approved 게이트 **전부 유지**.
- A·B는 **대부분 배선**이다. 노드→문제(`getSystematicNodeProblemSequence`), 난이도(`getProblemStatsBulk`), 쓰기(`addPackProblems`)가 이미 존재. **DB 스키마 변경 불필요.**
- **B의 "반 공통 약점"만 신규 집계가 필요**(노드 단위 멀티유저 약점은 전 코드베이스에 없음). 멤버·권한·페이징 인프라(`listCohortProgressSummary` 패턴)와 약점 공식(`weak-nodes.server.ts`)을 재사용.
- **코호트는 "약점 계산 입력"일 뿐, 팩 가시성 스코프가 아니다.** 생성된 팩은 기존대로 전역(`is_published`+과목 구독). → `mcq_packs`에 `cohort_id` 안 붙임(스키마 무변경).
- **선택 규칙(노드/난이도→문제 N개)을 pack-write와 분리한 순수 모듈**로 만들어, 나중 D(학생 셀프 개인약점→quiz_session)가 같은 규칙을 재사용. **단 D는 지금 만들지 않고 seam만 남긴다.**

## 1. ① 반 공통 약점 데이터 계획 (선결)

### 1.1 현황 (확인 완료 · 사실)

| 항목 | 상태 |
|---|---|
| 개인 약점 노드 `getWeakNodes(client, userId, lawCodes[], limit)` | 존재. **단일 userId 전용**(`buildNodeProgressByArticle`이 `.eq("user_id", userId)`). 반환 `WeakNodeItem[]` |
| 개인 OX 약점 `computeOxDiagnosis(client, userId, …)` | 존재. 단일 userId. **순수부 `buildOxDiagnosis(rows, meta, opts)` 분리됨**(멀티유저 유리) |
| 약점 공식 | `(100 - accuracyPct) × log10(attempts+1)`, `MIN_ATTEMPTS_FOR_RANKING=5` (`weak-nodes.server.ts:27,78-80`) — **순수, 재사용 가능** |
| 코호트 멤버·권한·페이징 | **풍부하게 존재**: `listCohortProgressSummary(client, cohortId)` 외 6종(`admin/queries/student-progress.server.ts` 등). 패턴 = `cohort_members→profileIds→.in("user_id", profileIds)` + adminClient + loader 게이트(`owner_id` 체크) |
| **노드 단위 반 약점 집계** | **없음**(기존 코호트 집계는 과목 단위 정답률까지만, 단원으로 안 쪼갬) |
| 출제 맥락 코호트 선택 | **없음**(mcq_packs에 cohort_id 없음, PackForm에 반 선택 없음) |

코호트 모델(사실): `cohorts(cohort_id, name, owner_id→profiles, …)` + `cohort_members(cohort_id, profile_id→학생, …)`. **강사-반 연결 = `cohorts.owner_id`**(한 강사가 여러 반 소유). 강사 자기 반 = `listCohorts({ownerId: user.id})`. 타 학생 데이터는 profiles RLS 때문에 **adminClient 필수**(기존 코호트 화면이 이미 그렇게 함).

### 1.2 결정 — (C)+(B) 혼합

> **(A) `getWeakNodes` 멀티유저 일반화** = 불가(단일 userId 가정으로 짜임).
> **(C) 코호트 인프라 재사용 + (B) 노드 약점 멀티유저 집계 신규** = 채택.

**신규 함수**(서버, adminClient): `getCohortWeakNodes(client, cohortId, lawCodes[], opts)` → `WeakNodeItem[]` (**개인용과 동일 반환 shape** — seam 핵심).

집계 방식:
1. `cohort_members` → `profileIds`(기존 패턴 재사용).
2. `user_problem_attempts`를 `.in("user_id", profileIds)` + (해당 과목 problem_id 한정) 일괄 조회(페이징, `listCohortProgressSummary:71-91` 템플릿).
3. 문제→노드 귀속: `primary_node_id` 직접 + `primary_article_id→article_systematic_links` subtree(=`computeOxDiagnosis`/노드 추출 함수가 쓰는 정석 경로).
4. 노드별로 attempts/correct **풀링 합산** → 동일 공식 `(100-acc)×log10(attempts+1)` 적용.
5. **"공통" 가드**(개인 약점과의 차별점 · 결정): 노드가 약점으로 잡히려면 (a) 누적 시도 ≥ MIN(=5), **그리고** (b) **그 노드를 시도(≥1)한 서로 다른 학생 ≥ 코호트의 35%**(기본값, 강사 설정 20~50%) — 반 크기 무관 **비율 기준**. 초소형 반 노이즈 방지 **하드 플로어 ≥ 3명**(비율 환산이 3명 미만이면 그 노드 제외). "한 명이 많이 틀림"을 반 공통 약점으로 오인 방지. (분모 = 코호트 전체 멤버 기본; 학기 초 과엄격하면 강사가 % 하향 — 구현 시 active 멤버 분모 옵션 검토.)
6. weaknessScore 내림차순 top N.

**스키마 변경 없음** — 런타임 집계(기존 코호트 집계도 전부 런타임). 추후 성능 이슈 시 SQL RPC로 승격 가능(현재는 불필요).

### 1.3 출제 맥락의 코호트 진입점 (신규, 경량)

- 강사가 "반 공통 약점 단원 N문항" 버튼을 누르면 **자기 소유 반 선택**(드롭다운, `listCohorts({ownerId})`). manager/admin은 전체 반.
- 권한: 약점 조회는 adminClient지만 **action에서 `cohort.ownerId === user.id || roleAtLeast(role,"manager")` 게이트**(기존 코호트 진척 화면과 동일 방어). 학생 접근 0.
- 이 코호트 선택은 **약점 계산 입력**일 뿐 — 생성 팩은 전역 그대로(가시성 무변경).

## 2. ② A — picker UX 설계

대상: `MockPackProblemPicker`(`app/features/mcq-packs/components/mock-pack-problem-picker.tsx`) + `search-content.tsx`(kind=problem). 현재 필터 = 출처/형식/연도뿐, 미리보기·중복배지 없음.

### 2.1 단원(node) 필터 — 신규(배선)
- search-content에 `nodeId` 파라미터 추가 → 내부에서 node subtree(path prefix)→article/problem 해소 후 `primary_node_id ∈ subtree OR primary_article_id ∈ subtreeArticles` 필터. (subtree 해소 로직은 `getSystematicNodeProblemSequence`가 쓰는 패턴 재사용.)
- picker에 **단원 셀렉터**(과목의 systematic 트리/리스트). 키워드·출처·형식·연도와 **교집합**.
- 대안: 단원만 고르면 검색 대신 `getSystematicNodeProblemSequence(nodeId)`로 그 노드 문제를 바로 나열(키워드 불필요). → 출제자가 "이 단원 전체"를 빠르게 훑기 좋음.

### 2.2 난이도 · 중요도 필터 — 신규
- **중요도**(쉬움): search-content에 `importance` 파라미터(`problems.importance ≥ n`). 컬럼 존재, 필터만 추가.
- **난이도**(주의): precomputed 컬럼 없음. 전체 풀 랭킹 RPC도 없음 → **현재 결과 집합을 `getProblemStatsBulk`로 보강해 정답률 기준 정렬/필터**(난이도 = 정렬 옵션). 시도<5 문제는 bucket=null(난이도 미산정)이라 "정답률 낮은 순"엔 신작/mock이 빠지고 기출 위주로 쏠릴 수 있음(한계 명시).

### 2.3 미리보기 — 신규
- search-content 반환에 **더 긴 본문**(또는 `body_md` 전체 + 선지 수) 추가. 현재는 80자 snippet만.
- picker 결과 행에 **펼침 토글**(발문 전체 + 선지 텍스트). 무거운 ProblemDetail 전체는 지양(목록 성능).

### 2.4 중복 배지 — 거의 배선만
- `mcq-pack-detail` loader는 이미 현재 팩의 `problems`(problemId 포함) 보유 → picker에 `existingIds={new Set(problems.map(p=>p.problemId))}` **prop 전달**.
- 결과 행에 `id ∈ existingIds`면 "이미 포함" 배지 + 추가 비활성(또는 회색). 같은 팩 중복은 이걸로 해결(서버는 여전히 멱등 skip로 2차 방어).
- cross-pack("다른 팩에 이미 있음")은 신규 역조회 쿼리 필요 → **후순위/선택**.

### 2.5 기타
- limit 20 → 상향 + 페이지네이션(소스 버튼이 후보를 많이 채울 때 필요).

## 3. ③ B — 소스 확장 버튼 + 뮤테이션 연결

picker 헤더에 staff 전용 버튼 2개. **둘 다 "후보를 채워주고", 최종 추가는 기존 통로(`addPackProblems`)** — 멱등·PK·approved 그대로.

### 3.1 "반 공통 약점 단원 N문항"
흐름:
1. 반 선택(§1.3) → `getCohortWeakNodes(cohortId, [packLawCode])` → top weak nodes.
2. 각 weak node → `getSystematicNodeProblemSequence(nodeId)`로 후보 problem_id 수집.
3. **선택 규칙**(§4 순수 함수)으로 N개 샘플 — **weaknessScore 가중 배분**(약한 단원에 더 집중), 단 **한 단원 상한 = `ceil(N × 0.4)`**(쏠림 방지) + 선정된 각 weak node 최소 1문항(가능 시). 같은 노드 내 문제 순서는 구현 시(최신 기출 우선 또는 무작위).
4. 후보를 picker의 선택 목록/미리보기에 **채움**(자동 커밋 아님) → 강사가 검토·가감 → "추가".
5. `intent=add_problems` → `addPackProblems` (멱등·approved).

### 3.2 "난이도 상위 N" (정답률 낮은 순)
흐름:
1. 후보 풀 확보(과목 또는 현재 필터 범위의 approved 문제 id 집합). **풀이 크면 범위 한정 필요**(전체 풀 랭킹 RPC 없음 — 한계).
2. `getProblemStatsBulk(ids)` → `accuracyPct` 오름차순, `attempts≥5` 필터 → top N.
3. 후보 채움 → 검토 → 추가(동일 통로).

### 3.3 공통 원칙
- 버튼은 **picker `selected`/후보 미리보기에 주입**만. 쓰기는 단일 통로(`addPackProblems`) → 일관성·중복방지·승인검증 유지.
- 200개 초과 시 분할(`add_problems`는 `z.array(uuid).max(200)`).
- 결과 통지: `{added, skipped, skippedUnapproved}` 노출(현재 picker는 skippedUnapproved 미표시 → 보강).

## 4. ④ 재사용 가능한 선택 로직 seam (D 대비)

**3-레이어 분리** — 가운데(선택 규칙)만 순수·공유, 위/아래는 교체 가능:

```
[소스 레이어]            [선택 규칙: 순수·공유]                 [싱크 레이어]
getCohortWeakNodes  ─┐                                      ┌─ addPackProblems       (B, 지금)
 (B: 반 약점)         ├─▶ pickProblemsFromWeakNodes(        ─┤   = pack write
getWeakNodes        ─┘     weakNodes, resolver, {N,weight})  └─ createQuizSession     (D, 나중)
 (D: 개인 약점)            → problem_id[]                        = quiz_session
                          pickProblemsByDifficulty(
                            candidateIds, statsMap, {topN})
                          → problem_id[]
```

- **신규 모듈**(예: `app/features/mcq-packs/lib/problem-source.ts` 또는 공용 `app/features/study/lib/problem-selection.ts`): `pickProblemsFromWeakNodes` / `pickProblemsByDifficulty` — **DB·pack·session 무지의 순수 함수**. 입력 = weakNodes(또는 candidateIds)+resolver/stats+config, 출력 = `problem_id[]`.
- 소스 레이어가 **동일 `WeakNodeItem[]` shape**를 반환하므로(개인=`getWeakNodes`, 반=`getCohortWeakNodes`) 선택 규칙은 양쪽에 그대로 동작.
- **D 대비 seam만 남긴다**: 선택 모듈이 `addPackProblems`를 import하지 않게(싱크 비의존), 약점 소스를 `cohortId`가 아니라 `weakNodes[]`로 받게 한다. → 나중 D는 `getWeakNodes(studentId)` + 같은 선택 규칙 + `createQuizSession`만 조립하면 됨. **D 자체는 이번에 구현하지 않음.**

## 5. ⑤ 단계안 + 규모

| 단계 | 내용 | 규모 | 위험/적합성 | 신규 vs 배선 |
|---|---|---|---|---|
| **1. picker 즉효 UX** | 중복 배지(existingIds prop), 발문 미리보기(긴 본문+펼침) | **S** | 매우 낮음·높음 | 거의 배선 |
| **2. picker 필터 확장** | 단원(node) 필터, 중요도 필터, 난이도 정렬(getProblemStatsBulk 보강), limit 상향/페이징 | **S~M** | 낮음·높음 | search-content/picker 배선 |
| **3. 선택 규칙 seam + 난이도 소스** | 순수 선택 모듈(`pickProblemsByDifficulty`/`…FromWeakNodes`) + "난이도 상위 N" 버튼 | **M** | 중·높음(코호트 불요) | 신규 순수모듈 + 배선 |
| **4. 반 공통 약점 소스** | `getCohortWeakNodes` 집계(신규), 코호트 셀렉터, "반 공통 약점 N문항" 버튼 | **M** | 중(신규 집계·권한) | 핵심 신규 |
| (D, 차후) | 학생 셀프: `getWeakNodes(개인)`+선택규칙+`createQuizSession` | — | 별 태스크 | seam 재사용 |

순서 근거: 1·2는 순수 UX·저위험 → 먼저 출하. 3(난이도)은 코호트 불요라 약점보다 먼저, 선택 seam을 여기서 확립 → 4가 그 seam 재사용. 4(반 약점)가 유일한 신규 집계 + 코호트 권한이라 마지막.

각 단계 독립 출하 가능(점증). 단계 사이 하드스톱·검토 권장.

## 6. 보존 / 권한 (불변)

- **staff 3겹**: 새 버튼·셀렉터는 `canEdit`에서만 렌더. 새 action(약점/난이도 소스)도 `getStaffRole` 403 게이트. mcq_pack 뮤테이션 RLS(`is_staff`) 경유 유지.
- **코호트 약점 조회**: profiles RLS상 cross-read 불가 → **adminClient + action 게이트(`cohort.ownerId===user.id || manager+`)**. 이 게이트가 유일 방어선이므로 필수(메모 `profiles-rls-staff-cross-read`·기존 코호트 화면 패턴 준수).
- **학생 노출 0**: 이번 전 기능은 출제 화면(`/latest/mcq*`, `canEdit`) 한정. 학생 경로 무변경.
- **중복·승인**: `addPackProblems` 단일 통로 유지 → PK `(pack_id,problem_id)` 멱등 + `review_status='approved'` 게이트 불변.
- **DB 스키마 변경 0**(런타임 집계). 마이그레이션 불요.

## 7. 결정 (확정 · 2026-06-22)

1. **"반 공통" 임계 = 비율 기반.** 노드를 시도한 서로 다른 학생 ≥ **코호트의 35%**(기본) — 반 크기 다양성 감안 비율(인원수 고정 아님). **강사 설정 가능(20~50%)**. 초소형 반 노이즈 방지 **하드 플로어 ≥ 3명**. 풀링 정답률 + 누적 시도 MIN=5 병행.
   - 제안 근거: 변리사 학원 반 규모(대략 10~40명 추정)에서 35%면 4~14명 — "공통"이라 부를 최소선이면서 작은 반도 동작. 5~8명 반은 플로어 3명이 실질 기준.
2. **N 배분 = weaknessScore 가중** + **한 단원 상한 `ceil(N×0.4)`** + 선정 노드별 최소 1문항.
3. **난이도 후보 풀 범위 = 구현 시 결정**(`getProblemStatsBulk` 정답률 기준, 후보 ID 집합 한정으로 충분).
4. **미리보기 채택** — 소스 버튼은 후보 목록만 채우고 강사가 확인·가감 후 추가(출제 책임 = 강사).
5. cross-pack 중복 배지 = **후순위**(이번 범위 제외).
