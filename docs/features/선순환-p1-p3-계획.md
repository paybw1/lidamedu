# 선순환 P1~P3 계획 — 강의 카탈로그 · 회차↔노드 매핑 · 문제 태깅

> 배경: Phase 0 감사가 확정한 3대 선결 공백을 채우는 계획. P4(개인 약점 엣지 정렬)는 완료(배포 검증 완료). 이 문서는 **계획만** — 착수 승인 후 각 트랙을 dry-run/하드스톱 게이트로 진행.
> 선행 문서: `선순환-phase0-노드정합성-감사.md`, `선순환-p4-개인약점엣지정렬.md`.
> 작성일: 2026-07-15. 현황 수치·경로는 운영 DB(mcgdoplo) 실측 + 코드 정독(file:line).

## 0. 한눈에 — 무엇이 무엇을 여는가

| 트랙 | 목표 | Phase 1(강의→복습) 관계 | 독립성 |
|---|---|---|---|
| **P1 강의 카탈로그** | 파일럿(특허법) 실제 VOD 회차 적재 | **필수 입력**(시딩할 강의 소스) | 콘텐츠-운영 의존 |
| **P2 회차↔노드 매핑** | `lesson_node_links` 적재 UI + 데이터 | **필수 브리지**(강의→노드) | 코드는 지금 가능, 데이터는 P1 후 |
| **P3 문제 태깅** | 상표·디자인 past_exam 576건 노드 귀속 | 파일럿엔 불필요, **루프 확장**에 필수 | P1/P2와 무관·병렬 |

- **트랙 A(파일럿)** = P1 → P2. 특허 하나로 "강의 보면 그 단원 복습 큐가 채워진다"를 검증.
- **트랙 B(확장)** = P3. 상표·디자인이 약점/마스터리/OX/모의 노드 신호를 **처음** 갖게 함(현재 0%).
- 두 트랙은 병렬. Phase 1 배선(강의→복습 시딩)은 트랙 A 완료 후 별도 태스크.

## P1 — 강의(VOD) 카탈로그 (파일럿 = 특허법)

### 현황 (실측)
- **관리 UI 완비**: 시리즈·에디션 = `/admin/lms/courses`(`admin-lms-courses.tsx`), 회차·영상 = `/admin/lms/courses/:courseId`(`admin-lms-course-detail.tsx`). 모두 `lms_video_admin` duty 게이트 + RLS 요청클라이언트.
  - 시리즈 생성(`create_series`, subject_code=patent 선택 가능) → 에디션 생성(`create_edition`) → 회차 추가(`add_lesson`) → Kollus 영상 부착(`set_video`: drm_video_id=mckey + duration 수기 입력).
- **콘텐츠는 테스트뿐**: `course_lessons` 4건(= `seed-kollus-test-course.mjs` 산출). 실제 특허 강의 없음.

### 성격 — 주로 콘텐츠-운영, 코드 거의 불필요
- 실제 특허 강의 **영상 확보 + Kollus 업로드 + mckey/duration 확보**가 본체(비즈니스 선행). 그 뒤 **staff가 UI로 회차 등록**하면 끝.
- ★게이트: **실제 특허 VOD가 존재해야 P1 착수 가능.** 없으면 P1은 대기, P2 코드/P3부터 진행.

### 코드 보강 (선택·소규모)
- **시리즈/에디션 edit 액션 부재**: 현재 `create_*`는 insert-only, 제목·subject_code·강사·연도 **수정/소프트삭제 UI 없음**(`admin-lms-courses.tsx:101-184`). 오타·정정 대비 edit 액션 추가 권고(작음). `add_lesson`·`set_video`·회차 toggle/reorder는 완비 → 불필요.
- Kollus mckey **수기 입력**(브라우즈/업로드 연동 없음) — 현 단계 수용(운영자가 Kollus 콘솔서 복사). 자동화는 후순위.

### 산출물
- 특허법 시리즈 1 + 현행 에디션 1 + 실제 회차 N(각 mckey·duration). `is_current=true` 발행.

## P2 — 회차↔노드 매핑 UI (`lesson_node_links` 적재)

### 현황
- 테이블 `lesson_node_links(lesson_id, node_id)` + RLS(`lesson_node_links_write_staff`/`_select_all`, `20260708_lms_m2_tables.sql:242,260`) **완비, 0행, 쓰기 경로 없음**.
- `getCourseDetail`가 이미 `nodeIds`를 회차별로 **읽음**(`lms/queries.server.ts:196,235`)지만 화면에서 **미표시**. `subjectCode`도 이미 CourseDetail에 있음(`:206`).

### 설계 (구체·최소 변경)
- **붙일 곳**: `admin-lms-course-detail.tsx`의 `LessonCard`(`:524-714`) — 이미 `set_video`/`materials`/`memo` 회차별 폼이 쌓인 곳. 여기 **회차별 노드 매핑 섹션** 추가.
- **loader 보강**: 코스 상세 로더에서 `getSystematicSkeleton(client, course.subjectCode)`(`laws/queries.server.ts:444`) 호출 → caseOnly 제외 + 조상 크럼 라벨(문제편집기 `admin-problem-edit.tsx:249-265` 패턴 복사)로 선택지 공급.
- **action 신설**: `set_lesson_nodes` — RLS 요청클라이언트로 `lesson_node_links`를 **회차 기준 재설정**(delete by lesson_id → insert 선택 노드들). 다대다.
- **표시**: `LessonCard`에 `lesson.nodeIds` 칩 렌더(현재 미표시분 노출).
- **picker**: `lesson_node_links`는 **다대다** → 문제편집기의 단일 `FormSelect` 재사용 **불가**. `getSystematicSkeleton` + 크럼 빌더만 재사용하고 **멀티셀렉트(체크박스/칩)** 자작.
- **마이그레이션 없음**(테이블·RLS 존재).

### 진행·검증
- 코드는 **지금 착수 가능**(테스트 강좌로 UI 검증). 실제 매핑 데이터 입력은 **P1 후**(특허 실제 회차에 노드 지정).
- 규모: 소~중(1로더 보강 + 1액션 + LessonCard UI). frozen 원칙: 신규 뮤테이션 1개(`set_lesson_nodes`)만.

### ✅ 구현 완료 (2026-07-15) — `admin-lms-course-detail.tsx`
- loader: `getSystematicSkeleton(subjectCode)` → `nodeOptions`(caseOnly 제외 + 조상 크럼 라벨). 법률 과목 아니면 빈 목록.
- action `set_lesson_nodes`: 회차∈에디션 확인 + 제출 노드를 **에디션 과목 노드로 필터**(교차 과목 오염 차단) → `lesson_node_links` delete+insert(회차 기준 재설정, RLS 요청클라이언트). 마이그레이션 없음.
- UI: `LessonCard`에 `LessonNodesSection` — 현재 매핑 칩(제거) + 검색형 체크박스 멀티셀렉트 + 변경 시 저장/되돌리기.
- 검증: typecheck ✅ · build ✅ · RLS `lesson_node_links_write_staff`(staff insert/delete) 확인 ✅. 실데이터 입력은 P1(특허 실제 회차) 후.

## P3 — 문제→노드 태깅 (상표·디자인 past_exam 576건)

### 현황 (실측)
- 상표 296 · 디자인 280 활성 문제 = **전량 `past_exam`(기출)**, **primary_node_id NULL + primary_article_id NULL**(노드·조문 앵커 둘 다 없음).
- 단, 각 문제 **year + problemNumber + source_doc_id 보유** → 특정 가능. **워크북 section 메타는 없음**(patent은 `source/_converted/*-merged.json`에 `section` 필드로 워크북 단원이 있었으나, `tm-design-merged.json`은 section 0/448 — patent 파이프라인 직접 재사용 불가).
- 타깃 노드 존재: 상표 156 · 디자인 150(non-case-only). **조문→노드 링크 양호**: 상표 244/258 · 디자인 222/249 조문이 노드-링크됨.

### 접근 — `ox-article-matching` 패턴 계승(3단계)
1. **명시 인용 백필(싸고 권위 있음)**: stem/explanation에서 **명시 조문 인용**(예: "상표법 제33조") 파서 추출 → `primary_article_id` 세팅. 조문 링크가 양호하므로 **상당수가 P4 폴백(핀 없으면 조문→노드)으로 즉시 노드 도달**. dry-run 대조 후 적용(백업).
2. **AI 후보 + 자기검증**: 인용 없는 잔여 → AI가 stem+선지+해설로 상표/디자인 skeleton 라벨 중 `primary_node_id` 후보 제안 + 검증(Anthropic 구조화출력, `anthropic-structured-output-schema-limits` 제약 준수).
3. **운영자 승인 큐**: 기존 `/admin/problems` 미매칭 큐 확장(ox-article-matching의 '조문 미매칭' 큐 형태) — staff가 후보 **승인·수정** → `primary_node_id` 확정. **승인 전 자동 노출 금지**.

### 도구·안전
- 적용은 **`apply-wb-node.mjs` 형태 재사용**(worklist `[{problemId, current, target}]` + backup + `--apply` 게이트). worklist 생성원만 워크북 section이 아니라 **인용파서/AI 후보**로 교체.
- 마이그레이션 없음(기존 컬럼). 대량 변경 = dry-run + 사용자 승인(Non-negotiable §8).
- ★감사 오탐 주의(`patent-workbook-missing-backfill` 교훈): 파싱 잔재·다중행·연도오라벨 → DB 핵심문구 대조 후 allow-list.

### 규모·독립성
- 중(인용 파서 + AI 배치 + 승인 큐 화면). 상표·디자인 각각. P1/P2와 **무관·병렬**.
- 완료 시 상표·디자인이 약점/마스터리/OX/모의 노드 신호를 **처음 획득**(현재 0% → 도달).

## 순서·의존성 요약

```
트랙 A (특허 파일럿):   P1(콘텐츠) ──▶ P2(매핑 데이터 입력)
                         P2(코드) ─┘ (지금 가능, 테스트강좌 검증)
트랙 B (확장):          P3(상표·디자인 태깅)  ── 병렬, 독립
                                    │
Phase 1 배선(강의→복습) ◀──────────── 트랙 A 완료 후 (별도 태스크)
```

### 권고 착수 순서
1. **P2 코드 먼저** — 지금 가능, 위험 낮음, Phase 1 핵심 인프라. 테스트 강좌로 검증까지.
2. **P3 병렬 시작** — Step 1 인용 백필(빠른 이득)부터 → AI 후보 → 승인 큐.
3. **P1 콘텐츠** — 실제 특허 강의 확보되는 대로. 확보 전엔 P2를 테스트강좌로 검증만 하고 대기.

### 각 P의 하드스톱 게이트
- P1: 실제 VOD 존재 확인 → 없으면 대기.
- P2: 테스트강좌 UI 동작 확인 → 특허 실제 회차 매핑 입력(P1 후).
- P3: 각 단계 dry-run 대조 + 승인 후 적용, 대량 변경 백업 필수.
