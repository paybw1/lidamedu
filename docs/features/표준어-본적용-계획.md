## 1. SSOT 거점 지도 (클러스터 → 파일)

| 클러스터 | 표준값(§4-0) | SSOT 상수 | 거점 밖 하드코딩(학생 대면) |
|---|---|---|---|
| 정오문제 | "정오문제" | ✅ `problems/labels.ts` `FORMAT_LABEL.ox` | **작업 없음**(이미 통일). "맞으면 O/틀리면 X" 도입문구는 §설명갭(별개) |
| 단원/종합 | "단원"/"종합" | ✅ `SCOPE_LABEL` | "범위"(`subjects/quiz-setup`) 등 소수 → 단원/종합 |
| 출처/유형/지식종류 | 기출·모의 등 | ✅ `ORIGIN_LABEL`·`FORMAT_LABEL`·`CHOICE_TYPE_LABEL` | 대체로 SSOT 경유. 일부 raw enum 노출(`origin=mock`)만 |
| **문제집(팩)** | "문제집"·**"팩" 폐기** | ❌ **없음** — kind만 SSOT(`MCQ_PACK_KIND_LABELS`=기출문제/전체 모의고사/진도별 모의고사). 묶음 총칭어는 화면 하드코딩 | **"팩" 83곳/25파일**(학생 대면 ≈48곳/8화면: mcq·mcq-pack-detail·mcq-pack-ox-exam·my-ox-sessions·mcq-pack-result·mcq-pack-sheet·dash-ox) |
| **회차 3분할** | 회차/시도/풀이 | ⚠️ `examRoundNo`는 **데이터**(불변), 라벨은 화면 하드코딩 | **"회차" 160곳/47파일** — 동음이의 분류 필요(다수 GS는 공식회차=유지) |
| **학생** | "학생" | ❌ 없음 | **"수험생" 22곳/15파일**(학생 대면 지칭 ≈10-12, 나머지 admin·코드주석·"수험생·강사" 쌍) |
| **문항** | "문항"(단위·카운터) | ❌ 없음 | **"문항" 118곳/37파일 — 대부분 이미 표준.** 잔여 = 단위로 쓰인 "문제" → 문항(규칙 확정 필요) |

**핵심 발견**: ① pack **묶음 총칭어**("문제집")와 MCQ **단위어**("문항")는 **SSOT 상수가 없다** → 거점 한 방 전파 불가, 화면별 작업. ② kind/scope/format/choice_type 라벨은 SSOT라 이미 일관(거의 손댈 것 없음). ③ 따라서 "거점 먼저"가 효과적인 건 §단원/종합(SCOPE_LABEL 확인)뿐이고, 나머지는 **화면별 + 분류**가 본체.

## 2. 단계 계획 (위험 낮은 → 높은)

각 단계 = 독립 커밋(1개념), typecheck, 텍스트 변경이라 라이트/다크 무관, 단계별 커밋 후 **일괄 푸시**.

| 단계 | 클러스터 | 위험 | 규모 | 비고 |
|---|---|---|---|---|
| **S1** | ★**문체 — 위험동작 confirm 격상** | 낮음(소수·고가치) | ~3-5곳 | **사용자 보호 최우선**. §5 참조 |
| **S2** | 학생(수험생→학생) | 낮음 | ~10-12곳 | 지칭만. "수험생·강사" 쌍·RLS 설명문 보존 검토 |
| **S3** | 단원/종합("범위"→) | 낮음 | 소수 | SCOPE_LABEL 이미 표준 → 거점 밖 "범위" 라벨만 |
| **S4** | 문제집(팩→문제집) | **중**(맥락 의존) | ~48곳/8화면 | 화면별. "기출 팩"→"기출 문제집" 등 자연스러움 확인. §3 DB 불변 |
| **S5** | ★**회차 3분할** | **고**(동음이의) | 분류 후 결정 | **분류표 먼저 → 검토 → 적용**. §4 참조. 일괄치환 금지 |
| **S6** | 문항(단위 "문제"→문항) | 고(churn·저명확) | 규칙 의존 | **규칙 확정 후**. §6 참조. 마지막 |
| (S7+) | §4-1 확장(전체 정답률·강의노트·온라인 GS·강사/운영자 호칭·띄어쓰기) | — | — | 선택적 후속 배치 |

## 3. DB 식별자 불변 경계 (★ 절대 규칙)

**라벨(사용자 노출 문자열)만 바꾼다. DB·코드 식별자는 절대 불변.**

| 불변 (건드리지 않음) | 변경 대상 (라벨만) |
|---|---|
| `mcq_packs` 등 테이블명, `.from('mcq_packs')` | JSX 텍스트 노드 |
| enum 값(`McqPackKind`·`ProblemExamRound`·`problem_exam_round`·`mock`·`past_exam`…) | 라벨 상수 **값**(예: 새 상수 도입 시) |
| `database.types.ts`, 타입명(`McqPackItem`·`ProblemFormat`…) | placeholder·toast·aria-label·title |
| 변수·prop명(`packId`·`examRoundNo`·`sessionId`·`kind`) | 빈 상태/설명 산문 |
| 쿼리·라우트 경로(`/latest/mcq`·`?session=`·`packId` param) | 버튼 라벨 |

- "문제집"·"시도"·"풀이"·"학생"·"문항"·"코멘트"는 **표시어**일 뿐 — DB는 그대로 `mcq_packs`·`examRoundNo`·`quiz_session`.
- 검증: 각 단계 후 `git diff`로 변경이 **문자열 리터럴/JSX 텍스트에 한정**되는지 확인. enum·타입·`.from(`·param 라인이 diff에 있으면 중단.

## 4. 회차 3분할 분류법 (★ S5 — 가장 위험)

"회차"가 **3뜻 동음이의** → 절대 일괄치환 금지. **분류표 산출 → 검토 → 의미별 적용.**

**의미 → 표준어 → 판별 기준:**
| 의미 | 표준어 | 판별 | 예상 사용처 |
|---|---|---|---|
| 공식 시험 회차번호 | **"회차"**(유지) | `examRoundNo` 기반·"제N회"·연도와 함께 | mcq `${examRoundNo}회`, exam-form 입력, **GS 공개 회차**(강사가 개설한 GS 인스턴스) |
| 내 N번째 응시/시도 | **"시도"** | 같은 대상을 반복 푼 횟수 | mcq-pack-result "이번/지난/새 회차", my-ox-sessions 응시 이력 |
| 퀴즈 풀이 세션 | **"풀이"** | `quiz_session` 기반 학습 세션 | subjects/science `quiz-setup` "학습 회차", problem-viewer "오답노트/즐겨찾기/퀴즈 회차" |

**절차(S5)**:
1. 학생 대면 "회차" 사용처 전수(`회차` grep, admin-* 제외) → 각 줄을 위 3태그로 분류한 **분류표(파일:줄 → 의미 → 신규어)** 산출 = 별도 산출물.
2. 사용자 검토(특히 GS "회차"=공식 분류 확인 — GS가 가장 많아 대부분 "유지"라 실변경은 시도/풀이 소수).
3. 의미별로 적용. 한 커밋에 한 의미(시도 커밋 / 풀이 커밋)로 더 쪼갤 수도.
- ★`examRoundNo`·`ProblemExamRound` enum은 §3대로 불변(데이터). "회차"→"시도/풀이"는 그 데이터를 **표시하는 라벨**만.

## 5. 문체 SSOT vs 산문 + 위험동작 우선 (S1)

**SSOT 적용 가능 vs 산문 수정 구분:**
- **정형(패턴 통일)**: `confirm("...")` 다이얼로그 문구, 버튼 라벨. 공용 confirm 헬퍼는 없음(화면별 `window.confirm`) → SSOT는 아니나 **동일 패턴**으로 통일.
- **산문(파일별)**: 빈 상태·설명문의 종결/격식 혼입.

**★S1 — 위험동작 confirm 격상(최우선, 사용자 보호):**
감사 §3-2에서 식별된 **위험↔격식 역전** 교정. 비가역·데이터 손실·제출은 `~하시겠습니까?` + 경고:
| 위치 | 현재 | → |
|---|---|---|
| `latest/mcq.tsx` | "수동 추가 문제는 사라질 수 있습니다. 진행할까요?" | "…사라집니다. 되돌릴 수 없습니다. 계속하시겠습니까?" |
| `latest/my-ox-wrong-note.tsx` | "그대로 제출할까요?"(미응답 포함) | "미응답 N개를 포함해 제출하시겠습니까?" |
| (기타 데이터 손실/제출 confirm 전수 확인) | "~할까요?" | "~하시겠습니까?" (+필요시 경고) |
- 이미 정중한 것(ai-chat "삭제하시겠습니까?")은 유지. 가벼운 토글은 "~할까요?" 허용(역전만 교정).

**문체 그 외(후속, 낮은 우선)**: 해요체 단발 혼입(quiz-result "저장됐어요"→"저장했습니다"), 영어 잔여(이미 A5/A6서 대부분 해소), 이모지·전문어 풀이 — 점진. S1만 우선 게이트, 나머지는 클러스터 작업에 묻어가거나 별도.

## 6. 문항 클러스터 — 규칙 확정 필요 (S6, 마지막)

- "문항" 118곳은 **대부분 이미 표준**(GS·quiz 카운터). 문제는 **MCQ 단위로 쓰인 "문제"**가 섞인 것.
- ★"문제"는 일반 개념어로 광범위(이 문제·문제 풀이·다음 문제·문제 목록) — **전수 "문항" 치환은 부자연**("다음 문항"·"문항 풀기"는 어색).
- **제안 규칙(확정 필요)**: **카운터·단위 라벨만** "문항"으로 — "총 N문항"·"문항 수"·"틀린 문항"·"오답 N문항". **개념·내비게이션 "문제"는 유지** — "다음 문제"·"문제 목록"·"이 문제"·"문제 풀이". 카운터 단위도 "개/건/문항" 혼용 → "문항"으로 통일.
- 이 규칙을 승인받은 뒤에야 S6 착수(규칙 없이는 범위 모호).
