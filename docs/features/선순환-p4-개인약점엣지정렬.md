# 선순환 P4 — 개인 약점 노드 귀속 엣지 정렬 (Stage A: 점검·영향분석·설계)

> 목적: 문제→노드 귀속 규칙이 **개인 약점만** 달라서(조문 경로 전용) 생기는 살아있는 오차를, 코호트/마스터리/OX와 동일한 **`primary_node_id` 우선 / 조문 폴백** 규칙으로 정렬한다.
> 성격: **Stage A = 읽기 전용.** 코드·DB 변경 0. 이 수정은 **학생이 보는 약점 결과를 바꾸므로**, 무엇이 얼마나 바뀌는지 실측 후 승인받고 Stage B(코드)로 간다.
> 작성일: 2026-07-15. 데이터 스냅샷: 운영 DB(mcgdoplo) 실측. 선행 감사: `선순환-phase0-노드정합성-감사.md` §3-(b).

## 0. 한 줄 결론

- **정렬 필요 = 확정.** 개인 약점/개인과제는 문제→노드를 **조문 경로로만** 잡아 `primary_node_id` 핀을 무시한다. 특허를 핀 기준으로 재배치했는데(memory `patent-node-mapping-workbook`) **개인 약점만 그 재배치를 못 본다.**
- **영향 실측: 활성 문제 380건의 귀속이 바뀐다**(특허 374·민법 6). **42개 노드**의 약점 신호가 달라지고, **실제 학생 시도 566건·학생 23명**이 영향. 규모는 크지 않고 **특허에 집중**(예상대로 핀 재배치 과목).
- **id 공간 문제 아님 → 마이그레이션 불필요.** 귀속은 요청 시 실시간 파생(저장 캐시 없음). **계산 로직 한 줄기 정렬**.
- **설계 권고: 공유 헬퍼 추출 권고.** 현재 코호트·마스터리·OX·개인약점이 "문제→노드 귀속"을 **4벌 따로** 구현 → 재발 방지 위해 단일 헬퍼로. 단 **P4 범위는 개인약점 정렬만**, 마스터리/OX의 부차 차이(아래 §1-주의)는 별도.

## 1. 귀속 규칙 대조

각 서브시스템이 활성 문제 하나를 노드에 귀속시키는 규칙:

| 서브시스템 | 규칙 | 조문 폴백 다중성 | 근거(file:line) |
|---|---|---|---|
| **개인 약점** `getWeakNodes` (+`weak-personal` 과제) | **조문 경로 전용** — `node.articles`(=`article_systematic_links`) 멤버십으로 집계. **`primary_node_id` 무시** | 조문의 **모든** 노드 | `subjects/lib/weak-nodes.server.ts:65-92` + `subjects/lib/node-progress.server.ts:54-58,84-93` |
| **코호트 약점** `buildProblemNodeAttribution` | **`primary_node_id` 우선 / 없으면 조문** | 조문의 **모든** 노드 | `admin/queries/cohort-weakness.server.ts:146-150` |
| **마스터리** `getNodeMastery` | **`primary_node_id` 우선 / 없으면 조문** | 조문의 **첫째만** | `study/mastery.server.ts:83-113` |
| **OX 진단** `computeOxDiagnosis` | **`primary_node_id` 우선 / 없으면 조문** | 조문의 **첫째만** | `study/lib/ox-diagnosis.server.ts:578-604` |

### 목표(정답) 규칙 = **`primary_node_id` 우선 / 없으면 조문 폴백** (코호트와 동일)
개인 약점은 이미 조문 폴백을 "모든 노드"로 쓰므로, 코호트와 정확히 일치시키려면 **`primary_node_id` 우선 분기만 추가**하면 된다(다중성 그대로 '모든 노드').

### ★주의 1 — 목표 3자끼리도 미묘하게 다름(부차 발견)
- 조문 폴백 시 **코호트=조문의 모든 노드**, **마스터리·OX=첫째 노드만**. → 조문이 여러 노드에 걸린 문제(예: 특허 제29조 = 신규성/진보성/확대선출원/산업상이용가능성 4노드)를 핀 없이 조문으로만 잡으면 코호트는 4노드에 분산, 마스터리·OX는 1노드에만. **이건 P4 범위 밖**(핀 없는 문제에 한함) — §3에서 헬퍼 옵션으로 흡수 가능하나 이번엔 개인약점 정렬만.

### ★주의 2 — 개인 경로는 "랭킹"과 "문제 추출"이 이미 서로 다른 규칙
- `getWeakNodes`는 노드를 **조문 경로로 랭킹**하지만, 그 노드에서 과제 문제를 뽑는 `getSystematicNodeProblemSequence`는 **`primary_node_id` 서브트리 ∪ 조문**으로 이미 핀을 존중한다(`problems/queries.server.ts:2771-2773`, feat-4-A-340).
- 결과: **핀으로만 어떤 노드에 걸린 문제(조문 링크 없음)는 랭킹에 안 잡혀 → 그 노드가 약점 상위로 안 뜸 → 과제로 안 뽑힘.** 즉 랭킹이 추출을 막는 상태. 개인 약점을 핀 우선으로 정렬하면 **랭킹과 추출이 같은 규칙**이 되어 내부 모순도 해소된다.

### 2-4. 저장/마이그레이션 여부
- 약점·마스터리는 **요청 시 실시간 계산(파생)**. 저장된 약점/마스터리 캐시 테이블 **없음**(전수 확인). → **DB 마이그레이션·재계산 배치 불필요.**
- 유일한 영속 하류물 = 과거 생성된 **약점 보충 과제**(`assignments`). 이는 생성 시점 규칙으로 이미 고정된 이력이며 **소급 재생성 안 함**(정상). 다음 생성분부터 새 규칙 적용.

## 3. 통일 설계 (최소 변경)

### 3-1. 공유 헬퍼 추출 — **권고**
"문제→노드 귀속"이 4벌(코호트·마스터리·OX·개인) 따로 있는 게 이 어긋남의 근본 원인. 재발 방지 위해 단일 헬퍼로 뽑는다.

```
// 신규: app/features/subjects/lib/problem-node-attribution.server.ts (제안 위치)
resolveProblemNodes(client, problemIds, {
  lawFilter?: LawSubjectSlug[],          // 지정 시 해당 과목 노드로 한정
  fallbackMultiplicity?: 'all' | 'first' // 조문 폴백 시 모든 노드 vs 첫째
}): Promise<Map<problemId, nodeId[]>>
// 규칙: primary_node_id 있으면 [primary_node_id], 없으면 조문 폴백(multiplicity 옵션)
```

- **코호트** `buildProblemNodeAttribution` → 내부를 `resolveProblemNodes(..., {fallbackMultiplicity:'all'})`로 위임(동작 동일, 무변화).
- **마스터리·OX** → `resolveProblemNodes(..., {fallbackMultiplicity:'first'})`로 위임(현행 'first' 보존 → **동작 무변화**). '주의 1'의 all/first 통일은 **별도 티켓**으로 미룸(P4 범위 밖, 프리징 원칙).
- **개인 약점** → 신규로 이 헬퍼 사용(아래 3-2).

> 헬퍼가 과하지 않은 이유: 네 곳이 이미 **거의 같은 코드**(핀 우선+조문 폴백)를 복붙 상태. 추출은 표면적을 늘리지 않고 4→1로 줄인다. 다만 다중성 옵션으로 기존 동작을 **정확히 보존**해 위험을 0으로.

### 3-2. 개인 약점 정렬 — 핵심 변경
현재 `getWeakNodes`는 **조문 중심**(`buildNodeProgressByArticle`가 article 단위 통계 반환 → 노드의 `n.articles` 합산)이라 **핀을 표현할 구조가 없다**(핀은 노드 직접 지정, 조문 없을 수 있음). 따라서:

- `getWeakNodes`를 **노드 중심 집계로 교체**: ①사용자 시도 문제 수집 → ②`resolveProblemNodes(pids, {lawFilter, fallbackMultiplicity:'all'})`로 노드 귀속 → ③노드별 시도/정답 합산 → ④과목·최소시도(5) 필터 → 약점 점수. **이는 `getNodeMastery`와 사실상 동형**(같은 사용자·노드 집계).
- **`buildNodeProgressByArticle`는 그대로 둔다** — 이 함수는 약점 외에 **조문 트리 진척 게이지**(`systematic-node-viewer.tsx:271`)와 **subjects 로더**(`loader.server.ts:912`)도 쓰는 article 단위 표시용이라 의미 보존 필요. 약점만 노드 중심으로 분리.
- `weak-personal.server.ts`·`session-from-weakness("D")`·대시보드 약점 위젯(`dash-weak`)은 **`getWeakNodes` 출력만 소비** → 시그니처 유지하면 **무수정**. 문제 추출(`getSystematicNodeProblemSequence`)은 이미 핀 존중이라 랭킹과 자동 정합.

### 3-3. 프리징/최소 경로
- 신규 뮤테이션 경로 0. 신규는 **읽기 헬퍼 1개**뿐. 기존 함수 시그니처 유지.
- 변경 파일 예상: `subjects/lib/weak-nodes.server.ts`(노드중심 재작성) + 신규 `problem-node-attribution.server.ts` + 위임 3곳(cohort/mastery/ox, 동작보존). **node-progress.server.ts·weak-personal.server.ts 무변경.**

## 4. Stage B 적용 계획

**영향 규모가 중간(380문제·23명·특허 집중)이므로 단발 수정 + 검증 게이트로 충분**(대규모 관찰 게이트 불필요).

1. **헬퍼 추출**: `resolveProblemNodes` 신설. 코호트/마스터리/OX를 위임으로 교체하고 **동작 무변화**를 typecheck + 스냅샷 대조로 확인(같은 입력에 같은 Map). ← 여기서 회귀 없으면 안전지대 확보.
2. **개인 약점 교체**: `getWeakNodes`를 노드 중심으로 재작성(헬퍼 사용). 
3. **검증**:
   - 오프라인 대조: Stage A 쿼리 재실행으로 "특허 39노드/민법 3노드가 새 규칙 결과와 일치"하는지 확인.
   - 특허 수강 대표 학생 1~2명의 before/after 약점 top-N 육안 비교(신규성/진보성 분리 반영 확인).
   - `npm run typecheck` + `npx react-router build`.
4. **롤백 지점**: 커밋을 (a)헬퍼추출+위임(무동작변화) / (b)개인약점 교체 **2커밋 분리**. 문제 시 (b)만 revert 하면 개인약점만 원복, 코호트/마스터리/OX는 영향 없음.
5. **비적용**: 과거 생성 약점과제 소급 재생성 안 함. 마스터리/OX의 all-vs-first 통일은 별도 티켓.

### 승인 요청 포인트
- 규모(380문제·23명·특허 집중)가 "정정 수준"으로 수용 가능한가 → Yes면 Stage B 착수.
- 공유 헬퍼 추출 범위: **개인약점만 동작변경 + 나머지 3자 동작보존 위임**(권고) vs 개인약점만 국소 수정(헬퍼 없이). → 권고는 전자(재발 방지).
