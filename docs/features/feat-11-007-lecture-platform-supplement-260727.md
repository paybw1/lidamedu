## 1. 결정 필요 사항 (착수 전)

1. **#6 권한**: 지금 사용하시는 관리자 계정의 역할이 `admin`(원장)이면 LMS·강의관리는 **이미 전 기능 열려 있습니다**. "제한된 기능이 많다"면 (a) 계정이 `manager`/`instructor` 등급이거나 (b) 특정 staff 계정에 `lms_video_admin` duty 미배정일 가능성. → **어떤 계정·어떤 화면에서 막히는지** 알려주시면 즉시 진단. (코드 변경보다 역할/담당 배정 문제일 확률 큼.)
2. **#4 콜러스 키**: media_content_key 로 바꾸면 **기존 저장분(upload_file_key) 재생 URL·동기화 dedupe 가 깨지므로 백필 필수**. 착수 시 **테스트 영상 1건으로 어느 키가 실제 재생되는지 먼저 검증** 후 전량 백필. (요청서 근거상 media_content_key 가 정답으로 보이나, 벤더 응답 확인 게이트를 둠.)
3. **#13 커뮤니티 에디터 = XSS 경계**: 공지·운영자 글은 신뢰 HTML 로 그대로 렌더 OK. 그러나 **커뮤니티는 학생 작성 글** — 원본 HTML 을 그대로 렌더하면 XSS. → 방침 선택: **(A) 통합 에디터는 운영자 작성물(공지·리담소식·운영자 커뮤니티글)에만 적용, 학생 글은 현행 마크다운 유지** _(권장, 안전)_ / (B) 학생 글도 HTML 허용하되 서버 sanitize 도입.
4. **#11 할인·쿠폰·포인트 지표**: 현재 **할인액이 별도 저장 안 됨**(total_krw 가 이미 할인 후 값), **포인트는 강의 결제에 없음**(포인트=별개 시스템). → (A) 지표에서 제외하고 결제/환불/실매출/건수 중심 _(권장)_ / (B) discounts 스냅샷 컬럼을 추가해 할인액 캡처(스키마 보완).
5. **#12 이미지 처리 방식**: "자동 리사이즈/중앙크롭" — 서버리스에서 런타임 sharp 는 부담. → (A) **권장 px·비율·형식·용량 안내 텍스트 + 표시단 object-cover(중앙크롭)** 로 깨짐 방지 _(권장, 가벼움)_ / (B) 업로드 시 클라이언트 canvas 리샘플 추가. PC/모바일 배너 분리는 별도 컬럼 필요 여부 확인.
6. **#14 링크 테이블 통합**: 현재 `plan_book_links`(cross-sell)와 `plan_books`(연결교재) **2개 공존**. → **`plan_books` 로 일원화**(주/부 `book_role` 컬럼 추가 + `requirement` 필수/선택 + `sort_order` 활용), `plan_book_links` 는 마이그레이션 후 폐지. 두 테이블 유지는 정합성 지옥.

### Phase 2 — 콜러스 동기화 키 (#4) *(★확인 대기 — 라이브 API 검증 결과)*
- **2026-07-27 라이브 API 실측**: 동기화 엔드포인트 `GET /0/media/library/media_content` 응답에는
  **`upload_file_key` 만 있고 `media_content_key` 필드가 존재하지 않는다.** 전체 필드 = `id, kind,
  title, upload_file_key, duration, category_name, category_key, poster_url, snapshot_url,
  original_file_name, transcoding_stage(_name), transcoding_files, channels, status, …`.
  → 코드의 `it.media_content_key` 폴백은 항상 undefined. 이 API 만으로는 "미디어 콘텐츠키"를
  가져올 방법이 없다.
- **따라서 착수 전 확정 필요(둘 중 하나)**:
  1. **미디어 콘텐츠키의 출처**: 콜러스 어느 화면/다른 API 필드가 "미디어 콘텐츠키"인가?
     (후보: 위 응답의 `id`(정수) 또는 `category_key`, 혹은 별도 "미디어 콘텐츠" 리스트 API.
     현재 라이브러리 API 의 `upload_file_key` 와 별개 식별자.)
  2. **또는 현행 재생 실검증**: 현재 `upload_file_key` 로 만든 웹토큰이 실제로 재생되는가?
     재생되면 요청의 "키 교체"는 불필요(현행이 정답). 재생 안 되는 케이스가 있으면 그 키를 확보.
- 확정 후: 파서 키 소스 교체 + **백필 마이그레이션**(video_contents.content_key 및 파생
  lesson_videos.drm_video_id) + 재생·동기화 재검증. 확정 전에는 재생을 깨뜨릴 수 있어 **보류**.
- **사용자 확인(2026-07-27)**: 미디어 콘텐츠키는 콜러스 **채널 뷰**(강의영상→채널→"리담변리사학원"
  호버)에 표시됨 = **채널 단위 미디어 콘텐츠키**. 즉 라이브러리 업로드 API 가 아니라 **채널
  media-content API** 를 찾아야 함(별도 조사 대상). → Phase 2 는 채널 API 확보 시 착수(현재 보류,
  사용자 지시로 Phase 3~5 선행).

### Phase 3 — 교재 연결·결제 UX (#14·17)
- **#14 모델 통합**: `plan_books` 에 `book_role`(main/sub) 추가·`requirement`·`sort_order` UI 노출, admin-plans "연결 교재"를 주/부·필수/선택·순서 편집 그리드로. `plan_book_links` 데이터 이관 후 폐지. (결정 6)
- **#17 결제 화면 간소 교재 선택**: 강의 상세/결제에 연결 교재 간소 블록(썸네일·주/부·명·가격·재고·체크박스+수량·상세보기 링크) + 금액 분해(강의/교재/배송/할인/최종). 동시결제(#16)는 기존 카트 경로 재사용.

### Phase 4 — 매출 통계 재구성 (#7~11) *(가장 큰 작업)*
- **#7 3분할**: 상품유형 리졸버를 `subscription(정기구독) | course(강의: course/tpass, lecture_category 세분) | book(도서)` 3분류로 재정의(order_items.item_type + subscription_plans.product_kind/lecture_category 조인). 3개 통계 탭 + 전체 합계.

- **#11 결과·다운로드**: 요약(주문/할인/결제/환불/실매출/건수/상품별수량/결제수단별) + CSV(현행 유지, xlsx 는 선택). 할인/쿠폰/포인트는 결정 4 반영.
