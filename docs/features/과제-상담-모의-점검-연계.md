# 과제·상담·모의고사 점검 + 학습현황 양방향 연계 (점검·설계)

> 상태: 점검·설계 문서 (코드 0). 2026-06-29 작성.
> 맥락: feat-7-040(학습현황 파악 = 조망·개별·신호)이 막 출시됨. 이제 **행동축(과제·상담·모의)**과 파악축의 **양방향 연계**를 점검한다.
> 관련: `docs/features/온라인종합반-관리자-학습현황.md`, feat-7-021b(과제), feat-7-025(상담), mcq-picker 고도화(모의).

## 0. 요약 (TL;DR)

- **행동→파악 backbone은 견고하다.** `user_problem_attempts`가 단일 정답 신호 테이블이고, 모의고사·과제 문제·OX를 푸는 행위가 **전부 표준 경로(`/api/problems/attempt` → `recordProblemAttempt`)로 이 테이블에 기록**된다. 따라서 진도·정답률·약점·**P2 추세 신호**가 자동 반영된다. 모의 정답률 급락도 P2가 잡는다(트렌드 쿼리에 `mode` 필터 없음).
- **그러나 파악 레이어는 `mode`/`session_id`/`pack_id`를 무시**한다 → "모의고사 점수", "실전 vs 자습 정답률", "과제 이행률" 같은 **구분된 뷰가 어디에도 없다**. 모의 성적이 자습과 구별 안 됨.
- **파악→행동은 거의 전부 상담(note) 한 채널로 깔때기 된다.** 5개 staff 화면에서 도달 가능한 진짜 액션은 (a) 1:1 코멘트 작성, (b) cohort 과제 목록으로 가는 일반 내비 링크 1개, (c) at-risk 일괄 격려(인박스 알림), (d) 멤버/커리큘럼 관리뿐.
- ★ **가장 큰 구조적 공백**: 플랫폼이 **단원(node)별 약점을 3곳에서 계산**(개별 `getNodeMastery`·`computeOxDiagnosis`, 반 공통 `getCohortWeakNodes`)하는데 **그중 한 곳도 "이 단원으로 과제 출제/연습 배정" CTA가 없다.** 유일하게 배선된 약점→행동은 **약점→모의고사**(`CohortWeaknessSource`, 모의 picker)뿐. 진단 레이어와 행동 레이어가 안 이어져 있다.
- **결론**: 기능 자체 구멍은 작다(게이트 견고, 자동 채점 정직). **가치는 연계 갭에 있다** — 특히 ① 약점→과제(모의처럼) ② 과제 이행을 개별 상세에 표시 ③ 신호→상담 루프(마지막 상담일·인라인).

## 1. 과제 (assignments) — feat-7-021/021b

### 1.1 구현
| 구분 | 내용 |
|---|---|
| 라우트 | staff: `/admin/cohorts/:id/assignments`(목록·생성), `/admin/cohorts/:id/assignments/:aid`(편집), `/api/admin/assignment`(action). student: `/assignments`, `/assignments/:aid` |

| 게이트(021b) | **action 레벨 owner 게이트**(RLS 백스톱 없음 — 쿼리는 adminClient). `resolveAssignmentCohortId`로 대상 cohort 역추적 → instructor면 `cohort.ownerId===user.id` 강제, manager+ 통과. cron(`curriculum-weekly`)만 adminClient 쓰기 경로. **견고** |

### 1.2 보완점 (구멍·미흡)
- **읽기 경로 전부 adminClient** — 학생 대면 `getStudentAssignment`/`listStudentAssignments`도 손수 `cohort_members` 멤버십 체크가 유일 방어. RLS 백스톱 없어, 향후 멤버십 체크 누락 쿼리가 생기면 타 반 과제 누출. (과제·상담·모의 공통 패턴 — adminClient 의존)
- `deleteAssignmentItem`는 hard delete(다른 곳은 soft). 콘텐츠 항목이라 수용 가능하나 일관성 메모.
- `study_sessions` 스캔 `.limit(5000)` 무압축 — heavy 사용자의 열람 항목이 5000행 밖이면 미완료 오판 가능.
- `recomputeSubmission` 매 로드 O(멤버×항목) — `last_checked_at` throttle 미사용. 비용 이슈(정합성 아님).
- `target_quantity` 무시 — 완료는 이진(≥1 정답). "x3 반복" 설정해도 판정 무영향(표시용).

### 1.3 ★연계
- **(a) 파악→행동 (약점→과제): ❌ 전무.** 과제 생성/항목추가에 `getCohortWeakNodes`·`getNodeMastery`·약점·auto-selection 참조 **0건**(grep 확인). 모의 picker가 가진 `pickProblemsFromWeakNodes`/`CohortWeaknessSource` 같은 게 과제엔 없음. "이 단원 약점 문제 추가" 버튼 부재 → **명백한 빠진 연결**.
- **(b) 행동→파악**: 풀이 기록 **✅** — 과제 문제는 별도 엔드포인트 없이 `entryUrl`로 일반 문제 러너 진입 → `/api/problems/attempt` → `user_problem_attempts`. 즉 과제 풀이가 진도·약점·신호에 자동 반영. **그러나 과제 이행(완료) 표시는 ❌** — `admin-student-detail.tsx`는 assignments를 **로드도 안 함**(grep 0). 개별 학생 360° 뷰에 과제 이행 없음. 과제 진행은 `admin-assignment-edit`의 per-cohort 집계로만 노출. (과제 *수*만 pass-prediction에 들어감)

- **(b) 행동→파악**: 개별 상세 표시 **✅**(`NotesSection`, 읽음 badge 포함). **그러나 집계 ❌** — cohort 진도/통계 어디에도 학생별 코멘트 수·마지막 상담일 컬럼 없음, 상담 피드 없음, 어떤 신호도 상담을 소비 안 함. **한 학생씩만** 열람.

## 3. 모의고사 (mock exams) — mcq-packs / quiz_sessions

### 3.1 구현 / 현재 상태
| 구분 | 내용 |
|---|---|
| 모델 | `mcq_packs`(kind mock_full/mock_progressive) · `quiz_sessions`(mode·scope='pack'·pack_id·problem_ids[]·time_limit) · `user_problem_attempts`(답안). 러너는 기출과 공유 |
| 화면 | detail(`/latest/mcq/:id`)→sheet 러너(`/sheet/:sid`)→result(`/result/:sid`). OX 시험은 별도 러너(`/ox-exam`) |
| picker(고도화) | **staff 출제 도구**: `MockPackProblemPicker`(난이도 상위 N `pickProblemsByDifficulty`) + `CohortWeaknessSource`(`getCohortWeakNodes`→약점 문제 추가). = 약점→모의 배선 |
| 결과 | 점수·석차·합격선·지난 회차 ±·단원별 정답률·오답 근거(조문/판례/AI). 다음 액션: 오답 재도전·약점 단원 체계도 deep-link |

### 3.2 보완점
- **실전 점수 미스냅샷** — exam 점수를 매번 `user_problem_attempts`에서 재계산. 시도 편집/삭제 시 과거 모의 점수가 바뀜(불변 기록 없음).
- ★ **OX 시험 bulk insert가 `recordProblemAttempt` 우회** → SRS 훅 미발동(OX 시험 답이 복습 큐 갱신 안 함). OX *자습*은 정상 경로(SRS 발동). 신호엔 영향 없음(같은 테이블).
- `getSessionWeakNodes` 다중매핑 조문을 첫 노드로 collapse(기존 알려진 한계).
- 결과 화면에 상담/과제 CTA 없음(3.3b).

### 3.3 ★연계
- **(a) 행동→파악 ((c) 재확인): ✅ 자동 반영.** 모의 sheet 답안 → `/api/problems/attempt` → `recordProblemAttempt` → `user_problem_attempts`(mode='exam', session_id 태그, 그 외 자습과 동일 필드). **트렌드 쿼리(`getCohortTrendSignals`)에 `mode` 필터 없음** → 모의 정답률 급락이 P2 추세 신호에 **잡힘**(최근14d vs 직전14d). OX 시험도 user_problem_attempts에 적재(별도 inline insert)되어 신호 반영. **즉 모의 결과는 진도·정답률·약점·신호에 자동 반영된다.**
- **(b) 파악→행동: ⚠️ 복습만, 상담·과제 없음.** 결과 화면 next-action = 오답 재도전(`session-from-attempts`) + 약점 단원 체계도 deep-link + 오답 근거 조문/판례. **상담·과제·SRS 복습 러너로의 CTA 없음.** 낮은 모의 점수 → 강사 상담/구조화 과제로 이어지는 경로 부재.

## 4. 연계 지도 (양방향 종합)

### 4.1 행동 → 파악 (행동이 학습현황에 반영되나)
| 행동 | user_problem_attempts 반영 | 파악 레이어 노출 | 평가 |
|---|---|---|---|
| 모의고사 풀이 | ✅ (표준 경로) | 진도·정답률·약점·**P2 트렌드** 자동 | ✅ **단, 모의 구분 뷰 없음**(mode 무시 → "모의 점수"·실전/자습 분리 부재) |
| 과제 풀이 | ✅ (일반 러너 경유) | 진도·약점·신호 자동 | ⚠️ **과제 이행(완료)은 개별 상세 미표시** |
| 상담 | — (풀이 아님) | 개별 상세에 표시 ✅ | ⚠️ **집계·롤업·신호 반영 전무** |
| OX 시험 | ✅ | 신호 반영 + OX 진단(별도) | ⚠️ OX 시험은 SRS 큐 미갱신(우회) |

### 4.2 파악 → 행동 (진단에서 행동으로 갈 수 있나)
| 파악(출발) | 과제 | 상담 | 모의/복습 |
|---|---|---|---|
| 반 공통 약점(`getCohortWeakNodes`, cohort-stats) | ❌ CTA 없음 | — | ✅ 모의 picker(`CohortWeaknessSource`) |
| 개별 약점(`getNodeMastery`·OX 진단, student-detail) | ❌ | ⚠️ 노트뿐(약점 연계 X) | ⚠️ 체계도 deep-link만 |
| 위험 신호(at-risk·추세) | ❌ | ⚠️ 상세로 내비(인라인X·마지막상담일X) | ❌ |
| 모의 결과(낮은 점수) | ❌ | ❌ | ✅ 오답 재도전·약점 체계도 |

### 4.3 있는 연결 / 빠진 연결
**있는 연결 (✅):**
- 모의·과제·OX 풀이 → `user_problem_attempts` → 진도·약점·**추세 신호**(자동).
- 약점(반 공통) → 모의고사 출제(`CohortWeaknessSource`).
- 신호/약점 → 상담(내비게이션 + 노트 표시).
- 모의 결과 → 오답 재도전·약점 단원 체계도.

**빠진 연결 (가치순):**
1. ★ **약점 → 과제** — 반 공통/개별 약점 단원에서 "이 단원 과제 출제"(약점 문제 자동추가)가 안 됨. 모의는 되는데 과제는 안 됨. **가장 명백·고가치**(모의 A+B의 과제판).
2. ★ **과제 이행 → 개별 상세** — `admin-student-detail`에 과제 완료/미완 표시 부재. 행동→파악 가시성 구멍.
3. ★ **신호 → 상담 루프** — at-risk에 "마지막 상담 N일 전/미상담" 신호 없음 + 리스트 인라인 상담 불가. 상담 활동이 파악 레이어로 전혀 안 돌아옴(집계 0).
4. **반 공통 약점 → 행동 CTA** — cohort-stats "보충 수업 주제" 카드가 read-only dead-end(과제·모의 배포 버튼 없음).
5. **모의 구분 뷰** — mode/pack_id 무시 → "모의 점수 추이"·실전/자습 분리 없음. 모의 결과 → 상담/과제 CTA 없음.
6. **개별 약점/마스터리/OX → 액션** — 가장 풍부한 진단이 액션 없이 끝남(노트 수기 입력만).

## 5. 우선순위 + 단계안

**원칙**: 기능 자체 구멍은 작다(게이트 견고). **학습현황이 막 출시됐으므로 연계 갭이 가치 최고** — 진단을 행동으로 잇는 한 칸이 곧 학습현황의 ROI다. 행동→파악 backbone(자동 반영)은 이미 서 있으니, **파악→행동 방향**과 **가시성(과제 이행·상담 집계)**이 핵심.

| 단계 | 내용 | 가치 | 규모 | 재사용 |
|---|---|---|---|---|
| **P1-a** | **약점 → 과제**: 반 공통 약점 카드(cohort-stats)·개별 약점에 "이 단원 과제 출제" → 과제 항목 자동추가. 모의의 `pickProblemsFromWeakNodes`/`CohortWeaknessSource` 시드 **재사용** | ★최고(빠진연결 #1·#4) | 중 | 모의 seam·`getCohortWeakNodes` 재사용 |
| **P1-b** | **과제 이행 → 개별 상세**: `admin-student-detail`에 `listStudentAssignments(profileId)` 카드(완료/미완·마감 임박). | ★높음(#2, 저비용) | 소 | 기존 함수 그대로 |
| **P2-a** | **신호 → 상담 루프**: at-risk·개별 상세에 "마지막 상담 N일 전/미상담" 배지(student_notes 집계) + at-risk 행 인라인 노트(또는 1클릭 빠른 코멘트). | ★높음(#3) | 중 | NotesSection·student_notes |
| **P2-b** | **상담 집계**: cohort 진도/통계에 학생별 코멘트 수·마지막 상담일 컬럼(파악 레이어로 환류). | 중 | 소~중 | listCohortProgressSummary 확장 |
| **P3-a** | **모의 구분 뷰**: 개별 상세/결과에 mode='exam' 분리("모의 점수 추이"). 모의 결과 화면에 상담·과제·SRS 복습 CTA. | 중 | 중 | user_problem_attempts.mode·session |
| **P3-b** | **기능 폴리시**: OX 시험 SRS 미발동 수정 · 모의 점수 스냅샷(불변 기록) · 과제 target_quantity 반영. | 소~중 | 소 | — |

**근거**:
- **P1 먼저**: 약점→과제(a)는 사용자가 명시한 "모의 A+B처럼 약점 문제 자동추가" 패턴의 과제판 — 가장 명백한 빠진 연결이고 모의 seam 재사용이라 신설 적음. 과제 이행 표시(b)는 함수 재사용이라 거의 공짜이면서 개별 상세를 완성.
- **P2**: 신호→상담 루프는 "위험 발견 → 개입 → 추적" 사이클을 닫음. 상담 집계는 강사가 "누구를 안 챙겼나"를 보게 함. 둘 다 student_notes를 파악 레이어에 처음으로 환류.
- **P3**: 모의 구분 뷰·폴리시는 가치 있으나 backbone이 이미 자동 반영 중이라 후순위. OX SRS 우회는 정합성 메모(신호엔 무해).

**완료 조건 매핑**: ①과제(1) ②상담(2) ③모의(3) ④연계 지도 있는/빠진(4) ⑤우선순위·단계(5). 코드 0(설계만).
