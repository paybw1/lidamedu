# feat-2-036 — 주관식 모범답안 연습 모드 (목차 연습 · 내용 연습)

> 요청(2026-09-04, 원장): "주관식 모범답안도 판례 도식처럼 연습 모드를 구현하자.
> 연습은 **목차에 대한 연습**과 **그 내용에 대한 연습**으로 구분해서 구현하고 싶다."
>
> 대상 화면: `/subjects/:subject/problems/:problemId` — 주관식(2차) 문항 뷰어.

상태: **S1~S3 구현 완료** — 목차 연습·내용 연습 모두 가동. §10 이 최종 방향이다(§4·§5 는 최초 설계로, 일부는 §10 에서 뒤집혔다).

---

## 1. Layer 1 판단 — 왜 만드는가, 왜 새 러너가 아닌가

모범답안은 이미 **답안을 쓰는 순서 그대로** 조판돼 있다 — `## Ⅰ. 설문` → `### 1. 문제의 소재`
→ `#### (1) …` → 본문. 연습에 필요한 건 그중 **어느 층을 가리고 학생이 채우게 하는가**뿐이다.

새 러너(`/study/…`)를 만들면 같은 문항을 두 화면에서 보게 된다. → **기존 주관식 패널 안의
모드 전환**으로 붙인다(KISS · 기존 메커니즘 통합). 판례 도식 S6(feat-2-035 §10)이 이미
같은 판단을 했고 그대로 작동하고 있다.

### 왜 두 가지로 나누는가

목차와 내용은 **틀리는 방식이 다르다.**

| | 묻는 것 | 학생이 실패하는 지점 |
|---|---|---|
| 목차 연습 | 이 사안을 **어떤 순서로 쪼갤 것인가** | 논점을 빠뜨리거나, 배점과 무관하게 지면을 배분 |
| 내용 연습 | 각 칸에 **어떤 법리를 채울 것인가** | 목차는 세웠는데 요건·판례를 못 씀 |

목차를 못 세우는 학생에게 내용을 물으면 두 실패가 섞여 무엇을 고쳐야 할지 알 수 없다.
**목차 → 내용** 사다리로 둔다.

## 2. 기존 기능과의 경계 (★중복 아님을 먼저 확인)

이 문항 화면에는 이미 **3단계 훈련**(feat-2-032 S5)이 있다. 경계를 분명히 해야 한다.

| | 3단계 훈련 (feat-2-032) | **연습 모드 (이 문서)** |
|---|---|---|
| 출발점 | **백지** — 스스로 논점을 찾고 목차를 세운다 | **모범답안을 가리고 복원**한다 |
| 채점 | AI 초안(3축·비용·지연) | 즉답·무료(핵심어 커버리지) |
| 저장 | `user_subjective_attempts` (학습현황 반영) | 초안만(§6) |
| 목적 | 실전 시뮬레이션 | 반복 숙달 |

feat-2-035 §10.1 이 `case_training`(쟁점을 스스로 찾기) ↔ 도식 연습(쟁점이 주어진 상태에서
법리 쓰기)을 가른 것과 **같은 사다리**다. 백지 훈련이 어려운 학생이 먼저 밟는 칸이다.

GS(2차 모의고사, feat-5-201~203)는 별개 시스템으로 건드리지 않는다.

## 3. 데이터 — 모범답안 목차 구조 (전수 실측 2026-09-04)

주관식 문항 중 모범답안이 있는 **184건**을 셌다.

| | 중앙 | 하위 25% | 상위 90% | 최대 |
|---|---|---|---|---|
| `##` (설문) | 3 | 2 | 5 | 7 |
| `###` (중목차) | 11 | 9 | 16 | 22 |
| `####` (소목차) | 9 | 3 | 16 | 23 |
| 글자 수 | 3,568 | 2,925 | 5,264 | 5,983 |

**`##` 이 없는 답안은 0건** — 목차 트리를 파싱해도 빈손이 되는 문항이 없다. 별도 컬럼이나
편집 화면 없이 `model_answer_md` 하나로 두 연습이 다 성립한다.

★다만 한 문항 전체는 소·중목차 합쳐 **중앙 20칸**이다. 통째로 연습시키면 한 번에
20칸을 채워야 한다 → **설문(`##`) 단위로 끊는다**(설문 하나당 중앙 6~7칸).

## 4. 화면

패널 머리에 모드 전환을 둔다 — **읽기 / 목차 연습 / 내용 연습**. 선택은 `localStorage`
(`subjectivePractice.mode`)에 남는다. 도식 패널의 「읽기/연습」과 같은 관례.

### 4.1 목차 연습

```
발문                                   ← 보인다(문제지)
설문 (1) [ 10점 ]  ← 설문 단위로 하나씩

  ┌──────────────────────────────┐
  │  목차를 세워 보세요                │   ← 한 칸짜리 textarea
  │  (Ⅰ. / 1. / (1) 층을 그대로 써도 되고, │
  │   줄바꿈만으로 나눠도 됩니다)          │
  └──────────────────────────────┘
                       [ 맞춰보기 ]
```

- **한 칸으로 받는다.** 층별로 칸을 나눠 주면 "몇 층 몇 칸인지"를 알려주는 셈이라 정작
  묻는 것(어떻게 쪼갤 것인가)이 사라진다.
- 「맞춰보기」 → 모범답안의 목차 트리가 아래에 펼쳐지고, **맞은 항목 / 놓친 항목**이 표시된다.
- 배점(`total_points`·설문 배점)은 **연습 전에** 보인다 — 지면 배분이 목차 훈련의 절반이다.

### 4.2 내용 연습

```
발문                                   ← 보인다
설문 (1)
  Ⅰ. 설문 (1) — 침해금지청구…            ← 목차는 **보인다**(문제지에 해당)
    1. 문제의 소재      [ 빈 칸 ]
    2. 甲의 주장
      (1) 구성요소완비의 원칙…  [ 빈 칸 ]
      (2) 재판상 자백…          [ 빈 칸 ]
    …
    5. 결론            ← 가린다(먼저 보이면 쓰기 전에 답을 읽는다)
                       [ 맞춰보기 ]
```

- **잎 노드(본문이 붙은 최하위 목차)만** 빈칸이 된다. 중간 목차는 제목만 있고 본문이 없다.
- 결론 칸은 도식 연습과 같은 이유로 「맞춰보기」 뒤에 열린다.
- 칸이 6~7개다 → 한 칸씩 접었다 펼 수 있게 한다(도식의 쟁점 접기/펴기와 같은 방식).

### 4.3 공통

- ★연습 중에는 **staff 편집 버튼을 걷는다.** 가려 둔 화면에서 「수정」을 누르면 textarea 에
  모범답안이 그대로 뜬다(도식에서 겪은 것과 같은 구멍). 운영자도 연습할 수 있어야 한다.
- 입력 칸은 **비제어**로 둔다. value 를 state 로 되쓰면 iPad 한글 입력에서 조합 중인 글자가
  밀린다(암기 탭·도식 연습에서 이미 겪었다). 저장해 둔 초안도 state 가 아니라 ref 로 채운다.

## 5. 채점 — 실측을 먼저 했다

feat-2-035 §10.3 의 **핵심어 커버리지**(재현율형)를 그대로 쓴다. `app/features/cases/lib/answer-match.ts`
가 이미 있고 단위 검증(12건)도 붙어 있다. **새로 만들지 않는다.**

★쟁점은 "그 방식이 **짧은 제목**에도 통하는가"였다 — 법리 본문은 200자인데 목차 한 줄은
10자다. 토큰이 적으면 한두 개 어긋나도 비율이 크게 흔들릴 수 있다.

**실측(2026-09-04, 2026년 1번 설문(1) 목차 15줄 기준)** — UI 를 짓기 전에 쟀다.
기록: `app/features/subjects/lib/outline-practice-probe.test.ts`

| 학생이 쓴 목차 | 커버리지 |
|---|---|
| 표현은 다르되 뼈대가 같은 목차 | **0.70** |
| 큰 뼈대만(소목차 없음) | 0.19 |
| 다른 논점(정정심판)의 목차 | 0.04 |

→ **도식과 같은 자리에 떨어진다.** 임계값도 공용으로 쓴다 —
`ACCEPT_MIN 0.65` · `PARTIAL_MIN 0.35`(`answer-match.ts` 의 상수 그대로).

- 되돌려주는 것은 **모범답안 자신의 말**뿐이다 — 맞은 항목 / 놓친 항목 / 놓친 핵심어(최대 8).
  AI 평은 넣지 않는다(Non-negotiable 11 · 응시마다 비용·지연).
- 내용 연습은 **칸별로** 채점하고 설문 단위로 합산해 보여 준다.

### 5.1 목차에서만 다른 점 — 순서

커버리지는 순서를 보지 않는다. 목차는 순서가 곧 논리라 그대로 두면 **뒤죽박죽 쓴 목차도
만점**이 된다.

→ 점수와 **별개 신호**로 표시한다: 맞은 항목들이 모범답안 순서대로 나왔는지(최장 증가 부분수열).
점수를 깎지는 않는다 — 순서가 다른 편이 나은 답안도 있고, 실측 없이 감점 규칙을 넣으면
근거 없는 채점이 된다. v1 은 **"순서가 다릅니다" 안내까지**.

## 6. 저장

**v1 은 `localStorage` 초안만** — `subjectivePractice.<problemId>.<blockKey>`.
쓰다가 새로고침해도 남는다. 도식 연습 v1 과 같은 선택이다.

`user_subjective_attempts` 에 넣지 않는 이유: 그 테이블은 **3단계 훈련의 응시 기록**이고
AI 채점·학습현황·KPI 가 거기에 물려 있다. 연습(모범답안을 보고 복원하는 반복 숙달)을 같은
칸에 넣으면 "훈련 착수" KPI 가 부풀고, 3단계 완주율이 뜻을 잃는다.
→ 연습이 실제로 쓰이는지 본 뒤, 필요하면 **별도 테이블**로 뺀다.

## 9. 결정이 필요한 것 (원장 확인 요청)

### ① 누구에게 열 것인가 ★가장 중요

**주관식 문항 뷰어 자체가 지금 staff 전용이다.**
`problem-viewer.tsx:233` — 학생이 직접 URL 로 들어오면 과목 홈으로 돌려보낸다. 게다가
모범답안·채점기준은 `redactSubjectiveAnswer` 로 서버에서 걷어낸다(feat-2-032 S5 "유지" 항목).

연습 모드는 「맞춰보기」에서 **모범답안을 드러내는 기능**이다. 그러므로:

- (가) **staff 전용으로 먼저 낸다** — 게이트를 건드리지 않는다. 원장·강사가 써 보고 판단.
- (나) **종합반 학생까지 연다** — 뷰어 게이트와 `redactSubjectiveAnswer` 를 함께 손봐야 한다.

권고는 **(가)**. 게이트를 여는 것은 연습 모드와 별개의 콘텐츠 공개 결정이고, 되돌리기 어렵다.
연습이 쓸 만한지 먼저 확인한 뒤 (나)를 별건으로 다루는 편이 안전하다.

### ② 연습 단위

설문(`##`) 단위를 기본으로 본다(§3). 문항 전체를 한 번에 연습하는 선택지도 둘 것인가?
— 권고: **설문 단위만**. 20칸짜리 화면은 아무도 끝까지 채우지 않는다.

### ③ 목차 연습의 입력 형식

한 칸 자유 입력을 권고한다(§4.1). 층을 나눠 받는 편이 채점은 정밀하지만, 몇 층 몇 칸인지를
알려주게 되어 문제가 쉬워진다.

## 10. 방향 전환 (2026-09-04, 원장) — 두 연습을 거울로

> "목차 연습을 내용 보여주고 빈칸 형태로 하고, 내용 연습은 목차 보여주고 빈칸 형태로 하는 것이
> 좋을 것 같아" · "모범답안 안에 목차연습·내용연습 토글 넣어주고"

|  | 보여 주는 것 | 빈칸 | 묻는 것 |
|---|---|---|---|
| 목차 연습 | **본문** | 제목 | 이 글에 붙일 이름은 무엇인가 |
| 내용 연습 | **목차** | 본문 | 이 자리에 무슨 법리를 쓰는가 |

거울 관계라 **채점·화면을 한 벌로** 만들었다 — `essay-practice-score.ts` + `essay-practice.tsx`,
`mode` 하나로 갈린다. 두 벌로 두면 한쪽만 고쳐져 기준이 어긋난다.

### 10.1 §4.1(한 칸 자유 입력)을 버린 이유

처음 설계는 목차를 **한 칸에 통째로** 받았다("몇 층 몇 칸인지 알려주면 문제가 쉬워진다").
빈칸 방식은 칸 수와 층을 드러내지만, **본문이라는 단서를 주고 이름을 묻는 것**이 실제 답안
작성에 더 가깝다 — 답안은 논증을 먼저 세우고 소제목을 붙이는 일이다.
그에 따라 버린 것:

- **순서 신호**(§5.1) — 칸이 제자리에 있으므로 순서를 물을 일이 없다. 순서 판정 코드는 지웠다.
- 한 칸 자유 입력 채점(`scoreOutline`) — 경로를 둘로 두지 않는다.

### 10.2 토글 자리

모범답안 카드 머리에 **읽기 / 목차 연습 / 내용 연습**(도식 패널의 「읽기·연습」과 같은 자리).
연습 중에는 모범답안 본문을 렌더하지 않는다 — 옆에 답이 펼쳐져 있으면 연습이 아니다.

### 10.3 실측 (실제 경로 `scorePractice`)

**목차 연습 — 제목 한 칸(핵심어 2~4개)**

| 학생이 쓴 제목 | 커버리지 |
|---|---|
| 말을 바꿔 쓴 제목 | **0.75** (인정) |
| 핵심어 절반만 | 0.25 (미흡) |
| 엉뚱한 제목 | 0.00 (미흡) |

짧은 제목에서도 임계값 0.65/0.35 가 그대로 선다.

**내용 연습 — 본문 한 칸**

| 학생이 쓴 본문 | 커버리지 |
|---|---|
| 실제 답안 수준(법률용어를 갖춰 씀) | **0.90** (인정) |
| 압축해 요약 | 0.62 (부분) |
| 표현을 많이 바꿔 법률용어를 피함 | 0.33 (미흡) |
| 다른 쟁점의 법리 | 0.10 (미흡) |

★처음 예시 답안이 0.62 로 나와 임계값을 의심했으나, **자를 물건에 맞추지 않았다.** 답안을
실제 수준으로 다시 쓰니 0.90 이 나왔다 — 도식 연습 실측(제대로 쓴 답 0.73~0.96)과 같은 자리다.

★**알아 둘 성질**: 법률용어를 피해 풀어 쓴 답은 0.33 으로 떨어진다. 2차 답안에서 법률용어를
쓰는 것 자체가 채점 요소라 그대로 두었지만, 이 연습은 **법리를 그 말로 쓰는 훈련**이라는 점을
학생이 알아야 한다. 완화가 필요하면 임계값이 아니라 문구로 안내한다.

### 10.4 비워 둔 칸은 채점에서 뺀다

0 점으로 깔면 한두 칸만 연습한 학생이 크게 손해다 — 3단계 훈련의 AI 채점이 미작성 축을
제외하는 것과 같은 이유다. 판정 칩에 `인정 n/쓴 칸 m (안 쓴 칸 k)` 로 함께 보여 준다.

### 10.5 상태
