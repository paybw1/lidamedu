## 0. 한눈 요약

- **exam_results는 차수(`exam_round`)·합불(`status`) 컬럼이 있고, 과목별 점수 컬럼(`self_reported_subject_scores` JSONB)도 있으나 — 폼·upsert에 미배선이라 항상 null.** 현재 입력은 **전체 점수(`self_reported_total_score`) 하나 + 자가신고 status**뿐.
- **커트라인 기반 1차 합격 자동판정은 없음**(status는 자가신고 드롭다운). 단 **커트라인 데이터(`official-exam-stats.json`)와 법정 floor 헬퍼는 이미 존재** → 신설 규모 **중간**(과목별 입력 배선 + 판정 함수).
- **재사용 자산 다 준비됨**: 동의 `ConsentSection`→`/api/consent`, 목표 `GoalSummaryBar`(독립 컴포넌트), 분포·백분위 엔진 `buildHist`/`pickPercentile`, 코호트 표본 패턴.
- **설계 핵심 = 3블록 독립 저장**: 목표·시험결과·동의를 한 Sheet에 두되 **각자 다른 action**(목표→`/study/stats`, 시험결과→결과 upsert, 동의→`/api/consent`)으로 분리 → **저장이 동의를 함의하지 않음**(법적 분리 보장).

## 1. 실제 시험 결과 현황 (exam_results / `/me/exam-results`)

### 1.1 스키마 (`database.types.ts:2670-2755`)
`result_id`(PK) · `user_id` · `exam_year` · **`exam_round` enum(first/second)** · **`status` enum(absent/pending/failed/passed)** · `self_reported_total_score`(전체점수 0~200) · **`self_reported_subject_scores` JSONB(과목별 — 존재하나 미사용)** · `verification_status`(self_reported/document_submitted/verified/rejected) · `certificate_path`/`url` · `verified_by`/`at` · `rejection_reason` · `study_summary_md`. **unique (user_id, exam_year, exam_round)**(upsert onConflict).

→ **과목별 점수: 컬럼은 있으나 입력 폼·`upsertMyExamResult`가 안 씀 → 항상 null**(`my-exam-results.tsx:40-49,509-571` / `exam-results/queries.server.ts:169-177`). **차수·합불 필드는 존재.**

### 1.2 차수 인지
`exam_round` 컬럼으로 저장하나 **입력 폼은 차수로 분기 안 함**(1·2차 동일하게 total 하나만). `profiles.next_exam_round`(차수 SSOT, feat-2-025)와 **입력은 직접 연동 안 됨** — next_exam_round는 합격 *예측* 임계값 분기에만 쓰임(`pass-predict.ts:71-78`).

### 1.3 합격 판정 — 현재 없음(자가신고), 신설 시 중간 규모
- 합불 = **학생 자가신고 `status` 드롭다운만**(`my-exam-results.tsx:548-559`). 점수→커트라인 자동계산 **없음**.
- 법정 floor 헬퍼 `isSubjectFloorFail`·`meetsAveragePass`(`pass-criteria.ts:131,136`)는 **정의돼 있으나 호출처 0**(미연결).
- **커트라인 데이터 존재**: `app/features/exam-results/data/official-exam-stats.json` — 1차/2차 **연도별 `cut_line`**(2022=81.66·2024=76.66·2025=79.16·2026=80.00, 일부 null) + 과목별 avg/fail_rate + 법정기준(과락 40·평균 60·1차 600명 3배수 상대선발). 헬퍼 `getRecentCutLineAvg`/`getOperativeTarget`/`getStatutoryFloor`. (※ `mcq_packs.pass_score`=모의고사 합격선, 실제 시험 커트라인과 별개.)
- **신설 규모 = 중간**: 이미(법정 floor 헬퍼·cut_line JSON·과목 enum·subject_scores 컬럼) / 신설(과목별 입력칸 + upsert 배선 + 판정함수 + 차수분기). **★도메인 한계**: 1차는 상대선발이라 **과락은 확정 탈락 판정 가능 / 합격은 cut_line "추정"까지만** — 확정 합불은 자가신고+합격증 검증이 본질. → status는 **자가신고 유지 + 과락/추정은 derived projection**(persisted와 분리, CLAUDE.md Layer2).

### 1.4 합격자 파생 (식별 기준)
합격자 = **`exam_results.status='passed'`** + 벤치마크 시 `profiles.pool_consent_at != null`(B 동의) + `is_synthetic != true`. 게이트 `isPasserBenchmarkEnabled`(실 동의 합격자 ≥ `PASSER_BENCHMARK_MIN_SAMPLE`=10, fail-closed, `passer-benchmark-gate.server.ts:42-85`). verified는 "인증됨" 카운트용(판정 게이트 아님).

## 4. ★ 입력 허브 설계 (대시보드 Sheet)

### 4.1 구조 — 한 Sheet · 3블록 (시각·구조 분리)
대시보드 "내 정보 설정" 버튼 → Sheet. 3개 **시각적으로 분리된 섹션**(별 카드/구분선·헤더):

```
[블록 1] 목표        — GoalFields (examRound·examDate·weeklyGoalHours·targetScore·notes)
[블록 2] 실제 시험결과 — 차수 분기(아래 4.2)
[블록 3] 동의(별도)   — ConsentSection (A 내분석 / B 풀, 각 독립 토글 + placeholder 문구)
```

### 4.2 ★ 시험결과 블록 — 차수 분기 (`next_exam_round` SSOT 재사용)
loader가 `profiles.next_exam_round`로 어느 폼을 보일지 결정:

- **1차 준비/응시(`next_exam_round='first'`)**: **과목별 점수 입력**(1차 3과목: 산업재산권법 · 민법개론 · 자연과학개론). 저장 = **점수만**(`self_reported_subject_scores` JSONB 배선 + total). **합불은 커트라인 사후 계산**:
  - **과락 즉시판정**: 한 과목 40 미만 → "과락 탈락"(확정 가능, 법정 floor).
  - **합격 추정**: 평균/실측 cut_line 대비 → "합격권 추정"(상대선발이라 확정 아님).
  - **cut_line 미공개 연도/미정**: **"판정 대기"** 표시(에러 아님).
  - status 자동값은 derived(과락=failed 후보), 최종 status는 자가신고/합격증 검증 유지.
- **2차(`next_exam_round='second'`)**: **합격여부(status) + 점수 입력**(필수과목 점수, 선택과목 P/F). 자가신고 중심(현행 유지).

### 4.3 ★ 동의 분리 보장 (법적)
- **시각·구조 구분**: 동의는 별 섹션 + 명확 헤더 + 각 항목(A/B) 개별 설명(placeholder 문구).
- **별도 명시 옵트인**: ConsentSection 자체 토글 → `/api/consent`. 목표·결과 저장 버튼과 **물리적으로 다른 컨트롤**.
- **독립 저장 = 3 action 분리(핵심)**: 한 Sheet여도 **블록마다 별 `fetcher.Form` + 별 action**:
  - 목표 → `/study/stats`(setNextExamPlan + upsertStudyGoals)
  - 시험결과 → 결과 upsert action(아래 4.4)
  - 동의 → `/api/consent`(setMyAnalysis/PoolConsent)
  → **목표/결과를 저장해도 동의 컬럼은 안 건드림**(저장 ≠ 동의). **동의 안 해도 목표·결과 저장됨.** 단일 통합 action 금지(동의 함의 방지).

### 4.4 재사용 (드리프트 방지)
- **목표**: `GoalFields` 추출(GoalSummaryBar에서) → stats 띠·허브 공유. action 재사용(`/study/stats`).
- **시험결과**: `upsertMyExamResult` **확장**(subject_scores 수용) + 입력 필드 `ResultFields` 추출 → `/me/exam-results`·허브 공유.
- **동의**: `ConsentSection` 그대로.
- 신규 폼 중복 생성 금지 — 전부 단일 소유.

### 4.5 트리거
- **목표 블록**: 차수·목표 **미설정 시** 대시보드 첫 방문에 허브 자동 오픈(온보딩성). 설정됨이면 자동 오픈 안 함(나그 금지).
- **시험결과**: 시험 후 시점 이벤트라 **상시 접근**(대시보드 "내 정보 설정" 버튼 항상). 자동 오픈 트리거 X.
- **동의**: 상시 토글(허브 내 + 기존 경로).
- → **자동 오픈은 "차수/목표 미설정"만**, 결과·동의는 상시 버튼.

## 5b. ★ 커트라인 예측 설계 (집단 점수 → 예측) — 별도 후속 단계

> **구현 순서: 입력 허브(과목별 점수 수집)가 먼저 → 데이터 쌓인 위에 예측은 별 단계.** (현재 과목별 점수 0건이라 예측 불가가 기본.)

### 5b.1 방법 + 재사용
- 입력된 **1차 과목별 점수가 누적** → **분포로 합격선 추정**. 1차는 상대선발(600명 3배수)이라 cut_line ≈ 선발 백분위 점수.
- **재사용(검증된 인프라)**: 분포·백분위 엔진 `buildHist`+`pickPercentile`(`exam-results/analytics.server.ts:393-434`) — 점수 배열만 넣으면 분포·중앙값·p25/p75. + 코호트 표본 수집 `.in("user_id", profileIds)`+range 페이징 패턴(`student-progress.server.ts:70-91`, ★유일 정렬키 필수 — mcq-pack-regen 메모). **신규는 "소스를 user_problem_attempts(정답률)→exam_results 점수로 바꾼 집계 함수"뿐.**
- **검증 기준**: `official-exam-stats.json`의 실측 cut_line과 예측을 대조(과대/과소 추정 점검).

### 5b.2 ★ 통계 신중 (책임 민감 — 합격은 인생사)
- **표본 가드**: N < K(예: `PASSER_BENCHMARK_MIN_SAMPLE`=10·`MIN_SAMPLE_FOR_DISTRIBUTION`=3 재사용) → **예측 숨김/미산출**(반 공통 약점 가드와 동형).
- **표본 편향 명시**: "**플랫폼 응시 학생 N명 기준 · 실제 합격선과 다를 수 있음**"(전국 모집단 아님).
- **참고용 표현(단정 금지)**: "추정 합격권/주의" 수준. **합불 단정·확정 판정에 직접 사용 금지**(자가신고/합격증이 본질).
- **누가 보나 + 동의**: 집단 점수 분포 = "내 점수 기여 → 집단 추정 열람"(대칭) → **B(pool) 게이트**(합격자 벤치마크와 동일 정합, viewer-B). A(my_analysis)는 "내 데이터로 내 분석"이라 집단 집계엔 부적합. (강사/전체는 익명 집계만, staff 별도.) ← 신규 기능 동의 범주는 설계 결정이나 **B 권장**.
