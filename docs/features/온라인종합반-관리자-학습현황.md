# 온라인 종합반 — 관리자 학생 학습현황 (점검·설계)

> 상태: 점검·설계 문서 (코드 0). 제안 feature ID: **feat-7-040** (SPEC 등록은 착수 시).
> 작성: 2026-06-29. 세 관점(조망·개별·신호) + ★보안·동의 + 우선순위.

## 0. 요약 (TL;DR)

- **3관점이 이미 상당 부분 구현돼 있다.** 신규 구축이 아니라 **갭 보완 + 신호 고도화 + ★보안/동의 정합**이 본 과제의 실체.
  - 조망(반 전체): `admin-cohort-stats` + `admin-cohort-progress` — 평균 KPI·정답률 분포·과목별·상하위·주간추이·SRS 집계.
  - 개별(학생): `admin-student-detail` — 진도·정답률·반평균비교·합격예측·SRS·OX약점진단·상담코멘트.
  - 신호(이상): `admin-at-risk` + `getAtRiskStudents`/`getCrossCohortAtRisk` — riskScore(정답률·풀이량·비활성) + 합격자 baseline.
- **자기 반 게이트(읽기)는 일관 적용**됨: 모든 staff 읽기 경로가 `roleAtLeast(role,"manager") || cohort.ownerId === user.id`. instructor=본인 소유 반만, manager·admin=전체(의도).
- ★ **핵심 발견 2가지 (가치·위험 높음)**:
  1. **동의/법무 갭** — staff가 학생 학습데이터를 보는 경로에 **동의(consent) 체크가 전무**하고, **법무 문서(약관/방침)에 강사 열람 근거 조항이 없다.** (현 설계 = 권한 게이트만으로 통제.)
  2. **보안 쓰기 구멍** — `at-risk-notify.tsx`가 owner 재검증 없이 **임의 학생에게 알림을 발송**할 수 있다(데이터 누출은 아님, 메시지 발송 구멍).
- **신설 가치 높은 것** — 이상 신호의 **추세/델타**(정답률 급락·진도 정체·활동 급감). 현재는 절대값 스냅샷 + 합격자 대비뿐, **개인 시계열 변화 감지가 없다.**
- **개별 뷰 갭(저비용 재사용)** — 마스터리·게임화(레벨/스트릭)·공부량·실제 응시결과. 전부 `userId` 인자를 받아 그대로 재호출 가능.

### 1.4 보안·권한 현황

- **읽기 경로(학습데이터 열람)**: 자기 반 게이트 **일관·안전**. instructor는 `owner_id===user.id`인 반/멤버만, manager·admin 전체(의도). 다른 반 학생을 "보는" 구멍 **없음**.
- ★ **쓰기 경로 횡적 구멍**: `admin/api/at-risk-notify.tsx` — role 게이트(`getStaffRole`)만 있고 **owner 재검증 없음**. 임의 `profileIds` CSV를 POST하면 자기 반이 아닌 학생에게도 인박스 알림 발송 가능. UI는 게이트된 목록에서 채우지만 action이 그 값을 **재검증하지 않음**. `createUserNotifications`도 수신자 게이트 없음(DB 백스톱 부재). (동일 유형: `announcement.tsx`·`curriculum.tsx`의 임의 audience/cohortId — 본 범위 밖이나 같은 계열.)
- **안전 확인된 쓰기**: `cohort-weak-problems.tsx`(owner 확인 O), `student-note.tsx`(create 시 `instructorOwnsStudent` O).
- **cron**(`inactive-alert`·`weekly-reports`): `CRON_SECRET` 게이트 + 수신자를 `owner_id`/본인으로 강제 — 시스템 발송이라 정상.
- **인프라 위생**: `cohort_members` RLS **DDL이 추적 SQL에 없음**, `docs/db-schema.md`(`member_id/instructor_id/role`)가 `database.types.ts`(`cohort_id/profile_id/joined_at/added_by`)와 **불일치**. self-read 정책 존재 여부와 무관하게 런타임은 전부 adminClient 우회 → 코드 게이트가 유일 방어선이라는 사실은 변함없음.

### 1.5 동의 현황 — ★ staff 뷰에 consent 체크 전무

- 동의 컬럼(전부 `profiles`, 정의 `exam-results/queries.server.ts`): `service_data_consent_at`(필수, PIPA 15①4 계약이행) / `my_analysis_consent_at`(A=내 분석, 기본 ON) / `pool_consent_at`(B=풀 기여↔비교 열람, 대칭).
- A/B 게이트(`hasMyAnalysisConsent`/`hasPoolConsent`)는 **오직 "학생 본인이 자기 데이터를 볼 때"**만 적용(stats·srs·dashboard·passer-trend). 전부 요청자 본인 `user.id`로만 호출 — 타 사용자 id 호출 경로 없음.
- **`app/features/admin/` 전체에서 consent grep = 0건.** staff가 진도·정답률·약점·SRS·OX진단·합격예측을 읽는 모든 경로에 동의 확인 부재.
- 법무 문서(`legal/docs/*.mdx`): 강사/코호트/모니터링 키워드 **약관·방침에 0건**. 학습데이터 처리는 "**회사가 본인 진단 + 가명집계**"로만 서술(약관 제6조) — 식별된 강사가 식별된 학생 진도를 보는 행위 수권 없음. 강사 열람을 다루는 유일 텍스트는 **합격증 파일 한정**(`analytics-consent.mdx:71`, 그나마 "법률 검토 전 임시 초안"). → **"종합반 등록=강사 관리 동의"의 텍스트 앵커가 현재 없음.**

## 2. 관점 ① 반 전체 조망 (설계)

**현황: 거의 완성.** `admin-cohort-stats`(평균·분포·과목별·상하위·주간추이·SRS)와 `admin-cohort-progress`(학생별 표)로 "반이 잘 굴러가나"를 한눈에 본다.

**보완(소):**
1. **반 공통 약점을 통계 화면에 편입.** `getCohortWeakNodes`(이미 존재, 현재 약점→문제배분 API에서만 사용)를 `admin-cohort-stats`에 "반 공통 약점 노드 top" 섹션으로 노출 → 강사가 보충 수업 주제를 즉시 파악. (재사용, 신설 0.)
2. **마스터리 분포**(선택) — 반 전체의 단원 마스터리 단계 분포(미진/학습중/익숙/마스터)를 집계해 "반의 정착도" 표시. `getNodeMastery`를 멤버별로 돌려 집계(비용 중간 → P3).

**판단**: 조망은 신규 가치 낮음(이미 충분). 약점 편입(1)만 저비용으로 가치 있음.

## 4. 관점 ③ 이상 신호 감지 (신설 로직)

**현황: 절대값 기반.** `getAtRiskStudents`의 riskScore = 정답률(0.5)·풀이량(0.3)·비활성일수(0.2) + 합격자 baseline gap. **개인 시계열 변화(추세)가 없다** — "원래 못하는 학생"과 "갑자기 무너지는 학생"을 구분 못 함.

**신설: 추세/델타 신호 (개인 시계열 변화 감지).** 기존 데이터에서 파생, 신규 테이블 0.

| 신호 | 정의 | 파생 원천 | 비고 |
|---|---|---|---|
| **접속 끊김** | `daysSinceActive ≥ N` (기존 비활성을 신호로 승격) | `lastActivityAt` | 이미 at-risk에 있음 — 추세 신호와 통합 |
| **정답률 급락** | 최근 2주 정답률 − 직전 2주 정답률 ≤ −X%p | `user_problem_attempts` 주별(=`getCohortAccuracyTrend` 개인판) | ★표본 가드 |
| **진도 정체** | 최근 N일 신규 조문열람·신규 문제 ≈ 0 (직전 대비 급감) | `study_sessions`·`user_problem_attempts` 일별 | "활동은 있는데 진도 0"도 포착 |
| **활동 급감** | 최근 주 공부량 / 직전 주 ≤ Y (예: 0.4배) | `getDailyStudyStats`→`weeklyStudyMs`/`studyDeltaPct` (이미 게임화에 있음) | 게임화 델타 재사용 |

**★ 표본·임계 가드 (오탐 최소 — 학기 초·소수):**
- **최소 활동 이력 요구**: 직전 구간에 시도 ≥ K(예: 풀이 10건), 접속일 ≥ M. 데이터 희소(신규·학기 초)면 신호 **발화 금지**(=관찰 보류, 위험 아님).
- **델타는 비율+절대 동시 충족**: 정답률 급락은 "−X%p **그리고** 직전 절대값 ≥ 하한"(이미 낮던 학생의 노이즈 제외).
- **신호 강도 단계화**: 단일 신호=관찰, 복수 신호 동시=주의/위험. 기존 riskLevel(고/중/저)에 **추세 신호를 가산**(별도 점수 아니라 reasons에 합류).
- **합격자 baseline은 데이터게이트 유지**(실합격자 표본 부족 시 baseline 비교 비활성 — 기존 `isPasserBenchmarkEnabled` 재사용).

**설계 형태**: `getAtRiskStudents`/`getCrossCohortAtRisk`에 추세 신호를 **가산**(새 화면 아님). reasons에 "정답률 2주새 −18%p", "공부량 직전주 대비 −60%", "5일째 진도 정체" 등 **사람이 읽는 사유** 추가 → 강사가 "왜 위험인지" 즉시 이해. 개인 추세는 `admin-student-detail`에도 미니 차트로 노출(3절 공부량 추세와 공유).

**판단**: 세 관점 중 **신규 가치 최고**. 기존 at-risk는 "낮은 정답률"만 잡지만, 추세는 "무너지기 시작한 학생"을 조기 포착(개입 타이밍이 핵심).

## 5. ★ 보안·동의 (설계)

### 5.1 자기 반 게이트 — 읽기는 유지, 패턴 표준화
읽기 경로는 이미 안전. 추가 작업 시(개별뷰 갭 보완·신호)에도 **동일 패턴 강제**: `roleAtLeast(role,"manager") || cohort.ownerId===user.id`. 새 함수가 `profileId`를 받으면 `admin-student-detail`의 `cohort_members×owner_id` 소유 확인을 **반드시 선행**(미적용이 곧 횡적 누출).

### 5.2 at-risk-notify 쓰기 구멍 — 닫기 (P0)
`at-risk-notify.tsx` action에서 발송 직전 **수신자 owner 재검증**: 요청 `profileIds`가 전부 caller의 소유 반(또는 manager+) 멤버인지 `cohort_members×owner_id`로 확인, 아니면 거부/필터. (UI 신뢰 금지 — action이 단독 방어선. 과제·상담 "쓰기 게이트 누락"과 동일 계열 수정.) 동형 `announcement`/`curriculum` audience도 같은 백필 대상(별건).

### 5.3 동의 모델 — 종합반 = "계약 이행"(별도 opt-in 아님)
- **결론: staff 열람에 A/B식 동의 게이트를 새로 두지 않는다.** 온라인 종합반은 "담당 강사에게 **지도받기로 등록**"하는 서비스 → 강사가 수강생 학습현황을 보는 것이 **계약 이행 그 자체**(과외 선생이 숙제를 보는 것과 동형). A/B는 **2차 활용(분석·풀 비교)** 동의라 성격이 다르고, 학생이 "지도받기"를 opt-out하면 종합반이 성립하지 않음.
- 즉 코드상 추가 consent 체크는 **불필요**하며, 현 모델(필수 `service_data_consent_at` + owner 게이트)이 올바른 메커니즘. ★단 아래 5.4 텍스트 앵커가 채워져야 `service_data_consent_at`의 계약이행 근거가 성립.

### 5.4 법무 텍스트 갭 — 명시화 (사용자 법률검토 영역)
현재 약관·방침에 "강사 열람" 근거가 **없다**(1.5). 보완 필요(코드 아님, **사용자 법률검토**):
- **약관/방침**에 "**담당 강사·운영자가 지도 목적으로 수강생의 학습현황(진도·정답률·약점·복습·응시결과 등)을 열람**한다"를 명시 → `service_data_consent_at`(계약이행)의 텍스트 앵커 확보.
- `analytics-consent.mdx`("법률 검토 전 임시 초안")의 합격증-한정 열람 조항을 **학습현황 일반으로 확장**.

### 5.5 투명성 (PIPA 원칙 + 신뢰) — 선택, 저비용
동의를 새로 받지 않더라도 학생에게 **고지**: 대시보드/온보딩에 "담당 강사 ○○○님이 학습현황을 봅니다"(읽기 전용 안내). 강사 열람을 숨기지 않음 = 신뢰 + 투명성 의무 충족. (코드 소, 텍스트 위주.)

### 5.6 민감도 차등 노출
- 진도·정답률·약점·SRS·마스터리 = 지도 핵심 → 자연 노출.
- **실제 응시결과(자기보고 합/불·점수)·공부량 백분위** = 가장 개인적 → 5.4 텍스트 + 5.5 고지 **이후** 노출. (백분위는 학생 본인 화면에서 pool 동의 전제였음을 감안 — 관리자뷰에선 "지도 목적 열람"으로 근거가 다르나, 노출 톤은 신중.)

## 6. 우선순위 + 단계안

직감(조망→개별→신호)을 **조정**한다: 조망·개별 골격이 이미 있어 신규 가치가 낮고, **보안/법무 리스크와 신호 고도화가 가치·시급성 최고**.

| 단계 | 내용 | 가치 | 규모 | 재사용/신설 |
|---|---|---|---|---|
| **P0 (보안·법무, 선행/병행)** | (a) `at-risk-notify` owner 재검증(5.2) · (b) 약관/방침 강사열람 명시(5.4, 법률검토) · (c) 학생 고지(5.5) | 위험 차단·컴플라이언스 | 소(코드)+텍스트 | 수정 |
| **P1 (개별 뷰 갭)** | `admin-student-detail`에 마스터리·게임화·공부량·실제응시결과 추가(3절) | 상담·지도 즉효 | 소(1일급) | **전부 재사용**(userId 함수) |
| **P2 (이상 신호 고도화)** | at-risk에 추세/델타 신호(급락·정체·급감) + 표본가드(4절) | **최고**(조기 개입) | 중 | 파생(신규 테이블 0) |
| **P3 (조망 보완)** | `admin-cohort-stats`에 반 공통 약점(`getCohortWeakNodes`) 편입 + (선택)마스터리 분포(2절) | 중 | 소~중 | 재사용 |

**근거:**
- **P0 먼저**: 쓰기 구멍은 즉시 닫고, 법무 명시는 리드타임(법률검토)이 있어 일찍 착수. P1~P3가 "학생 데이터를 더 보여주는" 작업이므로 **그 전에 열람 근거(법무)·투명성을 정렬**하는 게 순서상 옳음.
- **P1 다음**: 가장 싸고(전부 재사용) 상담 효과 즉시. 신호(P2)와 공부량 데이터를 공유하므로 토대도 됨.
- **P2**: 신규 가치 최고지만 표본 가드 설계가 필요(중간 규모) → P1 뒤.
- **P3**: 조망은 이미 충분, 약점 편입만 가성비.

**완료 조건 매핑**: ①현황(1절) ②조망(2) ③개별(3) ④이상 신호(4) ⑤보안·동의(5, 자기 반 게이트 + 동의 검토) ⑥우선순위·단계안(6). 코드 0(설계만).
