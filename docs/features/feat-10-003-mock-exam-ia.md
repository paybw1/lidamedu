# feat-10-003 — 모의고사 IA 정리 (Phase C)

> 모의고사 체계 정비 **Phase C**. 기능 추가가 아니라 **네비게이션 재배치** — 흩어진 모의고사 진입점을 한 메뉴로 모은다.
> 검토용 설계문서. C 는 DB 변경 없음 — 검토 후 바로 구현.

## 1. 목표

1차 모의고사(`mcq_packs` exam 모드)와 2차 모의고사(온라인 GS)가 **서로 다른 메뉴에 흩어져** 있다. 1차는 학습정보, 2차(GS)는 커뮤니티 메뉴 아래다. 사용자가 "모의고사를 보려면 어디로?" 가 명확하지 않다. C 는 **"모의고사" 메뉴를 신설**해 둘을 한곳에 모은다.

## 2. 현재 IA

상단 네비게이션 7개: 대시보드 · 학습관리▾ · 학습과목▾ · 학습보조▾ · 학습정보▾ · 커뮤니티▾ · 운영자.

| 항목 | 현재 위치 | 라우트 |
|------|-----------|--------|
| 1차 모의고사 (객관식 팩) | 학습정보 ▾ "객관식 문제" | `/latest/mcq` (기출·모의 한 색인, 구분 필터) |
| 2차 모의고사 (온라인 GS) | 커뮤니티 ▾ "온라인 GS" | `/gs` |
| 객관식 기출 | 학습정보 ▾ "객관식 문제" | `/latest/mcq` (같은 색인) |
| 주관식 기출·문제 | 학습정보 ▾ "주관식 문제" | `/latest/essay` |

## 3. 제안 — "모의고사" 메뉴 신설

상단 네비게이션에 **"모의고사" 드롭다운**을 신설(학습정보 다음, 8번째). 데스크톱 `SimpleDropdown` + 모바일 `MobileGroup` — 기존 패턴 그대로.

**모의고사 ▾** — 1차는 종합/진도별로 나눈다(둘은 성격이 다르고 `mcq_packs.kind` 가 이미 구분).
- **1차 종합 모의고사** → `/latest/mcq?kind=mock_full`
- **1차 진도별 모의고사** → `/latest/mcq?kind=mock_progressive`
- **2차 모의고사 (온라인 GS)** → `/gs`

`/latest/mcq` 색인 loader 는 이미 `?kind=` 값(`mock_full`·`mock_progressive`·`past_exam`)을 처리한다 — **코드 변경 없이** 메뉴 링크의 쿼리만으로 목적별 진입이 된다.

**학습정보 ▾** — "객관식 문제"→**"객관식 기출문제"**(`/latest/mcq?kind=past_exam`), "주관식 문제"→**"주관식 기출문제"**(`/latest/essay`). 모의가 모의고사 메뉴로 빠졌으므로 학습정보 쪽은 기출로 개명.

**커뮤니티 ▾** 에서 "온라인 GS" 제거 → 공지사항 · 자유게시판 · 스터디 모집 · Q&A · 합격 후기. GS 라우트(`/gs`)는 그대로, 네비 위치만 모의고사로 이동.

## 4. 변경 목록 (라우트 이동·DB·코드 변경 없음)

- `navigation-bar.tsx` — `mockExamItems` 배열 신설 + 데스크톱/모바일 "모의고사" 드롭다운. `communityItems` 에서 "온라인 GS" 제거. `latestItems` 객관식·주관식 라벨을 "기출문제"로 개명.
- **그 외 변경 없음** — `/latest/mcq` loader 의 기존 `?kind=` 처리를 그대로 활용. C 는 사실상 `navigation-bar.tsx` 한 파일 작업. `/gs`·`/latest/mcq` 라우트·URL·북마크 모두 보존.

## 5. 결정 필요 사항 (검토 시 확인)

1. **상단 메뉴 8개** — 현재 7개에서 "모의고사" 추가 → 8개. 폭 여유는 충분(데스크톱). 괜찮은지.
2. **"기출문제"** — (확정) 학습정보의 "객관식 문제"·"주관식 문제" → "객관식 기출문제"·"주관식 기출문제" 로 개명.
3. 2차 모의고사 = 온라인 GS — 메뉴 라벨 "2차 모의고사 (온라인 GS)" 병기로 확정.
