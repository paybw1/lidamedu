# feat-2-027 — 동기부여 게임화 설계 (자기 진척 + 공부량 구간)

> **상태**: 🔲 설계 (코드 0). 본 문서는 설계만 — 구현은 §5 단계안에 따라 별도 착수.
> **목표**: 기존 학습 지표를 "게임 옷" 입혀 **꾸준함·질 높은 학습**을 유도. 단, 게임화의 흔한 함정(질 떨어뜨리는 양치기·스트릭 죄책감·허영 뱃지·순위 경쟁)을 **설계에 내장해 회피**.

## 0. 설계 원칙 (가드레일)

게임화는 **외적 보상이 내적 동기를 밀어내는(crowding-out)** 위험이 있다. 그래서 본 설계의 모든 메커닉은 아래 4원칙을 만족해야 하며, §4에서 메커닉별로 검증한다.

| 원칙 | 의미 | 위반 예 (피함) |
|---|---|---|
| **질 보상** | 보상은 "정답률 + 복습 완료(파지)"에 연동. 문제 **수**만으로는 못 올라감 | 많이 풀수록 XP↑ → 쉬운 문제 반복·찍기 |
| **스트릭 가볍게** | 꾸준함은 격려하되 끊겨도 죄책감 최소·회복 가능 | "스트릭 끊김 0일부터" 압박 |
| **뱃지 = 학습 의미** | 모든 뱃지/단계는 실제 학습 성취에 연결 | "100일 로그인" 류 허영 지표 |
| **구간이지 순위 아님** | 비교는 백분위/구간("상위 30%")·나의 성장. 1~N 등수 없음 | 반 전체 리더보드 1등 다툼 |

**표시 위치 원칙**: 별도 "게임 화면"을 만들지 않는다. **`/study/stats`(학습현황)**·**`/dashboard`**의 기존 카드를 증강한다 — 게임 메커닉이 학습 데이터와 한 화면에 붙어 있어야 "학습 의미 연결" 원칙이 지켜진다.

### 1.2 레벨·단계·마스터리 개념이 있나? → **없음. 전부 신설.**

`database.types.ts` 전수 grep 결과 `level / mastery / badge / achievement / xp / trophy / leaderboard` **게임화 컬럼 0건**. `profiles`에 해당 컬럼 없음. 오인 주의(전부 게임화 아님):
- `article_level`(조문 계층 part/chapter/…), `gs_points_*`(2차 **논술 채점** 보상 원장 — 도메인 다름, 재사용 부적합), `problems.total_points`(시험 배점), `user_bookmarks.star_level`(즐겨찾기 별점).
- **마일스톤**(`MilestonesCard` stats.tsx:594, 25/50/75/100% 🥉🥈🥇🏆)은 존재하나 **순수 UI 파생(영속 없음)**.
- **스트릭**은 계산기(`getDailyStudyStats.currentStreak`)·표시가 있으나 **영속 저장 없음**.

**결론**: 마스터리·레벨·약점정복·뱃지는 **신설**. 스트릭은 계산기 재사용 + (최장기록) 영속만 추가.

### 1.3 공부량·코호트 백분위를 낼 수 있나? → **그렇다(강한 선례 존재).**

- 멤버별 집계: **`listCohortProgressSummary(cohortId)`** 가 멤버당 `{problemsAttempted, problemsCorrect, accuracyPct, articlesViewed, ...}` yield(adminClient). **`getCohortAggregateStats`** 가 평균·분포 버킷·상/하위 5명까지 산출 — `sortable` 배열에 **rank만 추가하면 "상위 N%" 즉시** 도출. 표본 게이트 `AVG_ACCURACY_MIN_ATTEMPTS=5`.
- 백분위 RPC 선례: `mcq_exam_attempt_stats`(getExamAttemptRanking, mcq-exams/queries.server.ts:607) → `{rank, totalTakers, percentile, zScore}` 이미 DB가 산출.
- **공부량(학습시간) 백분위만** 멤버별 집계에 시간 합산이 아직 없음 → `study_sessions` 시간 합산 헬퍼 신규 필요(`passer-srs-benchmark.server.ts:90`의 `.in("user_id", allIds)` bulk 패턴 그대로 적용).
- **재료 한계 메모**: ① "공부량"은 현재 **문제 풀이 시간만**(조문/판례 열람 시간 제외, `study_sessions.duration_ms` 미기록). ② `daily_study_stats` 사전집계 테이블은 **미존재**(전부 실시간 계산) — 게임화 지표가 많아지면 성능상 도입 검토 대상. ③ streak·activeDays는 "문제 푼 날" 기준(열람만 한 날 제외).

## 2. 자기 진척 메커닉 설계 (성장)

> 핵심: **남과 비교 없이 "어제의 나보다"** 성장하는 축. A(my_analysis) 동의만으로 동작(코호트 불필요).

### 2.1 단원 마스터리 — `학습 중 → 익숙 → 마스터` (★질 게이트)

단원(체계도 노드)별 3단계. **문제 수가 아니라 정답률 + 복습 완료(파지)로 게이트.**

| 단계 | 게이트 조건(제안, 전부 상수 SSOT) | 근거 |
|---|---|---|
| **학습 중** (Learning) | 노드 시도 ≥ 1 | 손댄 단원 |
| **익숙** (Familiar) | 노드 정답률 ≥ `MASTERY_FAMILIAR_ACC`(70%) **AND** 시도 ≥ `MASTERY_MIN_ATTEMPTS`(5) | 표본 + 질 |
| **마스터** (Mastered) | 정답률 ≥ `MASTERY_MASTERED_ACC`(85%) **AND** 노드 문제 SRS `reps ≥ 2`(간격 1회 이상 통과) **AND** overdue due 없음 | 질 + **시간 두고 파지**(찍기·벼락치기 차단) |

- **재사용**: 노드별 정답률 = `getSessionWeakNodes`(:2833)/`getWeakNodes` 로직. SRS 파지 = `user_problem_srs`(reps·next_due_at). 표본 게이트 `MIN_ATTEMPTS=5`는 기존 약점 진단과 동일 상수 체계.
- **약점과 직결**: "마스터" 노드 = "약점" 노드의 반대. 같은 `weaknessScore` 파이프라인의 양 끝.
- **표시**: `/subjects/{과목}` 체계도에 단계 칩(학습 중/익숙/마스터), `/study/stats`에 "마스터 단원 N개" KPI.
- **함정 회피**: 마스터는 정답률+SRS 통과라 **양치기·찍기로 못 올라감**.

### 2.2 전체 레벨 — 의미 있는 수험 성장 단계

레벨 = **마스터한 단원 수**(주축) + 전체 정답률·진도(보조). 누적 문제 수 XP 아님.

- **제안 산식**: `levelScore = 마스터단원수×3 + 익숙단원수×1`(질 가중) → 구간 매핑.
- **명칭(학습 의미 연결)**: 등번호 대신 수험 단계 메타포 — 예: `입문 → 기초 다지기 → 단원 정복 → 실전 감각 → 합격권`. (숫자 레벨은 허영화 위험 → 단계명 권장.)
- **재사용**: 마스터/익숙 단원 수(§2.1) + `getOverallProgress`·`getDashboardKpis` 정답률.
- **함정 회피**: 레벨이 **질 게이트된 마스터 수**에 묶여 있어, 레벨업하려면 단원을 실제로 정복해야 함.

### 2.3 약점 정복 — "정복!" 표시 (약점 분석 직결)

가장 동기부여 강한 축: **약점 노드가 약점에서 빠지면 "정복" 이벤트**.

- **판정**: 노드가 약점 랭킹(`weaknessScore` 상위)에서 벗어남 + 정답률이 `익숙` 임계 상향 돌파 → "정복".
- **영속 필요 최소화**: 주기 스냅샷(`pass_prediction_snapshots` 패턴 재사용)으로 "이전 약점 → 현재 정복" 비교. 또는 경량 테이블 `user_node_conquest(profile_id, node_id, conquered_at)`.
- **표시**: `/study/stats` 약점 탭 상단 "이번 주 정복한 단원 🎯 N개", 약점 매트릭스에서 정복 노드 강조.
- **함정 회피**: 보상이 **실제 약점 해소**에만 발생 → 학습 의미 100% 연결.

### 2.4 스트릭 — 넣되 가볍게·회복 가능

- **재사용**: `getDailyStudyStats.currentStreak`(:1721, 이미 계산). 영속은 **최장기록만** 신규(`longest_streak`).
- **★가볍게 설계**:
  - **주간 케이던스를 1차 프레이밍**: "이번 주 X일 학습"(주 N회 목표) — 하루 빠짐에 0 리셋되는 일일 스트릭 압박 회피.
  - **회복 가능**: `streak freeze`(주 1회 자동 보호) 또는 "어제 못 했어도 오늘 하면 이어짐"(현 계산기가 이미 오늘 0이면 어제부터 허용).
  - 현재 스트릭은 부드러운 표현(🔥 N일), **끊김 알림·죄책감 문구 없음**.
- **함정 회피**: 일일 강박 대신 주간 케이던스 → 꾸준함 격려하되 벌하지 않음.

## 3. 공부량 구간 (가볍게·구간·동의 게이트)

> ★**순위 아님**. 구간/백분위 + 나의 성장. ★**코호트 비교는 B(pool) 동의 게이트**.

### 3.1 구간(밴드) — 1~N 등수 금지

- **표시**: "상위 30%" · "평균 이상" 같은 **구간**만. 정확한 등수·이름 목록 노출 금지.
- **밴드 예**: `상위 10% / 상위 30% / 평균 이상 / 평균권 / 평균 이하`(격려 톤, "이하"도 비난 아닌 "성장 여지").
- **재사용**: `getCohortAggregateStats`의 `sortable` 정렬 + rank→백분위. 정답률·풀이량은 `listCohortProgressSummary`로 즉시. **학습시간 백분위만** `study_sessions` 시간 합산 헬퍼 신규.

### 3.2 나의 성장 (비교 없이도 동작 — 기본값)

- "지난주 대비 +20% 풀이량", "정답률 68→74%" 등 **본인 시계열**. `getDailyStudyStats`(주별 버킷)·`getUserAccuracyTrend`(:2706) 재사용.
- **A(my_analysis) 동의만으로 동작** — 코호트·B 동의 불필요.

### 3.3 ★동의 게이트 (B/pool, 대칭)

코호트 백분위는 다른 코호트 비교 기능과 동일하게 **`hasPoolConsent`** 게이트.

- **컬럼**: A = `profiles.my_analysis_consent_at`(기본 ON, 내 분석) / B = `profiles.pool_consent_at`(opt-in, 기여↔열람 대칭) / 필수 = `service_data_consent_at`.
- **게이트 헬퍼**: `hasPoolConsent`(exam-results/queries.server.ts:128, **fail-closed**). 기존 viewer-B 강제 위치(dashboard.tsx:235, study/srs.tsx:99, study/stats.tsx:316, passer-trend.tsx:35)와 동일 패턴.
- **규칙**:
  - B 동의 O → 코호트 구간/백분위 노출(+ 본인 데이터도 코호트 집계에 기여).
  - B 동의 X → **나의 성장만**(§3.2). 코호트 구간 숨김 + 안내("동료 비교를 보려면 풀 기여 동의가 필요해요" — 대칭 설명).
- **대칭 유지**: 보는 것 = 기여하는 것. 기존 합격자 벤치마크와 정확히 같은 모델([[passer-consulting-copy-gate]]).

### 3.4 함정 회피

- 순위 대신 **구간**(3.1) → 1등 경쟁·하위 모욕 회피.
- 기본은 **나의 성장**(3.2) → 미동의자도 가치, 비교 강요 없음.
- B **동의 게이트**(3.3) → 비교 불안은 본인 선택(opt-in)일 때만.

## 4. 함정 회피 — 메커닉별 검증표

| 메커닉 | 질 보상 | 스트릭 가볍게 | 뱃지=학습의미 | 구간≠순위 |
|---|:--:|:--:|:--:|:--:|
| 단원 마스터리(§2.1) | ✅ 정답률+SRS 게이트 | — | ✅ 단원 정복 | — |
| 전체 레벨(§2.2) | ✅ 마스터수 기반(수≠) | — | ✅ 단계명 | — |
| 약점 정복(§2.3) | ✅ 약점 해소만 보상 | — | ✅ 약점 직결 | — |
| 스트릭(§2.4) | — | ✅ 주간 케이던스·회복 | ✅ 꾸준함 | — |
| 공부량 구간(§3) | — | — | — | ✅ 백분위/구간·동의게이트 |

**추가로 막는 함정**:
- **메트릭 게이밍**(시간 늘리기·쉬운 문제 반복): 마스터/레벨이 정답률+약점 기반이라 무의미.
- **외적보상 crowding-out**: 모든 보상이 실제 학습 신호(정답률·파지·약점해소)에 연동 — 학습과 분리된 점수 없음.
- **비교 불안**: 구간+동의 게이트+기본 본인성장.
- **허영 뱃지**: "로그인 N일" 류 없음. 전부 학습 성취.

## 5. 설계 선택지 + 단계안

### 5.1 선택지 (조합) + tradeoff

| 옵션 | 포함 | 신규 영속 | 동의 | 위험 | 매력 |
|---|---|---|---|:--:|:--:|
| **A 최소(자기진척)** | 단원 마스터리 + 약점 정복 | 거의 0(대부분 파생) | A만 | **낮음** | 중 |
| **B 중간(+성장서사)** | A + 전체 레벨 + 스트릭 영속 | `user_gamification`(레벨·최장스트릭·정복) | A만 | 중 | 중상 |
| **C 전체(+사회적)** | B + 공부량 구간(코호트 백분위) | + 학습시간 합산 헬퍼 | A + **B 게이트** | 중상 | 상 |

- **A**: 기존 데이터에서 파생만 → 표시 추가에 가깝고 동의/코호트 이슈 없음. 가장 안전. 단 "성장 서사·사회적 끌림" 약함.
- **B**: 레벨/스트릭 영속으로 "성장 누적" 서사. 경량 테이블 1개. 코호트·동의 무관이라 여전히 안전.
- **C**: 코호트 구간으로 몰입↑. 단 B(pool) 동의·코호트 인프라·시간합산 헬퍼·비교불안 관리 필요 → 위험 가장 큼.

### 5.2 단계안 (위험 낮은 것부터)

> 각 단계 독립 배포·검증 가능. 단계마다 `/study/stats`·`/dashboard` 증강.

- **Phase 1 — 자기 진척(A 옵션)** 🔲
  - 단원 마스터리(§2.1) + 약점 정복(§2.3). **대부분 파생**(기존 노드 정답률·SRS·약점 함수 재사용), 영속은 정복 스냅샷 정도.
  - 상수 SSOT(`app/core/lib/constants.ts`)에 마스터리 임계 정의. A 동의 게이트(`hasMyAnalysisConsent`, 기존).
  - 완료조건: 체계도/통계에 단계 칩 + "정복 N개". 코드 외부 의존 0.
- **Phase 2 — 성장 서사(B 옵션)** 🔲
  - 전체 레벨(§2.2, 단계명) + 스트릭 영속(최장기록·주간 케이던스).
  - 신규 테이블 `user_gamification(profile_id PK, level_key, longest_streak, last_active_date, conquered_count, updated_at)` + RLS 본인 R/W. `recordProblemAttempt`/일배치에서 best-effort 갱신(SRS 패턴).
  - 완료조건: 대시보드 성장 카드(단계·최장스트릭).
- **Phase 3 — 사회적 구간(C 옵션)** 🔲
  - 공부량 구간(§3): `getCohortAggregateStats` 재사용 + rank→백분위 + 학습시간 합산 헬퍼. **B(pool) 동의 게이트**(`hasPoolConsent`), 미동의 시 나의 성장만.
  - 완료조건: 코호트 구간 카드(동의 O) / 본인 성장 카드(동의 X), 대칭 검증.

### 5.3 권장

**Phase 1부터.** 신규 스키마·동의·코호트 없이 기존 지표를 질 게이트로 "성장"으로 번역 — 위험 최저이면서 약점 분석과 직결돼 학습 가치가 즉시 명확. Phase 2(서사)·3(사회적)은 Phase 1 반응을 보고 점진 확장.
