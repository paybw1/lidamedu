## 0. 한 문장 판단

> 이 스펙은 **이미 완성된 데이터 모델(feat-11) 위에 얹는 운영자 UX·워크플로우가 85%**이고, **구조적으로 새로운 것은 딱 하나 — 콜러스 "콘텐츠 라이브러리 + 강의그룹" 레이어**다. 나머지는 (a) 흩어진 관리 화면의 통합, (b) 컬럼 몇 개, (c) 독립적인 신규 기능(리뷰·HTML 에디터)일 뿐이다.

즉 **새 도메인을 새로 짓는 프로젝트가 아니라, 있는 뼈대에 운영 살을 붙이는 프로젝트**다. 핵심은 "무엇을 새로 만드나"가 아니라 "무엇을 통합하고, 그 하나의 새 레이어를 어떻게 넣나"이다.

## 2. 핵심 설계 판단 2가지

### 판단 A — 콘텐츠 라이브러리를 신규 레이어로 넣는다 (이 프로젝트의 유일한 구조 변경)

**현재**: `lesson_videos`가 콜러스 `drm_video_id`를 **인라인 저장**하고 재생시간은 **수동 입력**. 같은 영상을 다른 강의에 쓰려면 키를 다시 타이핑 → 중복·오타·모수 불일치.

**스펙 요구**: 콜러스 영상을 한 번 동기화해 라이브러리에 두고, **여러 강의·플랫폼에서 재사용**하며, 재생시간·인코딩 상태를 **자동 수집**.

**결정**: 콜러스 미디어 자산을 회차에서 **분리**하는 카탈로그 2테이블을 신설하고, `lesson_videos`를 인라인 키 → **콘텐츠 참조**로 재배선한다.

```
video_contents (콜러스 콘텐츠 라이브러리, 동기화 대상)
  content_id PK · drm_provider · content_key(콜러스 mckey, unique) ·
  title · original_filename · duration_seconds(자동) · encoding_status ·
  group_id FK content_groups nullable · use_status(사용/중지) · is_active(신규연결 가능) ·
  synced_at · created_by
        │
content_groups (강의그룹)
  group_id PK · name · year · subject_code · instructor_id · exam_track(1차/2차) ·
  course_type · book_title · staff_memo
        │
lesson_videos  ← content_id FK 추가 (drm_video_id/duration 은 콘텐츠에서 파생)
```

- **하위호환**: 마이그레이션이 기존 `lesson_videos` 행마다 `video_contents` 행 1개 생성(키·duration 이관) 후 `content_id` 연결. 재생·회계 경로 무변경(playback 은 여전히 content 의 key 로 서명).
- **재사용**: 한 `video_contents`를 여러 `lesson_videos`가 참조. 영상 교체 = 회차의 content_id 만 새 콘텐츠로(수강기록·진도율 유지 — 기존 append-only 그대로).
- **동기화**: 콜러스 콘텐츠 API → `video_contents` upsert(content_key unique 로 중복방지), 인코딩 상태·duration 자동. **[전제] 콜러스 콘텐츠 조회 API 접근 필요**(재생 토큰 API 와 별개 — 확인 대상).

이 한 레이어가 스펙의 "콘텐츠 관리" 섹션 전체(동기화·강의그룹·재사용·자동 재생시간·인코딩 상태)를 관통한다. **먼저 깔아야 나머지 콘텐츠 운영이 수작업을 벗어난다.**

### 판단 B — "강의등록"은 통합 셸이지, 새 모델이 아니다

**현재**: 하나의 "강의"가 `course_series` + `courses` + `subscription_plans` + `plan_policies`에 흩어져 **3개 관리 화면**(admin-lms-courses / admin-lms-course-detail / subscriptions/admin-plans)에 분산.

**스펙 요구**: 기본정보 최초 저장 → 판매정보·수강정책·강의소개·강의목차·교재·변경이력 **탭 활성화** 단일 플로우.

**결정**: **기존 테이블·액션 위에 탭 오케스트레이션 셸**을 씌운다. 데이터 모델·뮤테이션 경로를 **복제하지 않는다**(DRY·"뮤테이션 경로 동결"·"통합 우선").
- 탭 = 기존 화면들의 재배치(기본정보=series/course, 판매정보·수강정책=plan/policy, 강의목차=lesson/video, 교재=materials).
- "기본정보 저장 전 목차 비활성" = course_id 생성 여부로 게이트(이미 성립).
- 신규는 **셸 + 소수 컬럼(유형·카테고리·복수강사·메모)**뿐.

## 3. 단계별 로드맵 (우선순위 × 의존성)

> **진행 현황(2026-07-21)**: Phase 1~4 구현 완료·배포. Phase 5(콜러스 업로드 등)만 잔여.
> - **P1 콘텐츠 라이브러리** ✅ — video_contents/content_groups + lesson_videos.content_id 재배선 + 콜러스 동기화(수동 버튼 + **cron 자동 + content_sync_logs 오류로그**) + 진도율 컬럼 승격.
> - **P2 강의 등록 UX** ✅ — 탭 셸(기본정보/강의목차/변경이력) + course_categories(대/중/소) + course_instructors(복수강사) + course_audit_logs + courses 컬럼(course_type/category_id/admin_memo/is_visible/public_no) + 강의복사(클론) + 노출토글·배지.
> - **P3 HTML 에디터** ✅ — **소스 우선 하이브리드**(비주얼 contentEditable ↔ 소스 textarea ↔ 미리보기, 저장값=원본 HTML 단일소스로 임의 HTML/CSS 무손실) + 이미지 업로드 + 표/유튜브/링크/색 + 전체화면. admin-plans 수강신청 상세에 적용.
> - **P4 커머스 부가** ✅ — course_reviews(수강평 plan/교재평 book, 별점·베스트·블라인드·신고·운영자답변, **구매자 게이트=action**, RLS author 기준) + /admin/lms/reviews 모더레이션 + 도서 무료배송 임계(app_settings free_shipping_threshold_krw, cart-resolve 적용, 배송관리 설정) + 과세/면세는 books.tax_free 기존 활용.

각 단계는 독립 배포 가능. 하드스톱 — 단계 완료·검토 후 다음 단계.

### Phase 1 — 콘텐츠 라이브러리 (구조 코어, 최우선)
`video_contents` + `content_groups` 신설, `lesson_videos.content_id` 재배선(하위호환 마이그레이션), 콜러스 동기화 job(+동기화 오류 로그), 관리자 **콘텐츠관리** 화면(목록·검색·상태필터·강의그룹 CRUD·연결현황·영상확인). 진도율 인정 기준을 콘텐츠 컬럼으로 승격(하드코딩 제거).
→ **[전제] 콜러스 콘텐츠 조회 API 확인.** 없으면 "수동 등록 + duration 수기"로 라이브러리만 먼저(동기화는 후속).

### Phase 2 — 강의 등록 운영 UX 통합
탭 등록 셸(기본정보/판매정보/수강정책/강의소개/강의목차/교재·자료/변경이력). 신규 컬럼: 강의 유형(무료특강 포함)·카테고리 대/중/소분류(taxonomy)·담당강사 복수(join)·course 관리자 메모·강의 고유번호(사람이 읽는). 강의복사(에디션 클론, 수강기록 제외·비공개 생성). 노출설정·목록 배지. course 변경 이력 audit.

### Phase 3 — 통합 HTML 에디터 (★★★★ 독립 코어)
강의소개 상세페이지용 리치 에디터: 일반↔소스 모드 무손실 전환, 이미지 업로드·표·유튜브/iframe·링크·글자 크기/색·전체화면·미리보기·**모바일 HTML/CSS 보존**. 현재 `<textarea>` + `dangerouslySetInnerHTML` 대체.
→ **결정 포인트**: 성숙 라이브러리 채택(권장) vs 자체 구현. 스펙의 "소스↔일반 무손실·모바일 CSS 보존" 요구는 성숙 라이브러리(tiptap 계열) 강력 추천. XSS = 신뢰 경계(운영자 작성물, 학생 노출) 정책 필요.

### Phase 4 — 커머스 부가
수강평/교재평(별점·관리자답변·베스트·공개/비공개·신고·블라인드, **구매자 전용 작성** RLS). 도서 무료배송 임계(설정 + 도서 결제금액만 기준 계산). 무료지급 UX(회원↔강의 양방향 진입). 과세/면세 컬럼.

### Phase 5 — 잔여·후순위
관리자페이지 콜러스 업로드(★선택), 강의 변경이력 고도화, feat-11-005 M5 이관과 병행.

## 4. 결정 필요 (최소)

1. **콜러스 콘텐츠 조회 API** 접근 가능 여부 — Phase 1 동기화의 전제. (없으면 라이브러리 수동 등록으로 시작)
2. **HTML 에디터** — 성숙 라이브러리(권장) vs 자체 구현.
3. 착수 순서 — **Phase 1(콘텐츠 라이브러리) 우선** 권장. (다른 순서 선호 시 지정)

## 5. 하지 않을 것 (YAGNI / 통합 우선)

- 새 `products`/`courses` 병렬 데이터 모델 — 기존 plan/course 확장으로 충분(결제·할인·정산 이중화 금지).
- 회차 단위 판매(plan_lessons) — 요구 생기면 그때.
- 대칭 저장·중복 캐시(진도율·잔여배수·재고·매출은 전부 파생 유지).
- 강의그룹 없이 콘텐츠 재사용 우회(라이브러리부터 깔고 재사용).
