# 상표법 2차 주관식 모범답안 작성·검증 브리프 (feat-2-039, 에이전트용)

이 문서는 **한 문항을 맡은 에이전트**가 그대로 따르는 작업 지시서다. 설계 SSOT 는 `docs/features/feat-2-039-trademark-essay-answers-260917.md`, 규칙의 근원은 CLAUDE.md 「2차 모범답안·채점기준 작성 시」·Non-negotiable 11·12 다. 수험생이 그대로 학습하는 콘텐츠이므로 **그럴듯한 서술을 근거 없이 남기지 않는다.**

## 0. 입출력·완료 조건

- 입력: `tmp/essay/input/tm-<year>-<no>.json` — `problem_id`·`year`·`no`·`round`(변리사 2차 회차)·`points`·`body_md`(발문, 견본 이미지 자리는 `[img#N]`)·`images`(견본 이미지 목록)·`grading_notes`(채점위원 채점평, 있으면)·`instructor_files`(리담 강사 해설 텍스트 경로, 있는 회차만 — 논점·목차 참고용, 문장 복제 금지)·`existing`(B군만: 2026-07 강사해설 기반 생성분. **규칙 미반영 구본**이라 논점·판례 후보 참고용일 뿐, 문장·목차를 옮기지 않는다).
- 견본 이미지는 미리 PNG 로 받아 두었다: `tmp/essay/img/tm-<year>-<no>-<N>.png` (`[img#N]` 과 대응). 표장의 형태·문자·도형 구성이 쟁점이면 **Read 도구로 그 PNG 를 열어 직접 본 뒤** 답안에서 표장을 말로 묘사한다(발문 문장만으로 표장을 추측하지 않는다).
- 출력 3파일(모두 새로 쓴다):
  - `tmp/essay/tm-<year>-<no>.md` — 모범답안(model_answer_md)
  - `tmp/essay/tm-<year>-<no>.rubric.md` — 채점기준(grading_rubric_md)
  - `tmp/essay/tm-<year>-<no>.items.json` — rubric_items `[{"label": "...", "points": N}, …]`, points 합 = 총점
  - `tmp/essay/tm-<year>-<no>.report.md` — 작업 보고(§7 양식)
- 완료 조건: `node scripts/jagwa/essay-file-check.mjs --file tmp/essay/tm-<year>-<no>.md --law trademark --points <총점> --rubric tmp/essay/tm-<year>-<no>.rubric.md --items tmp/essay/tm-<year>-<no>.items.json` 이 **FAIL 0**(exit 0). WARN 은 분량 WARN(181.5자/점 초과)만 허용하되 가능하면 없앤다.
- **DB 는 읽기 전용 도구로만 접근한다.** `problems` 등에 쓰지 않는다. MCP supabase 툴은 쓰지 않는다.
- 형식 표본 = 파일럿 `tmp/essay/tm-2015-1.md`·`.rubric.md`·`.items.json`. **작업 전에 세 파일을 통독**하고 같은 결로 쓴다.

## 1. 절차 (예외 없음)

⓪ 이 브리프의 규칙(§4~§6)을 먼저 읽는다 → ① 발문·채점평(·existing)에서 설문별 쟁점을 도출한다 → ② 기본서 절 통독 + 판례 원문 대조 + 2차도서 목차 대조 → ③ 서술: 각 설문은 **판단(법적 평가) → 반응(조치·항변·심판)** 순서.

- **절 통독**: 기본서는 키워드 검색으로 나온 조각만 보지 말고, 쟁점이 속한 절을 `tm-book-read.mjs <from> <to>` 로 **chunk 순서대로 끝까지** 읽는다. 요건·학설·판례의 태도는 교재의 항목 구분과 순서를 그대로 따른다(층위가 다른 것을 합치지 않는다).
- **판례 원문 대조**: 인용할 사건번호마다 `tm-case-find.mjs --case <번호>` 로 상표 행 실존·법원·판시를 확인하고, 답안에 쓰는 판시 문언은 그 원문(또는 교재)에서 가져온다.
- **2차도서**는 논점 누락·목차 대조에만 쓴다. 문장·목차를 옮기지 않는다. 리담 교재와 다르면 리담이 우선한다. 2차도서의 조문 번호는 2016 전부개정 전후 판본이 섞여 있으니 그대로 믿지 않는다.

- 표본 파일 `tmp/essay/tm-2015-1.*` 은 읽기 전용이다. 고치지 않는다.

## 3. 근거의 권위 순서

1. 리담상표법(제20판) 본문 — 법리·요건·학설·판례의 태도의 체계
2. 리담 상표법 판례(제16판) = DB `cases` 상표 행 — 판시 문언·사건번호
3. 채점위원 채점평(`grading_notes`) — 논점 선택·감점 포인트
4. 2차도서 4권(데생·테마 풀이노트·테마 사례집·정상) — 논점 누락 대조(참고 전용)
5. `existing`(B군 구본) — 논점·판례 후보 참고(참고 전용)

교재에서 확인하지 못한 법리·학설·판례의 태도는 **쓰지 않는다**. 「종전 판례는 ~였다」「통설은 ~이다」「판례는 ~라고 한다」는 교재나 판례 원문에 그 문장이 있을 때만 쓴다. 해석이 확립되지 않은 쟁점은 단정하지 않고 판례에 따라 결론을 낸다.

## 4. 사건번호·조문 (★환각은 번호에 붙는다)

- 사건번호는 **기억에서 꺼내 쓰지 않는다.** `tm-case-find.mjs --case` 로 상표 행이 확인된 번호만 쓴다. 특허·상표 겹침 판례는 법률별 별도 행이라 특허 행만 있는 번호는 못 쓴다. 병합 사건번호(예 `2006후3397,3403`)는 DB 표기의 첫 번호로 인용한다.
- DB 에 없지만 리담 교재 본문에 번호가 그대로 있는 판례는 파일 검사기가 통과시키지만, **되도록 DB 수록 판례로 대체**한다(뷰어 배지는 DB 판례에만 붙는다). 어디에도 없으면 번호를 빼고 법리만 쓴다.
- 인용 형식: 문장 끝 괄호 `(대법원 2011후3698 전합)`·`(대법원 2015후1690)`·`(특허법원 2004허5894)`·`(대법원 2023도352)` 고정형. 괄호 안에 「종전 판례 변경」 같은 부기를 붙이지 않는다 — 필요하면 괄호 밖 별도 문장으로 쓴다. 「대판」 금지. 법원명은 사건부호와 맞춘다(후·다·도=대법원, 허=특허법원, 나·가합=하급심 — DB `court` 대조). 같은 판례를 반복 인용할 때도 매번 번호를 쓴다.
- 채점기준·rubric_items 에 쓰는 사건번호는 모범답안에 이미 인용한 번호여야 한다(GR 전용 번호 금지). 감점 주의 문장에는 번호 대신 별칭(「뉴발란스 사건」)을 쓴다.
- 조문: **본문(괄호 밖) = 정식 표기** 「제33조 제1항 제3호」「제34조 제1항 제13호」「제90조 제1항 제2호」. **괄호 안 = § 약호** `(§33①(3))`·`(§34①(13))`·`(§2①(11)다)`·`(§119①(3) 본문)`. 항=원문자, 호=(N), 목=가·나. 자기법 접두 없음(상§·法 금지). 타법은 `특§`·`디§`·`민§`·`민소§`, 부정경쟁방지법·시행령·조약은 풀네임. 「제33조 제1항 제3호부터 제7호까지」처럼 범위는 정식 표기. `§N조`·로마자 호(`§7Ⅰ`) 금지.
- 현행법으로 푼다. 부칙·시행일·경과조치는 쓰지 않는다. 발문이 구법 조문·용어(구 제7조 제1항, 서비스표, 지정서비스업, 특허청)를 쓰면 **현행 대응관계를 한 줄만** 밝히고 이후 현행 표기로 쓴다(구§7①→§34①, 구§73①→§119①, 서비스표→상표, 특허청→지식재산처). 대응표 `tmp/law-history/trademark-mapping-review.md`.
- 2014년 §33② 인식도 완화(「현저하게 인식」→「식별할 수 있게 된」), 2024-05-01 시행 개정으로 §33② 대상에 제7호 포함. 판시 인용문 안의 구법 문언은 원문대로 두되 법리 서술은 현행 문언으로 쓴다(예: 제33조 제2항은 「현저하게 인식」이 아니라 「특정인의 상품에 관한 출처를 표시하는 것으로 식별할 수 있게 된」).
- 판례를 인용할 때는 **그 판례가 전제한 사실관계가 사안과 맞는지** 확인한다(예: 제33조 제2항으로 등록된 상표에 관한 판시를 그 요건 없이 등록된 상표에 쓰지 않는다). 조문도 그 호의 문언이 사안에 걸리는지 확인하고, 걸리지 않으면 「각 호에 해당하지 않는다」로 쓴다.
- 교재가 「보충적 규정」이라고 한 호(예: 제33조 제1항 제7호)를 다른 호와 동시에 적용하지 않는다. 교재가 명시한 명제와 상충하는 서술(예: 「무효사유가 명백하면 권리범위확인심판 청구가 각하된다」)을 쓰지 않는다.

## 5. 모범답안 형식

- 위계 고정: `## Ⅰ. 설문 (1) — 제목 (N점)` → `### 1. 제목` → `#### (1) 제목` → `① **(제목)** 내용을 같은 줄에 이어 쓴다.` h1·`#####`·불릿·번호목록·표 금지. 설문이 하나뿐이면 `## Ⅰ. 설문 — 제목 (N점)`(총점).
- 설문 헤딩의 `(N점)` 은 발문의 설문별 배점. 발문에 설문별 배점이 없으면 쟁점 비중대로 안분하고 report 에 적는다. 합 = 총점.
- 설문 도입 = `### 1. 문제의 소재`(5점 이하 소형 설문은 생략 가능). **5점 이상 설문은 마지막 목차를 `### N. 결론` 으로 따로 둔다**(「사안의 포섭 및 결론」 합침은 2~4점 설문에만). 조문을 드는 목차 = 「관련 법규정」(「조문」 금지), 적용 조문 확정 = 「적용 법규정」, 의의·취지·조문을 묶으면 「의의 및 취지」, 사안 적용 = 「사안의 포섭」(「사안의 해결」 금지), 설문 마지막 `### N. 결론`(「소결」 금지). 「논점」「논점의 정리」「설문(N)의 해결」「물음」「소문항」「종합 결론」 금지. 문서 전체 결론 섹션 없음.
- 흐름: 문제의 소재 → 관련 법규정·판례의 법리 → 사안의 포섭 → 결론. 설문이 조치를 묻더라도 전제가 되는 법적 판단을 먼저 목차로 세운다. 비교형 설문은 요건/제도/권리 중 한 틀로 일관되게(제도 비교 = 요건·절차·효과·불복) 문장으로 비교한다(표 금지).
- 문장은 서술어 완결체(「…권리이다.」). 개조식·명사형 종결 금지. 판례 용어는 판시 문언대로(사회통념상 동일성·상표적 사용·요부관찰). 강학 조어(학설상 분류 명칭)는 요건·효과로 풀어 쓴다.
- 볼드는 ① 제목에만. `**…(§103)**의` 처럼 볼드가 `)` 로 끝나고 한글이 바로 붙지 않게 한다.
- 기관명 「지식재산처」. 당사자는 발문의 甲·乙·丙 그대로.
- 분량: **총 글자수 ≈ 배점 × 165자**(공백 포함, 검사기 산정 기준). 설문 간에도 배점 비율로 안분. 181.5자/점을 넘으면 WARN, 200자/점을 넘으면 FAIL. 초과하면 주변 설명·중복 서술을 줄여 맞춘다(판시 인용을 늘리려고 총량을 넘기지 않는다). 2~4점 소형 설문은 본문과 중복되는 결론 대신 「사안의 포섭 및 결론」으로 합친다.

## 6. 채점기준·rubric_items

- 채점기준(`.rubric.md`) 3부: `## 핵심 쟁점과 배점`(표: 쟁점 | 배점 | 득점 포인트, 마지막 줄 「합계: N점」) → `## 축별 채점 기준`(`### 1) 논점 추출(약 40%)` `### 2) 목차·구성(약 25%)` `### 3) 답안 작성·논증(약 35%)`, 각 축에 감점 항목 포함) → `## 감점 주의`(오답 유형, 사건번호 대신 별칭). 채점기준에는 표를 써도 된다.
- rubric_items(`.items.json`): 핵심 쟁점 표와 1:1 로 대응하는 항목, label 은 「(N) …을 적시했는가」형 완결 문장에 근거 판례 번호 포함, points 합 = 총점.
- 답안의 결론과 채점기준의 결론이 같아야 한다.

## 7. 작업 보고(`tmp/essay/tm-<year>-<no>.report.md`)

```
# tm-<year>-<no> 보고
- 총점/분량: N점 · X자(Y자/점) · 설문별 …
- 검사기: FAIL 0 / WARN …
- 쟁점(설문별): …
- 인용 판례(모두 tm-case-find 상표 행 확인): 번호 — 별칭 — 인용 취지
- 통독한 교재 구간: chunk a~b(절 제목) …
- 대조한 2차도서 페이지: 데생 p.…, 테마 p.…, 정상 p.…
- 채점평 반영: …
- 판단이 갈리거나 근거가 약한 지점(사람 확인 요청): …
- 데이터 이상(있으면): 발문 body_md 의 글자 결손, 강사해설 파일이 비어 있음, DB 판례 메타데이터(선고일·병합 번호)와 교재 표기 불일치 등 — DB 는 고치지 않고 여기에만 적는다
```

## 8. 검증 에이전트 지시 (적대적)

검증 에이전트는 작성 에이전트와 별도로 같은 문항을 받아 **틀린 곳을 찾는 것이 목적**이다. 결과는 `tmp/essay/review/tm-<year>-<no>.review.md` 에 쓴다.

1. 사건번호 전수: 답안·채점기준·items 의 모든 사건번호를 `tm-case-find.mjs --case` 로 확인하고, **인용 취지가 그 판례의 판시와 맞는지** 원문과 대조한다(번호는 맞는데 취지가 다른 것이 가장 흔한 오류).
2. 법리 대조: 답안의 요건 목록·학설·「판례의 태도」 문장마다 교재(`tm-book-read.mjs`)에서 근거 문장을 찾는다. 못 찾으면 FIX 로 기록한다. 교재의 항목 구분과 다르게 합치거나 나눈 곳도 FIX.
3. 조문 전수: 답안·채점기준·items 의 모든 조문 인용(본문 정식 표기·괄호 안 약호)을 `tm-article-read.mjs` 로 출력한 현행 조문과 대조해 **그 항·호가 답안이 말하는 내용인지** 확인한다(호 번호 오기가 가장 흔하다). 용어가 현행인지(구 제7조·서비스표·특허청 잔존, 2024 §33② 제7호 포함, 2016 대응관계 한 줄), 부칙 서술이 없는지.
4. 논점 완결: 채점평·2차도서 3권의 목차와 비교해 빠진 논점·발문이 배제한 논점을 다룬 곳을 적는다. 결론이 발문의 물음에 즉응하는지, 답안 결론 = 채점기준 결론인지.
5. 형식: §5·§6 규칙 위반(검사기가 못 잡는 것 — 문체·목차 표제·볼드·판단→반응 순서·분량 안분).
6. 판정: `PASS`(수정 불요) / `FIX`(항목별 「위치 — 문제 — 근거 — 고칠 방향」). 확신이 없으면 FIX 가 아니라 `CHECK`(사람 확인)로 분류한다. 파일은 고치지 않는다.

## 9. 수정 에이전트 지시

review 의 FIX 를 답안·채점기준·items 에 반영하고 검사기 FAIL 0 을 다시 확인한다. CHECK 항목은 손대지 않고 report 의 「사람 확인 요청」에 옮겨 적는다. 수정한 내용은 report 끝에 「수정 이력」으로 남긴다.
