1. 관리자 메뉴 전면 재편 요청
1.1 현재 문제
  • 같은 업무에 속하는 강의, 가격정책, 영상자료, 수강권, 연장 기능이 서로 멀리 분산돼 있습니다.
  • 주문·결제·배송·정산 메뉴가 나뉘어 있어 한 주문을 처리하기 위해 여러 메뉴를 오가야 합니다.
  • 강의개설 화면과 영상자료 분류단위, 판매정책 화면의 연결 위치와 명칭이 일관되지 않습니다.
  • “series·edition”, “강의”, “상품”, “plan” 용어가 혼재해 관리자가 같은 대상을 다른 기능으로 오해할 수 있습니다.
  • 오류가 발생하는 메뉴도 사이드바에 그대로 노출되어 실제 운영 중 업무 중단을 유발합니다.
1.2 재편 방향

타사의 LMS사이트 구성을 참고하되, 리담의 온라인 강의·Kollus DRM·교재 판매·강사 정산 업무에 맞춰 아래 구조로 재편합니다.

1.4 메뉴 사용성 필수조건
  1. 좌측 메뉴는 상위 업무군별 아코디언 구조로 만들고, 관리자가 연 메뉴와 마지막 방문 위치를 유지합니다.
  2. 상단에 전체 메뉴 검색을 제공하며 “수강권”, “환불”, “할인권”처럼 기능명으로 바로 찾을 수 있어야 합니다.
  3. 자주 쓰는 메뉴 메뉴와 최근 사용 메뉴를 제공해 반복 업무 접근 단계를 줄입니다.
  4. 권한이 없는 메뉴는 비활성 선택단추으로 남기지 말고 숨기며, 직접 URL 접근도 서버에서 차단합니다.
  5. 모든 화면에 “상위 업무군 > 목록 > 상세” 형태의 경로표시와 목록 돌아가기 선택단추을 통일합니다.
  6. 동일 기능의 대표 URL은 하나만 사용합니다. 예: 판매정책 연결이 /admin/plans와 /admin/pricing으로 갈라지지 않도록 통일합니다.
  7. 목록 필터·정렬·화면크기·검색어는 상세 화면을 보고 돌아와도 유지합니다.
  8. 대시보드 경고카드에서 결제대기 장기건, 환불요청, 재생오류, 배송대기, 수강권 만료예정으로 바로 이동합니다.
  9. 오류가 발생한 메뉴는 정상화 전 배포하지 않으며, 장애 시 빈 화면 대신 추적번호와 안내를 표시합니다.

공통 완료 기준 각 오류는 단순히 화면가 열리는 것으로 완료 처리하지 않습니다. 검색·목록·상세·저장·취소·권한차단·변경이력까지 테스트하고, 기존 운영데이터에 대한 DB 자료전환 및 원복계획을 제출합니다.
3. 결제·수강연장 안정화
3.1 현재 확인된 문제
  • 결제창을 열고 결제하지 않아도 내주문 배송에 주문이 결제대기 상태로 계속 쌓입니다.
  • 수개월 전 일반 강의 결제 시도도 결제대기 상태로 남아 자동 만료되지 않습니다.
  • 관리자 결제내역에서는 연장 대상 상품명이 공란이며 수강권·연장 회차를 식별하기 어렵습니다.
  • 수강생 결제내역에는 “course_extension”이라는 내부 코드가 그대로 표시되어 있습니다.
  • 도서는 도서명이 나오지 않으며, 2개 주문하면 도서*2로 표시 됩니다.
  • 사용자가 결제창을 닫은 시도와 실제 결제대기 주문이 같은 목록에 섞여 있습니다.
3.2 최종 수정요청
  1. PG 호출 전 생성한 건은 “결제시도”로 저장하고 일반 주문·매출 집계와 분리합니다.
  2. 결제창 종료 또는 제한시간 경과 시 “사용자취소/만료”로 자동 전환합니다.
  3. 연장 주문에 주문유형, 상품명, 수강권 ID, 기존 종료일, 연장일수, 연장 회차, 금액을 저장합니다.
  4. 수강생과 관리자 화면에는 “수강기간 연장”이라는 한글 명칭을 표시합니다.
  5. 결제 승인 승인 응답과 PG 알림요청이 중복 수신돼도 한 번만 연장되도록 중복방지키를 적용합니다.
  6. 현재 수강 중이면 기존 종료일 뒤에 연장하고, 만료 후 연장이면 결제승인 즉시 수강 가능하게 하되 다음 날부터 연장일수를 계산합니다.
  7. 최초 수강 종료 후 30일 이내, 허용 횟수, 허용 상품종류를 서버에서 재검증합니다.
  8. 결제 성공 전에 수강기간을 변경하지 않습니다. 결제 실패·취소 시 권한 변경도 없어야 합니다.
  9. 환불 성공 시 자동으로 연장분을 되돌리며, 이미 기간을 사용해 자동회수가 곤란하면 관리자 수동처리와 사유기록을 제공합니다.
  10. 연장 주문의 생성·결제·권한변경·환불·복구 전 과정을 감사로그에 연결합니다.
 
4. 분야별 최종 기능요구
4.1 강의·상품관리
  • 강의목록 검색조건: 카테고리, 온라인/현장/패키지/T-PASS, 신청기간, 신청상태, 판매상태, 진행상태, 공개상태, 종료상태, 강의명, 강사명, 강의 UID.
  • 목록 열: 선택, UID, 대표이미지, 강의명, 카테고리, 강사, 유형, 신청기간, 정상가·할인가, 판매·진행·공개·종료상태, 정렬순서, 등록·수정일.
  • 행동: 상세, 수정, 복사, 목차, 수강생, 판매정책. 연결 데이터가 있는 경우 삭제 대신 비활성화합니다.
  • 강의등록 선택단추은 별도 강의등록 화면으로 연결하고, 가격관리 화면으로 우회시키지 않습니다.
  • 관리자 화면의 “series·edition·plan” 용어를 제거하고 “강의개설·강의·판매정책”으로 통일합니다.
  • 수강기간과 수강배수는 별도 정책으로 유지하고, 저장 제약조건 오류를 재검증합니다.
  • PC·모바일 최대기기수 입력란은 삭제합니다. 기기 허용은 Kollus 정책에서만 관리합니다.
4.2 영상자료 영상보관소·분류단위·회차
  • 영상자료 영상보관소에는 영상자료 UID, Kollus 키·카테고리, 동기화상태, 인코딩상태, 연결분류단위·강의 수, 등록·수정일을 표시합니다.
  • 영상명·키·카테고리·분류단위·상태·기간으로 검색하며 Kollus 동기화 오류를 별도 목록에서 재처리할 수 있게 합니다.
  • “동기화·등록 재배선은 후속 단계”와 같은 개발중 안내문을 제거합니다.
  • 영상자료 분류단위에는 UID, 분류단위명, 설명, 강사, 카테고리, 사용상태, 연결강의, 영상자료수, 총시간을 관리합니다.
  • 회차 연결은 전체 영상 select 반복방식이 아니라 검색형 영상보관소 대화창과 다중선택·일괄추가를 제공합니다.
  • 회차번호·제목·공개·미리보기·자료·정렬순서를 일괄 편집하고 드래그 및 수치순서 입력을 모두 지원합니다.
  • 연결된 판매상품·수강생이 있는 회차 삭제 시 영향대상을 표시하고 비활성 또는 대체영상 연결을 우선합니다.
4.3 수강권·학습운영
  • 회원명·회원번호·강의명·수강권 ID·상태·기간·결제주문번호로 검색합니다.
  • 수강권 부여, 시작일·종료일 수정, 연장, 일시정지, 재개, 회수, 차단, 수강배수 초기화와 사유를 기록합니다.
  • 회원상세 CRM에서 수강권·진도·주문·상담·기기지원·변경이력을 구분화면으로 확인합니다.
  • 학생 강의실에는 강의시간·학습시간·진도율만 표시하고 재생횟수와 내부 제한 수치은 노출하지 않습니다.
  • 상품 수강배수와 회차별 최대재생 정책이 동시에 설정돼 이중차감되지 않도록 단일 판정엔진과 우선순위를 명시합니다. 두 제한을 동시에 사용할 때는 관리자에게 예상 동작을 표시합니다.
  • 관리자 검수 재생은 수강권·진도·배수·재생횟수에 반영하지 않습니다.
4.4 Kollus DRM·재생보안
