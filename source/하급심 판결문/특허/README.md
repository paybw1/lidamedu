# 하급심 판결문 투입 폴더 (특허법)

feat-2-035 판례 도식화의 **사실관계** 소스. 대법원 판결문은 법률심이라 사실관계가
"원심이 인정한 사실은 …" 으로 압축돼 있어, 2차 각색 출제의 원형이 되는 구체적 사실이 남지 않는다.

## 자동 수집이 먼저다

```bash
node scripts/case-diagram/fetch-lower-court.mjs --year 2025    # 연도 단위
node scripts/case-diagram/fetch-lower-court.mjs --from 2005    # 전체
```

대법원 원문의 `【원심판결】` 표기를 파싱해 국가법령정보센터에서 하급심 전문을 받아온다.
**여기에 파일을 넣어야 하는 건 자동 수집이 실패한 건뿐이다** — 실행 끝에 그 목록이 출력된다.

## 파일명 규약

```
<대법원 사건번호> <법원> <하급심 사건번호>.pdf
```

```
2022후10814 특허법원 2021허4232.pdf
2022다265123 특허법원 2022나1234.pdf
2022다265123 서울중앙지법 2021가합5678.pdf     ← 심급 여러 개면 파일 여러 개(같은 접두어)
```

- **첫 공백 앞 토큰 = 대법원 사건번호 = 매칭 키.** DB 의 유일한 안정 키라 이걸 쓴다.
- 뒤 문구(법원·하급심 사건번호)가 그대로 학생 화면의 **출처 캡션**이 된다.
- 같은 접두어 파일이 여러 개면 전부 읽어 합친다(1심+2심). 순서는 파일명 정렬.
- 허용 확장자: `.pdf`(텍스트 레이어 있는 것) · `.txt` · `.md`
- **스캔 이미지 PDF 는 텍스트가 안 나온다** — 추출 0자면 경고 후 건너뛴다(OCR 은 범위 밖).
- 수기 파일이 있으면 자동 수집보다 **우선**한다(일부러 넣은 것이므로).

## 산출물

- `../.cache/<대법원사건번호>.json` — 전문 캐시. 재실행 시 재요청하지 않는다(`--refresh` 로 무시).
- `../.cache/_report-<범위>.json` — 확보/미확보 분류 리포트.

전문은 **DB 에 저장하지 않는다.** DB(`case_diagrams`)에는 정리된 사실관계와 출처 표기만 들어간다.
